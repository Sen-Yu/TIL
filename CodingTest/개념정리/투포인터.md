# 투포인터 정리

지금까지 푼 투포인터 문제들을 바탕으로 정리한 노트.
예제 코드: [two_pointer_examples.py](./two_pointer_examples.py) (VS Code에서 F5로 실행하면 각 틀이 움직이는 과정을 출력한다)

---

## 1. 한 줄 요약

> 투포인터는 **"한쪽으로만 움직여도 놓치는 답이 없다"**가 보장될 때 쓴다.
> 두 포인터가 각각 최대 N번만 움직이므로 O(N)이다 (정렬이 필요하면 O(N log N)).

---

## 2. 판별법

### 이런 신호가 보이면 의심한다

| 신호 | 이유 | 예 |
|---|---|---|
| N이 10만~100만 | O(N²) 불가, O(N) 또는 O(N log N) 필요 | 178870, 1806, 22862 |
| **연속된** 구간 / 부분 수열 | 구간을 `[left, right]` 두 끝으로 표현할 수 있다 | 178870, 보석 쇼핑, 1806, 22862 |
| 정렬된(정렬해도 되는) 배열에서 **두 수** 고르기 | 정렬하면 어느 쪽을 버릴지 정할 수 있다 | 2470, 2230, 구명보트 |
| 가장 짧은 / 가장 긴 구간 | 조건에 따라 늘리고 줄이는 규칙이 생긴다 | 1806, 22862 |

### 꼭 확인할 것: 단조성

> **두 포인터를 각각 움직였을 때 값이 한 방향으로만 변하는가?**

- 합 문제는 **원소가 모두 양수**일 때만 성립한다. (늘리면 커지고 줄이면 작아진다)
- 개수 문제(종류 수, 홀수 개수)는 늘리면 같거나 많아지고, 줄이면 같거나 적어진다.

### 투포인터가 아닌 신호
- 음수가 섞인 배열의 "합이 k인 구간" → 누적합 + 딕셔너리
- 연속이 아닌 아무 원소 조합 → DP / 완전탐색
- 답의 범위가 억 단위이고 "최대 몇 명" → 이분 탐색 (징검다리 건너기)

## 3. 두 가지 유형과 고르는 기준

| | ① 같은 방향 | ② 양 끝에서 안쪽으로 |
|---|---|---|
| 시작 | `left = 0`, `right`는 `for`로 0부터 | `left = 0`, `right = n-1` |
| 반복문 | `for right` + 안쪽 `while`로 `left` 이동 | `while left < right` 하나 |
| 푼 문제 | 178870, 보석 쇼핑, 롤케이크, 두 큐, 2230, 1806, 22862 | 2470, 구명보트 |

### 고르는 기준: "값을 키우는 이동과 줄이는 이동이 둘 다 있는가"

겉모양("정렬 + 두 수 고르기")만 보고 고르면 틀린다 (2230에서 실수).

| 보는 값 | `left` → 오른쪽 | `right` → 왼쪽 | `right` → 오른쪽 | 맞는 유형 |
|---|---|---|---|---|
| 합 `A[l] + A[r]` (2470) | 증가 | **감소** | — | ② 양 끝 |
| 차이 `A[r] - A[l]` (2230) | 감소 | 감소 ❌ | **증가** | ① 같은 방향 |
| 구간 합 (1806) | 감소 | — | **증가** | ① 같은 방향 |

양 끝에서 시작했는데 두 이동이 모두 값을 줄이면, 한 번 지나친 쌍을 다시 볼 수 없다.

## 4. 같은 방향: 가장 짧은 구간 vs 가장 긴 구간

같은 틀이지만 **`while` 조건**과 **답 갱신 위치**가 반대다. 이 차이만 기억하면 된다.

| | 가장 짧은 구간 | 가장 긴 구간 |
|---|---|---|
| `while` 조건 | 좋은 구간인 **동안** 줄인다 | 나쁜 구간인 **동안** 줄인다 |
| 답 갱신 위치 | `while` **안** (줄이기 전) | `while` **뒤** (다시 좋아진 뒤) |
| 초기값 | 나올 수 없는 큰 값 (`n + 1`) | 0 |
| 이유 | 좋은 구간을 찾을 때마다 더 짧게 만들어 본다 | 나쁜 구간을 좋게 되돌린 뒤 길이를 잰다 |
| 푼 문제 | 1806 부분합, 178870, 보석 쇼핑 | 22862 짝수 부분 수열 |

### 가장 짧은 구간: 합이 S 이상인 가장 짧은 구간

```python
def shortest(arr, S):
    n = len(arr)
    left = 0
    total = 0                  # 정의: total = arr[left] ~ arr[right] 합 (양 끝 포함)
    answer = n + 1             # 나올 수 없는 값 = "아직 못 찾음"

    for right in range(n):
        total += arr[right]                        # 1) 오른쪽을 넣고

        while total >= S:                          # 2) 좋은 구간인 동안
            answer = min(answer, right - left + 1)  #    줄이기 전에 갱신
            total -= arr[left]                     #    왼쪽을 빼서 더 짧게
            left += 1

    return answer if answer <= n else 0
```

`arr = [2, 1, 3, 2, 4, 1]`, S = 6 (실행 결과 그대로)

```text
  [0, 2] [2, 1, 3] 합 6 -> 길이 3 기록
  [1, 3] [1, 3, 2] 합 6 -> 길이 3 기록
  [2, 4] [3, 2, 4] 합 9 -> 길이 3 기록
  [3, 4] [2, 4] 합 6 -> 길이 2 기록
  답: 2
```

### 가장 긴 구간: 합이 S 이하인 가장 긴 구간

```python
def longest(arr, S):
    left = 0
    total = 0
    answer = 0

    for right in range(len(arr)):
        total += arr[right]                        # 1) 오른쪽을 넣고

        while total > S:                           # 2) 나쁜 구간인 동안
            total -= arr[left]                     #    왼쪽을 빼서 다시 좋게
            left += 1

        answer = max(answer, right - left + 1)     # 3) 다시 좋아진 뒤 갱신

    return answer
```

같은 배열 `[2, 1, 3, 2, 4, 1]`, S = 6 (실행 결과 그대로)

```text
  [0, 0] [2] 합 2 -> 길이 1
  [0, 1] [2, 1] 합 3 -> 길이 2
  [0, 2] [2, 1, 3] 합 6 -> 길이 3
  [1, 3] [1, 3, 2] 합 6 -> 길이 3
  [3, 4] [2, 4] 합 6 -> 길이 2
  [4, 5] [4, 1] 합 5 -> 길이 2
  답: 3
```

- 가장 짧은 쪽은 **좋은 구간이 될 때만** 기록한다 (4번).
- 가장 긴 쪽은 `right`마다 **항상** 기록한다 (6번). `while` 뒤에는 언제나 좋은 구간이기 때문이다.

### 들고 다니는 값만 바꾸면 된다

| 문제 | 들고 다니는 값 | 좋은 구간 | 유형 |
|---|---|---|---|
| 1806 부분합 | 구간 합 | 합 ≥ S | 가장 짧은 |
| 보석 쇼핑 | 보석별 개수 + 종류 수 | 모든 종류 포함 | 가장 짧은 |
| 22862 짝수 부분 수열 | 홀수 개수 | 홀수 ≤ K | 가장 긴 (답은 `길이 - 홀수 개수`) |
| 2230 수 고르기 | (차이를 바로 계산) | 차이 ≥ M | 가장 작은 차이 (`left < right` 필요) |

## 5. 양 끝에서 안쪽으로

```python
def closest_pair(arr):
    arr = sorted(arr)
    left, right = 0, len(arr) - 1
    answer = (arr[left], arr[right])

    while left < right:                            # 같은 원소를 두 번 고르지 않게
        now = arr[left] + arr[right]
        if abs(now) < abs(answer[0] + answer[1]):
            answer = (arr[left], arr[right])
        if now < 0:
            left += 1                              # 더 큰 수가 필요
        else:
            right -= 1                             # 더 작은 수가 필요

    return answer
```

`[-2, 4, -99, -1, 98]` (실행 결과 그대로)

```text
  -99 + 98 = -1
  -2 + 98 = 96
  -2 + 4 = 2
  -2 + -1 = -3
  답: (-99, 98)
```

- 합 < 0이면 지금 `arr[left]`는 어떤 짝과도 이보다 0에 가까워질 수 없다 → 버린다.
- 그래서 모두 양수 / 모두 음수도 **특별 처리 없이** 맞는다.

## 6. 코드 쓰기 전 5줄 메모

1. **무엇을 들고 다니나?** 합, 개수 딕셔너리, 홀수 개수 …
2. **정의 한 문장**: "`total`은 항상 `arr[left]`부터 `arr[right]`까지(양 끝 포함)의 합이다." 코드 모든 곳에서 참이어야 한다.
3. **움직이는 규칙**과 **놓치지 않는 이유** 한 줄. 유형은 3번 표로 고른다.
4. **답 갱신 위치**: 가장 짧은 → `while` 안 / 가장 긴 → `while` 뒤 / 양 끝 → 옮기기 전.
5. **종료**: `for right` 끝까지 / `left < right` / 시뮬레이션은 상한 (두 큐: 3n).

## 7. 제출 전 체크리스트 (실수 모음)

- [ ] 반복문 안에 `sum()`, `count()`, `in list`가 없나? → O(N²) (두 큐, 롤케이크)
- [ ] 시작점마다 `right`를 처음부터 다시 훑지 않나? → O(N × 구간 길이) (22862)
- [ ] 구간 길이는 `right - left + 1` (양 끝 포함) (22862)
- [ ] `left < right`가 필요한 문제인가? 서로 다른 두 수면 필요(2470, 2230), 원소 한 개도 구간이면 불필요(1806)
- [ ] "못 찾음" 초기값이 진짜 답과 겹치지 않나? (1806: `n` 대신 `n + 1`)
- [ ] 종류 수를 `len(dict)`로 세면서 0이 된 키를 안 지우지 않았나? → 카운터 변수 (보석 쇼핑, 롤케이크)
- [ ] 특별 처리가 정말 필요한가? 일반 규칙이 맞으면 지운 뒤 경계 케이스로 확인 (2470, 1806, 22862)
- [ ] 포인터를 하나 더 추가하고 싶어지면 틀을 의심 → 정의 한 문장부터 다시 (22862)
- [ ] 백준: `input().split()`, 짝수는 `% 2`, 출력은 `print(*answer)`
