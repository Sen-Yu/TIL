# 백준 - 부분합 (1806) 풀이 정리

문제 링크: https://www.acmicpc.net/problem/1806

최종 코드: [1806.py](./1806.py) · 예제 입력: [input.txt](./input.txt)

---

## 1. 문제 요약 및 제약 조건

### 문제 요약
- 길이 N의 자연수 수열이 주어진다.
- 연속된 수들의 부분합이 S 이상이 되는 것 중 **가장 짧은 길이**를 구한다.
- 그런 부분합을 만들 수 없으면 **0**을 출력한다.

### 제약 조건
- N: **10 이상 100,000 미만 (10만)** → 모든 구간을 보는 O(N²)은 불가능
- S: 0 초과 1억 이하, 수열의 원소: 10,000 이하 자연수

---

## 2. 고민 과정 및 코드의 발전

같은 날 수 고르기(2230)에서 같은 방향 투 포인터를 익히고 바로 이어서 푼 문제. 틀은 처음부터 맞았고, **경계 처리** 두 군데에서 틀렸다.

### ❌ 1단계: 같은 방향 틀 + `left < right` + 특별 처리 (오답)

```python
import  sys

def main():
    input = sys.stdin.readline
    N, S = map(int, input().split())
    arr = list(map(int, input().split()))
    
    left = 0
    sum=0
    answer = N
    if min(arr) >= S:
        print(1)
        return()
    
    for right in range(N):    
        sum+=arr[right]
        
        while sum >= S and left < right:
            answer = min(answer, right-left+1)
            sum-=arr[left]
            left+=1

    print(answer)

main()
```

- **아이디어**: `right`로 넣고, 합이 S 이상인 동안 길이를 갱신하며 `left`를 줄인다. 모든 원소가 S 이상이면 1을 바로 출력.
- **문제점**: 직접 고른 10개 케이스 중 4개 오답.

| 입력 (N S / 수열) | 결과 | 정답 |
|---|---|---|
| `3 100` / `1 2 3` | `3` | `0` |
| `1 10` / `5` | `1` | `0` |
| `3 5` / `1 10 1` | `2` | `1` |
| `4 7` / `1 1 1 9` | `2` | `1` |

  1. **답이 없을 때 N 출력**: `answer = N`으로 시작해서, 한 번도 갱신되지 않으면 N이 그대로 나온다. 진짜 답이 N인 경우(`3 6` / `1 2 3`)와도 구분이 안 된다.
  2. **길이 1 구간을 확인하지 않음**: `left < right` 때문에 `left == right`인 원소 한 개짜리 구간은 `while`에 들어가지 못한다.

```text
수열: 1  10  1     S = 5
right=0  sum  1  → S 미만
right=1  sum 11  → left=0 < 1: 길이 2 기록, sum 10, left=1
         sum 10  → S 이상인데 left=1 < right=1 이 거짓 → 멈춤
                   [10] 한 개짜리 구간을 못 봄 → 출력 2 (정답 1)
```

  3. `min(arr) >= S` 특별 처리는 **모든** 원소가 S 이상일 때만 막아 준다. 한 개만 S 이상인 경우는 놓친다.

### ⭕ 2단계: `answer = N+1`, `left` 조건과 특별 처리 제거 (통과)

```python
import  sys

def main():
    input = sys.stdin.readline
    N, S = map(int, input().split())
    arr = list(map(int, input().split()))
    
    left = 0
    sum=0
    answer = N+1

    for right in range(N):    
        sum+=arr[right]
        
        while sum >= S :
            answer = min(answer, right-left+1)
            sum-=arr[left]
            left+=1

    if answer == N+1:
        answer = 0
    
    print(answer)

main()
```

- `answer = N+1`: 진짜 답은 최대 N이므로 N+1이 남아 있으면 "못 찾음" → 0 출력.
- `while`에서 `left < right`를 빼서 길이 1 구간도 확인한다. 그러자 `min(arr) >= S` 특별 처리도 필요 없어져 지웠다.
- 검증: 직접 고른 10개 케이스(예제, 답 없음, 전체 합이 딱 S, 가운데/마지막 한 개가 S 이상, 모두 S 이상, N=1 가능/불가, 앞쪽/뒤쪽 짧은 구간) 모두 통과. N=10만 최대 입력 2개 각각 0.03초.
- 백준 제출 중 런타임 에러가 한 번 났지만, 코드가 아니라 제출할 때 입력이 잘못 들어간 것으로 보이고 다시 제출해서 통과했다.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 같은 방향 투 포인터 (가장 짧은 구간)
- 원소가 모두 양수라서 `right`를 늘리면 합이 **커지고**, `left`를 늘리면 합이 **줄어든다.**
- 합 < S → `for`가 `right`를 늘린다.
- 합 ≥ S → 길이를 기록하고 `left`를 늘려 더 짧은 구간을 찾는다.

```text
수열: 1  10  1     S = 5,  처음 answer = 4 (N+1)
right=0  [1]        sum  1 → S 미만
right=1  [1 10]     sum 11 → 길이 2 기록, left 이동
         [10]       sum 10 → 길이 1 기록, left 이동
         (빈 구간)  sum  0 → S 미만, while 종료
right=2  [1]        sum  1 → S 미만
출력 1
```

### 💡 2. `left` 조건이 없어도 되는 이유
- `left`가 `right`를 넘어가는 순간 구간이 비어서 `sum`은 0이 된다.
- S는 0보다 크므로 `sum >= S`가 거짓이 되어 `while`이 저절로 멈춘다.
- 원소가 양수이고 S > 0이라는 조건 덕분이다. 0이나 음수가 섞이면 이 성질이 깨진다.

### 💡 3. "못 찾음"을 표시하는 값
- 최솟값을 구할 때는 **나올 수 없는 큰 값**으로 시작한다 (N+1, `float('inf')` 등).
- 끝에서 그 값이 그대로면 "한 번도 갱신 안 됨"으로 판단한다.
- 가능한 답 범위 안의 값(N)으로 시작하면 진짜 답과 구분이 안 된다.

### 💡 4. 같은 날 푼 두 문제 비교

| | 수 고르기 (2230) | 부분합 (1806) |
|---|---|---|
| 대상 | 정렬된 배열의 두 수 | 연속 구간 |
| 보는 값 | 차이 `A[right] - A[left]` | 구간 합 |
| `while` 조건 | 차이 ≥ M **그리고 `left < right`** | 합 ≥ S |
| `left < right`가 필요한가 | 필요 (서로 다른 두 수) | 불필요 (한 개도 구간) |
| 답이 없는 경우 | 항상 있음 | 0 출력 → N+1로 표시 |

## 4. 디버깅 & 실수했던 포인트 정리

1. **구간의 최소 모양 확인하기**: 2230에서 쓴 `left < right`를 그대로 가져왔다가 길이 1 구간을 놓쳤다. 코드 쓰기 전에 "가장 짧은 구간은 어떤 모양인가"를 적어 보자.
2. **"못 찾음" 초기값**: 답이 될 수 있는 값으로 초기화하면 진짜 답과 구분이 안 된다. 범위 밖의 값으로 시작하자.
3. **특별 처리는 일부만 막는다**: `min(arr) >= S`는 증상 하나만 가렸다. 일반 규칙을 고치니 필요 없어졌다 (두 용액, 보석 쇼핑과 같은 교훈).
4. **변수 이름 `sum`**: 내장 함수 `sum()`을 가린다. 이 코드에서는 `sum()`을 안 써서 문제없었지만 `total` 같은 이름이 안전하다.
5. **런타임 에러는 에러 이름부터**: 백준은 괄호 안에 에러 이름을 보여 준다 (`IndexError`, `FileNotFoundError` 등). 원인을 좁히는 첫 단서다.

---

## 5. 복잡도 분석

- **시간 복잡도**: $O(N)$ — `right`와 `left` 모두 최대 N번만 움직인다.
- **공간 복잡도**: $O(N)$ — 입력 배열.

## 6. 결론 및 배운 점
- 같은 방향 틀은 그대로 써도, `while` 조건은 **문제의 구간 정의**에 맞춰 다시 정해야 한다.
- 최솟값 문제에서 "답 없음"이 있으면 범위 밖의 초기값을 두고 끝에서 확인한다.
- 일반 규칙이 경계를 처리하면 특별 처리는 지운다. 지운 뒤 경계 케이스로 다시 돌려 확인한다.
