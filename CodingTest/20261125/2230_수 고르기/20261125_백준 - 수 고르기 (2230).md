## 1. 문제 요약 및 제약 조건

### 문제 요약
- N개의 정수로 이루어진 수열 A에서 두 수를 고른다 (같은 수일 수도 있다).
- 두 수의 차이가 **M 이상이면서 가장 작은 차이**를 구한다.

### 제약 조건
- N: **1 이상 100,000 이하 (10만)** → 모든 쌍을 보는 O(N²)은 불가능
- M: 0 이상 20억 이하, |A[i]|: 10억 이하
- 항상 차이가 M 이상인 두 수를 고를 수 있는 입력만 주어진다.

---

## 2. 고민 과정 및 코드의 발전

어제 두 용액(2470)을 "정렬 + 두 수 고르기 → 양 끝에서 안쪽으로"로 풀었고, 같은 판단으로 시작했다. 하지만 이 문제는 **같은 방향** 투 포인터였다.

### ❌ 1단계: 양 끝에서 안쪽으로 (오답)

```python
import  sys

def main():
    input = sys.stdin.readline
    
    N, M = map(int, input().split())
    A = [int(input().strip()) for i in range(N)]
    A.sort()
    
    left = 0
    right = N-1
    answer = A[right]-A[left]
    while left < right:
        now = A[right]-A[left]
        
        if now >= M:
            answer = min(now, answer)
            if answer == M:
                break
            
        if now < M:
            right-=1
        
        elif now > M:
            left+=1
    print(answer)
        

main()
```

- **아이디어**: 정렬 후 양 끝에서 시작. 차이가 M보다 크면 `left`를 옮겨 줄이고, 작으면 `right`를 옮긴다.
- **문제점**: 직접 고른 10개 케이스 중 5개 오답.

| 입력 (N M / A) | 결과 | 정답 |
|---|---|---|
| `4 2` / `1 5 7 20` | `13` | `2` (5, 7) |
| `4 3` / `1 4 100 200` | `100` | `3` (1, 4) |
| `3 0` / `5 5 9` | `4` | `0` (5, 5) |
| `4 4` / `-10 -3 0 8` | `8` | `7` (-10, -3) |
| `4 5` / `0 1 7 100` | `93` | `6` (1, 7) |

  1. 차이 `A[right] - A[left]`는 **`left`를 옮겨도 줄고, `right`를 옮겨도 준다.** 차이를 키우는 이동이 없어서, 한 번 지나친 쌍은 다시 볼 수 없다.

```text
정렬: 0  1  7  100     M = 5
L=0(0)   R=3(100)  차이 100 > 5 → left 이동
L=1(1)   R=3(100)  차이  99 > 5 → left 이동
L=2(7)   R=3(100)  차이  93 > 5 → left 이동 → 종료. 출력 93
                   정답 (1, 7) = 6 은 right가 100에 머물러서 한 번도 못 봄
```

### ⭕ 2단계: 같은 방향 (`for right` + `while`로 `left` 줄이기) (통과)

```python
import  sys

def main():
    input = sys.stdin.readline
    
    N, M = map(int, input().split())
    A = [int(input().strip()) for i in range(N)]
    A.sort()
    
    left = 0
    answer = A[-1]-A[0]
    for right in range(1,N):
        now = A[right]-A[left]
        
        while now >= M and left < right:
            answer = min(now, answer)
            if answer == M:
                break
            left+=1
            now = A[right]-A[left]

        
    print(answer)
        

main()
```

- 1단계 힌트("두 포인터가 값을 반대 방향으로 바꾸는가?")를 받고, 178870·보석 쇼핑에서 쓴 같은 방향 틀로 바꿨다.
- 검증: 직접 고른 10개 케이스(예제, 가운데/작은 쪽/큰 쪽 쌍이 답, M=0과 같은 값, N=1, 두 개뿐, 음수 포함, 양 끝 사이에 답, 왼쪽만 옮겨서 놓치는 경우) 모두 통과. N=10만 최대 입력 2개(M 큼, M=1) 각각 0.03초.
- 백준 제출 통과.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 두 포인터를 둘 다 앞에서 시작하기
- 정렬 후 `right`를 한 칸씩 늘리면 차이가 **커지고**, `left`를 늘리면 차이가 **줄어든다.** 두 이동이 값을 반대 방향으로 바꾸므로 투 포인터가 성립한다.
- 차이 < M (조건 못 채움) → `right`를 늘려 차이를 키운다 (`for`).
- 차이 ≥ M (조건 채움) → 답을 갱신하고 `left`를 늘려 더 작은 차이를 찾는다 (`while`).

```text
정렬: 0  1  7  100     M = 5,  처음 answer = 100
right=1(1)    left=0(0)  차이  1 < 5 → right 이동
right=2(7)    left=0(0)  차이  7 ≥ 5 → answer 7,  left 이동
              left=1(1)  차이  6 ≥ 5 → answer 6,  left 이동
              left=2(7)  left == right → while 종료
right=3(100)  left=2(7)  차이 93 ≥ 5 → answer 6 유지, left 이동 → 종료
출력 6
```

### 💡 2. 왜 놓치는 쌍이 없나
- `left`를 옮기는 건 `A[right] - A[left] ≥ M`을 이미 확인한 뒤다.
- `right`가 더 커지면 같은 `left`와의 차이는 더 커지기만 하므로, 그 `left`에 대해서는 지금 본 차이가 최선이다. 그래서 버려도 된다.

### 💡 3. 같은 방향 vs 양 끝 — 고르는 기준은 "값을 키우는 이동이 있는가"

| | 두 용액 (2470) | 수 고르기 (2230) |
|---|---|---|
| 보는 값 | 합 `A[left] + A[right]` | 차이 `A[right] - A[left]` |
| `left` 오른쪽으로 | 합 **증가** | 차이 **감소** |
| `right` 왼쪽으로 | 합 **감소** | 차이 **감소** |
| `right` 오른쪽으로 | — | 차이 **증가** |
| 맞는 유형 | 양 끝에서 안쪽으로 | 같은 방향 |

"정렬 + 두 수 고르기"라는 겉모양은 같아도, **값을 늘리는 이동과 줄이는 이동이 둘 다 있도록** 시작 위치를 정해야 한다.

## 4. 디버깅 & 실수했던 포인트 정리

1. **겉모양으로 유형 고르기**: "정렬 + 두 수 고르기 = 양 끝"으로 외우면 차이 문제에서 틀린다. 코드 쓰기 전에 두 포인터를 각각 움직였을 때 값이 어떻게 변하는지 표로 적어 보자.
2. **`left < right` 조건**: 두 용액에서 배운 대로 같은 원소를 두 번 고르지 않게 처음부터 넣었다.
3. **`break`는 안쪽 `while`만 빠져나온다**: 답이 M이 된 뒤에도 바깥 `for`는 계속 돈다. 결과는 같지만, 바로 끝내려면 `print(M)` 후 `return`.

---

## 5. 복잡도 분석

- **시간 복잡도**: $O(N \log N)$
  - 정렬 $O(N \log N)$ + 투 포인터 $O(N)$ (`left`, `right` 모두 최대 N번만 움직인다).
- **공간 복잡도**: $O(N)$ — 입력 배열.

---

## 6. 결론 및 배운 점
- 투 포인터 유형은 **두 포인터를 움직였을 때 값이 반대 방향으로 변하는지**로 고른다. 합은 양 끝, 차이는 같은 방향.
- 같은 방향 틀(`for right` + `while`로 `left` 줄이기)은 구간 문제뿐 아니라 "정렬된 배열에서 차이가 조건을 만족하는 두 수"에도 쓰인다.
- 2470 정리에 적은 "두 원소 고르기 → 양 끝"은 **합**일 때의 이야기였다.
