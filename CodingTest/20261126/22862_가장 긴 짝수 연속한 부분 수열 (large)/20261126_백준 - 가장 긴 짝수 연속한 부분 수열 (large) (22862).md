# 백준 - 가장 긴 짝수 연속한 부분 수열 (large) (22862) 풀이 정리

문제 링크: https://www.acmicpc.net/problem/22862

최종 코드: [22862.py](./22862.py) · 예제 입력: [input.txt](./input.txt)

---

## 1. 문제 요약 및 제약 조건

### 문제 요약
- 길이 N의 수열 S에서 원소를 **최대 K번** 삭제할 수 있다 (다 쓰지 않아도 된다).
- 삭제한 뒤 **짝수로만 이루어진 연속한 부분 수열** 중 가장 긴 길이를 구한다.

### 제약 조건
- N: **1 이상 1,000,000 이하 (100만)** → O(N²)은 불가능, O(N)이 필요
- K: 1 이상 100,000 이하

---

## 2. 고민 과정 및 코드의 발전

2230, 1806에서 **가장 짧은** 구간을 찾는 같은 방향 틀을 익혔고, 이번에는 **가장 긴** 구간 버전.

### ❌ 1단계: 짝수마다 시작해서 오른쪽으로 훑기 (에러 → 고쳐도 시간 초과)

```python
"""
K는 삭제 가능한 최대횟수(반드시 다 사용할 필요가 없다.)
처음 자른곳을 기점으로 연속된곳을 잘라야한다.
- 항상 길이가 긴곳을 자른다(다익스트라) -> 가장 긴 한곳이 다른곳과 연결하기위해서는 수많은 홀수를 제거해야하는 경우 예외 발생

엣지 케이스
- 홀수 만 이루어진 케이스
    : 0
- 짝수 만 이루어진 케이스
    : S
- N<K 케이스
    : 짝수 수

2 1 1 2 1 2 1 1 1 1 2 2 1
시작 지점을 기점으로 오른쪽 증가, 오른쪽 증가(한쪽 증가이기에 중복 방지 가능)

배열 원소 접근 반복문:
    짝수인가?:
        left = 현재 인덱스
        right = left
        count = 0
        count < K 반복문: 

"""
import sys

def main():
    
    input = sys.stdin.readline
    S, K = map(int, input())
    arr = [ map(int, input()) for idx in range(S) ]
    
    answer = 0
    
    for left in range(S):
        if arr[left] // 2 == 0:
            right = left
            count = 0
            length = 0
            while count <= K and right < S:
                if arr[right] // 2 == 0:
                    length +=1
                else:
                    count +=1
                right+=1
            answer = max(answer, length)
    
    print(answer)
    
main()
```

- **아이디어**: 짝수에서 시작해 오른쪽으로 가며, 홀수는 K개까지 건너뛰고 짝수만 센다.
- **문제점**: 원인을 하나씩 확인하려고 조금씩 고친 버전도 같이 돌렸다.

| 버전 | 10개 케이스 | 최대 입력 (N=100만, K=10만) |
|---|---|---|
| 보낸 코드 | 0 / 10 (`ValueError`) | 에러 |
| 입력만 고침 | 2 / 10 | 5초 넘게 안 끝남 |
| 입력 + 짝수 판별 고침 | **10 / 10** | 5초 넘게 안 끝남 |

  1. **입력**: `input()`에 `.split()`이 없어서 글자 하나씩 `int`로 바꾸다 공백에서 에러 (`invalid literal for int() with base 10: ' '`). 수열은 한 줄인데 S줄을 읽고, 리스트에 `map` 객체가 들어갔다.
  2. **짝수 판별**: `값 // 2 == 0`은 **몫**이라 0과 1에서만 참이다. 짝수 판별은 나머지 `값 % 2 == 0`.
  3. **시간 초과**: 시작점마다 `right = left`로 처음부터 다시 훑는다. 짝·홀이 번갈아 100만 개, K=10만이면 시작점 50만 개 × 약 20만 칸 ≈ 1000억 번.

- 정답을 세는 생각은 맞았다 (입력·판별만 고치면 10개 모두 정답).

### ⭕ 2단계: 같은 방향 틀 (가장 긴 구간) (통과)

```python
import sys

def main():
    
    input = sys.stdin.readline
    S, K = map(int, input().split())
    arr = list(map(int, input().split()))
    
    answer = 0
    left = 0
    count = 0

    for right in range(S):
        if arr[right] % 2 == 1:
            count+=1
            
        while count > K :
            if arr[left] % 2 == 1:
                count -= 1
            left += 1
        answer = max(answer, right-left+1-count)
    
    print(answer)
    
main()
```

- 1단계 코드 구조를 살린 빈칸 코드 힌트를 받아, 바깥 반복을 `for right`로 바꾸고 `count`를 이어서 쓰도록 고쳤다.
- 검증: 직접 고른 10개 케이스(예제, 모두 홀수, 모두 짝수, K보다 홀수가 적음, 홀수로 시작, 2·3이 아닌 짝수 판별, 뒤쪽이 더 김, N=1 짝수/홀수, 홀수 2개 지우기) 모두 통과. 최대 입력(100만 개, K=10만) 0.18초.
- 백준 제출 통과.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 문제를 "홀수가 K개 이하인 구간"으로 바꾸기
- 구간 `[left, right]` 안의 홀수가 **K개 이하**면, 홀수를 모두 지워서 짝수만 남길 수 있다.
- 그때 남는 짝수 개수 = **구간 길이 − 홀수 개수** = `(right - left + 1) - count`.
- 그래서 "홀수가 K개 이하인 구간 중 짝수가 가장 많은 것"을 찾으면 된다. 구간이 홀수로 시작해도 상관없다.

### 💡 2. 가장 긴 구간 틀
- `right`는 `for`로 한 칸씩 넣는다. 홀수면 `count += 1`.
- `count > K`인 **동안**(조건이 깨진 동안) `left`를 뺀다.
- `while`이 끝나면 다시 좋은 구간 → **여기서** 답을 갱신한다.

```text
수열: 1 2 3 4 5 6 7 8,  K = 2
right(값)  count       left 이동               구간          짝수 = 길이 - count   답
0 (1)      1           -                       1             1 - 1 = 0             0
1 (2)      1           -                       1 2           2 - 1 = 1             1
2 (3)      2           -                       1 2 3         3 - 2 = 1             1
3 (4)      2           -                       1 2 3 4       4 - 2 = 2             2
4 (5)      3 > K       1 뺌 → 2                2 3 4 5       4 - 2 = 2             2
5 (6)      2           -                       2 3 4 5 6     5 - 2 = 3             3
6 (7)      3 > K       2 뺌(그대로 3), 3 뺌 → 2  4 5 6 7       4 - 2 = 2             3
7 (8)      2           -                       4 5 6 7 8     5 - 2 = 3             3
출력 3
```

### 💡 3. 왜 `right`를 되돌리지 않아도 되나
- 구간 `[left, right]`에서 맨 앞을 빼면 홀수 개수는 같거나 줄어든다. 그래서 줄어든 구간은 여전히 조건을 만족한다.
- `right`를 `left`로 되돌려 다시 볼 이유가 없어서, `left`와 `right`는 앞으로만 간다 → 각각 최대 N번 → O(N).
- 1단계 코드와의 차이는 바깥 반복을 `left`에서 `right`로 바꾸고 `count`를 이어서 쓴 것뿐이다.

### 💡 4. 가장 짧은 구간 vs 가장 긴 구간

| | 부분합 (1806, 가장 짧은) | 이 문제 (22862, 가장 긴) |
|---|---|---|
| 들고 다니는 값 | 구간 합 | 구간 안 홀수 개수 `count` |
| 좋은 구간 | 합 ≥ S | `count` ≤ K |
| `while` 조건 | 좋은 구간인 **동안** 줄임 | 나쁜 구간인 **동안** 줄임 |
| 답 갱신 위치 | `while` **안** (줄이기 전) | `while` **뒤** (다시 좋아진 뒤) |

---

## 4. 디버깅 & 실수했던 포인트 정리

1. **입력 `.split()` 누락**: 백준 문제를 시작할 때 템플릿의 입력 두 줄을 복사해서 쓰자. 수열이 한 줄이면 `list(map(int, input().split()))`.
2. **짝수 판별은 `% 2`**: `// 2`는 몫이다.
3. **양 끝 포함 구간의 길이는 `right - left + 1`**: 1806에서도 쓴 식. 원소 한 개짜리 구간(`left == right`)에 넣어 보면 바로 확인된다.
4. **포인터를 더 추가하고 싶어지면 틀을 의심하기**: 정의 한 문장("`[left, right]` 안의 홀수가 K개 이하")부터 다시 적으면 `left`, `right` 두 개로 충분하다.
5. **처음부터 다시 훑는 반복은 시간 초과 신호**: 시작점마다 `right = left`로 되돌리면 O(N × 구간 길이)다.

---

## 5. 복잡도 분석

- **시간 복잡도**: $O(N)$ — `left`, `right` 모두 최대 N번만 움직인다.
- **공간 복잡도**: $O(N)$ — 입력 배열.

---

## 6. 결론 및 배운 점
- 같은 방향 틀은 가장 짧은 구간과 가장 긴 구간 두 버전이 있다. 가장 긴 구간은 **나쁜 동안 줄이고, `while` 뒤에서 갱신**한다.
- "최대 K개 삭제" 같은 조건은 "구간 안에 버릴 것이 K개 이하"로 바꾸면 투 포인터 조건이 된다.
- 세는 변수(`length`)를 따로 두기보다, 구간 길이와 이미 들고 있는 값(`count`)으로 계산하면 실수가 줄어든다.
