## 1. 문제 요약 및 제약 조건

### 문제 요약
- 롤케이크 위에 토핑이 한 줄로 올려져 있다 (`topping` 배열).
- 케이크를 한 번 잘라 철수와 동생이 나눠 가진다.
- 두 조각에 올라간 **토핑의 종류 수**가 같아지는 자르는 위치의 개수를 구한다. (조각 길이나 토핑 개수는 상관없음)

### 제약 조건
- `topping` 길이: **최대 1,000,000 (100만)**
- 토핑 번호: **최대 10,000 (1만 종류)**

---

## 2. 고민 과정 및 코드의 발전

### 아이디어
```text
토핑의 종류수가 서로 같아야한다.
왼쪽/오른쪽 각 dict() 만듬
처음에 왼쪽은 빈 dict() 오른쪽은 모든 토핑 들고 있는 상태로 시작

-> 한칸씩 컷하면서 왼쪽은 추가, 오른쪽은 삭제
-> 서로 토핑수가 같은지 확인
-> 반복 진행
```

### ❌ 1단계: 처음 코드 (실행 에러)

```python
def solution(topping):
    answer = 0
    length = len(topping)
    types = set(topping)
    topping_length = len(types)
    brothers = list()
    brothers.append({t:0 for t in types})
    brothers.append({t:topping.count(t) for t in types})
    print(brothers)
    
    counts = [0,types]
    for cut in range(topping_length):
        now = topping[cut]
        
        if brothers[0][now] == 0:
            counts[0] += 1
        brothers[0][now] += 1
        
        brothers[1][now] -= 1
        if brothers[1][now] == 0:
            counts[1] -= 1
        
        if counts[0] == counts[1]:
            answer += 1
    
    return answer
```

- **문제점**:
  1. `counts = [0, types]`: `types`는 `set`이라서 `counts[1] -= 1`에서 `TypeError`가 난다. 오른쪽 처음 종류 수는 **개수**(`topping_length`)여야 한다.
  2. `for cut in range(topping_length)`: **종류 수**만큼만 돈다. 자르는 위치는 **케이크 길이**(`length`) 기준이어야 한다.
  3. `topping.count(t)`: 호출할 때마다 배열 전체를 훑는다 → O(n × 종류 수).
  4. `print(brothers)`: 길이 100만이면 출력만으로도 느려진다.

### ❌ 2단계: 1, 2, 4번을 스스로 고침 (시간 초과)
- `counts = [0, topping_length]`, `for cut in range(length)`로 고치고 `print`를 지웠다.
- 정답은 맞게 나오지만 `topping.count(t)`가 남아 있어서 **시간 초과**가 났다.
- 길이 100만 배열에서 `count()`로 2,000종류만 세도 **9.4초**가 걸렸다. 문제에서는 1만 종류까지 나온다.

### ⭕ 3단계: `Counter` 적용 (최종 통과)

```python
"""
토핑의 종류수가 서로 같아야한다.
왼쪽/오른쪽 각 dict() 만듬
처음에 왼쪽은 빈 dict() 오른쪽은 모든 토핑 들고 있는 상태로 시작

-> 한칸씩 컷하면서 왼쪽은 추가, 오른쪽은 삭제
-> 서로 토핑수가 같은지 확인
-> 반복 진행
"""
from collections import Counter
def solution(topping):
    answer = 0
    length = len(topping)
    types = set(topping)
    topping_length = len(types)
    brothers = list()
    brothers.append({t:0 for t in types})
    brothers.append(Counter(topping))

    counts = [0,topping_length]
    for cut in range(length):
        now = topping[cut]
        
        if brothers[0][now] == 0:
            counts[0] += 1
        brothers[0][now] += 1
        
        brothers[1][now] -= 1
        if brothers[1][now] == 0:
            counts[1] -= 1
        
        if counts[0] == counts[1]:
            answer += 1

    return answer
```

- 오른쪽 개수를 `Counter(topping)`로 **배열을 한 번만 훑어서** 만든다 → O(n).
- 검증: 예제 2개 정답, 랜덤 입력 30,000개(자르는 위치마다 `set`으로 직접 세는 방식과 비교) 오답 0개, 길이 100만·1만 종류 입력 **0.25초**.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 자르는 위치를 한 칸씩 옮기며 "들고 있는 것"만 갱신
- 자르는 위치마다 `set(topping[:i])`, `set(topping[i:])`를 새로 만들면 O(n²)이다.
- 대신 왼쪽은 빈 상태, 오른쪽은 전부 들고 시작해서 **토핑 하나를 오른쪽 → 왼쪽으로 옮기기만** 한다. 한 번 옮길 때 O(1).

```text
topping = [1, 2, 1, 3, 1, 4, 1, 2]

자르는 위치    왼쪽 종류      오른쪽 종류         같나?
1 | 2 1 3 ...  {1}       1    {1,2,3,4}      4
1 2 | 1 3 ...  {1,2}     2    {1,2,3,4}      4
1 2 1 | 3 ...  {1,2}     2    {1,2,3,4}      4
1 2 1 3 | 1 .. {1,2,3}   3    {1,2,4}        3   ⭕
1 2 1 3 1 | 4  {1,2,3}   3    {1,2,4}        3   ⭕
1 2 1 3 1 4 |  {1,2,3,4} 4    {1,2}          2
                                          → 정답 2
```

### 💡 2. 종류 수는 카운터 변수로 직접 관리
- 왼쪽: 어떤 토핑 개수가 **0 → 1**이 되면 종류 +1.
- 오른쪽: 어떤 토핑 개수가 **1 → 0**이 되면 종류 -1.
- `len(dict)`로 세려면 0이 될 때마다 `del`해야 한다. 변수로 관리하면 그럴 필요가 없다. 보석 쇼핑(67258) 재풀이에서 쓴 방법과 같다.

### 💡 3. `list.count()` vs `Counter`

| | `{t: topping.count(t) for t in types}` | `Counter(topping)` |
|---|---|---|
| 동작 | 종류마다 배열 전체를 훑음 | 배열을 한 번만 훑음 |
| 시간 복잡도 | O(n × 종류 수) | O(n) |
| 100만 × 1만 기준 | 약 100억 번 (2,000종류만 9.4초) | 0.25초 이내 |

`Counter` 사용 시 주의할 점:
- 없는 키를 조회하면 `KeyError` 대신 **0**을 돌려준다.
- `c[k] -= 1`로 0이 되어도 **키가 남는다** → `len(c)`는 "개수가 1 이상인 종류 수"가 아니다.
- `Counter`는 `dict`를 상속하므로 딕셔너리처럼 그대로 쓰면 된다.

## 4. 디버깅 & 실수했던 포인트 정리

1. **변수 이름이 비슷하면 헷갈린다**:
   - `types`(set)와 `topping_length`(종류 수), `length`(케이크 길이)를 섞어 썼다.
   - `counts = [0, types]`, `range(topping_length)` 두 실수 모두 여기서 나왔다.
2. **반복문 안이나 컴프리헨션 안의 `count()`**:
   - 두 큐(118667)의 `sum()`과 같은 실수다. **배열 전체를 훑는 함수를 반복 안에서 부르면 O(n²)**이 된다.
   - 개수 세기는 `Counter`나 반복문 한 번으로 미리 만들어 둔다.
3. **제출 전 `print` 지우기**: 입력이 100만이면 출력이 실행 시간을 크게 잡아먹는다.

---

## 5. 복잡도 분석

- **시간 복잡도**: $O(n)$
  - `set`, `Counter` 만들기 O(n) + 자르는 위치 n개, 각 O(1).
- **공간 복잡도**: $O(k)$ (k = 토핑 종류 수, 최대 1만)
  - 왼쪽/오른쪽 딕셔너리.

---

## 6. 남은 개선점

- `brothers[0]`, `brothers[1]`, `counts[0]`, `counts[1]` 대신 `left`, `right`, `left_kinds`, `right_kinds`처럼 이름을 붙이면 읽기 쉽다.
- 왼쪽도 `Counter()`로 시작하면 `{t: 0 for t in types}` 줄이 필요 없다 (없는 키는 0).
- `types`는 길이를 구할 때만 쓰므로 `len(set(topping))` 한 줄로 합칠 수 있다.
- `range(length)`로 마지막 칸까지 돌아도 오른쪽이 비면 종류 수가 0이라 답에 영향이 없다. `range(length - 1)`로 쓰면 의도가 더 분명하다.

---

## 7. 결론 및 배운 점
- 처음 떠올린 "왼쪽은 비우고, 오른쪽은 다 들고 시작해서 한 칸씩 옮기기"가 그대로 정답 구조였다. 실수는 변수 혼동과 `count()` 사용 두 가지였다.
- **개수 세기는 `Counter`**. 배열 전체를 훑는 함수(`count()`, `sum()`, `in list` 등)를 반복 안에서 부르고 있지 않은지 제출 전에 꼭 확인하자.
- 보석 쇼핑에서 익힌 "종류 수를 카운터 변수로 관리하기"를 이번에도 그대로 썼다.
