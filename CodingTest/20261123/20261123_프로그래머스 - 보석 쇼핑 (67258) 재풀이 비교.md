# 프로그래머스 - 보석 쇼핑 (67258) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/67258

이전 풀이 정리: [20260809_프로그래머스 - 보석 쇼핑 (67258).md](../../KTB4/CodingTest/20260809_프로그래머스%20-%20보석%20쇼핑%20(67258).md)

## 문제 요약
- 진열된 보석 목록 `gems`가 주어진다.
- 모든 종류의 보석을 적어도 하나씩 포함하는 **가장 짧은 연속 구간**을 찾는다.
- 같은 길이의 구간이 여러 개면 시작 번호가 가장 작은 구간을 반환한다 (1번부터 시작).
- `gems` 길이는 최대 100,000이라 O(n)이 필요하다.

## 핵심 아이디어 (두 풀이 공통)
- **투 포인터(슬라이딩 윈도우)** + 구간 안 보석별 개수를 세는 딕셔너리.
- 오른쪽을 늘려 모든 종류를 채우고, 모든 종류가 들어 있는 동안 왼쪽을 줄이면서 가장 짧은 구간을 갱신한다.
- `left`, `right` 모두 앞으로만 움직이므로 O(n).

## 이전 풀이 (2026.08.09, Python)

```python
"""
딕셔너리에 하나씩 넣기
    
buy = {DIA: [],RUBY}
슬라이딩 윈도우 
왼쪽 오른쪽
처음에 오른쪽으로 dict에 하니씩넣으면서 증가
    
    set의 수가 종류의 수랑 같으면 왼쪽 증가로 변경
왼쪽 오른쪽이랑 동일할때까지 증가
"""
def solution(gems):
    answer = [-1,100000]
    length = len(gems)
    types = len(set(gems))
    buy = dict()
    left,right = 0 , 0

    if types == 1:
        return [1,1]
    
    while right < length :
        
        while len(buy) < types and right < length :
            if gems[right] in buy:
                buy[gems[right]] += 1
            else:
                buy[gems[right]] = 1
            
            if len(buy) == types and answer[1] - answer[0]  > right - left:
                answer = [left, right] 
            right+=1
    
        while len(buy) == types and left < right  :
            now = gems[left]
            buy[now] -= 1
            left+=1 
            if buy[now] == 0:
                del buy[now]

            if len(buy) == types and answer[1] - answer[0]  > (right-1) - left:
                answer = [left, right-1]
        
    answer[0]+=1
    answer[1]+=1
    
    return answer
```

- 8월에는 `break`, `right`가 가리키는 위치 불일치 등으로 세 번 실패한 뒤 이 코드로 통과했다. (자세한 과정은 이전 정리 파일 참고)

## 오늘 풀이 (Python, 한 번에 통과)

```python
"""
연속된 길이 가장짧은 합 -> 투포인터

gems의 요소 전부 구하기
"""

def solution(gems):
    
    individuals = set(gems)
    types = len(individuals) 
    gem = dict()
    for i in individuals:
        gem[i] = 0
    
    length = len(gems)
    left = 0
    count = 0
    answer = [0,length+1]
    for right in range(length):
        now = gems[right]
        if gem[now] == 0:
            count+=1
        gem[now] += 1
        
        while count == types:
            if right - left < answer[1] - answer[0]:
                answer = [left, right]
            now = gems[left]
            gem[now] -= 1
            if gem[now] == 0:
                count -= 1
            left+=1
    
    answer[0] +=1
    answer[1] +=1
    return answer
```

## 비교

| 구분 | 이전 풀이 (8월) | 오늘 풀이 |
|---|---|---|
| 핵심 알고리즘 | 투 포인터 + 딕셔너리 | 동일 |
| 반복문 구조 | 바깥 `while` 안에 넓히는 `while`, 좁히는 `while` | `for right` + 좁히는 `while` 하나 |
| 구간 정의 | 넓힐 때 `[left, right]`, 좁힐 때 `[left, right-1]` | 항상 `[left, right]` |
| 정답 확인 위치 | 넓힐 때, 좁힐 때 **두 군데** | 좁히기 직전 **한 군데** |
| 종류 수 세기 | `len(buy)` — 개수가 0이 되면 `del`로 키를 지움 | `count` 변수 — 0 → 1이 될 때 +1, 1 → 0이 될 때 -1 |
| 딕셔너리 준비 | 처음 보는 보석이면 키를 새로 만듦 | 모든 종류를 0으로 미리 채움 |
| 특별 처리 | 종류가 1개면 바로 `[1,1]` 반환 | 없음 |
| 정답 초기값 | `[-1, 100000]` (문제 최대 길이에 맞춘 숫자) | `[0, length+1]` (입력 길이에 맞춤) |
| 시도 횟수 | 3번 실패 후 통과 | 한 번에 통과 |

8월 풀이는 `right`가 "마지막으로 넣은 칸"인지 "다음에 넣을 칸"인지가 루프마다 달라서 `right-1` 보정이 필요했다. 오늘은 `for right`로 오른쪽을 한 칸씩만 늘리고 `[left, right]`를 끝까지 같은 뜻으로 써서, 보정도 특별 처리도 필요 없었다.

## 남은 개선점
- `gem`을 0으로 채우는 반복문은 `gem = {g: 0 for g in individuals}` 한 줄로 줄일 수 있다.
- `now`를 오른쪽 보석과 왼쪽 보석에 번갈아 쓰고 있다. `add`, `remove`처럼 이름을 나누면 읽기 쉽다.
- 8월 풀이의 `if types == 1: return [1,1]`은 빼도 결과가 같았다 (같은 테스트로 확인). 투 포인터가 이 경우도 알아서 처리한다.

## 배운 점
- 8월 정리에서 "`right`의 의미가 루프마다 달라진다"를 배웠는데, 오늘은 처음부터 **`for right` + `[left, right]` 고정**으로 짜서 그 문제를 아예 만들지 않았다.
- 연속된 부분 수열의 합(178870) 최종 코드와 같은 틀(`for right` → 조건 만족하는 동안 `while`로 왼쪽 줄이기 → 한 군데에서 정답 확인)을 이번에도 그대로 썼다. 두 큐 합 같게 만들기(118667)도 같은 투 포인터 구조다. 연속 구간 최소 길이 문제의 기본 틀로 굳혀 두자.
- "종류가 몇 개 들어 있나"는 `len(dict)` + `del` 대신 **카운터 변수 하나**로 관리하면 딕셔너리 키를 지울 필요가 없어 더 단순하다.
