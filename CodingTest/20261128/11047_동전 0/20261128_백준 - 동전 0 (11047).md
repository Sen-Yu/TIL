# 백준 - 동전 0 (11047) 풀이 정리

문제 링크: https://www.acmicpc.net/problem/11047

최종 코드: [11047.py](./11047.py) · 예제 입력: [input.txt](./input.txt)

---

## 1. 문제 요약 및 제약 조건

### 문제 요약
- 동전 N종류가 오름차순으로 주어지고, 각 동전은 개수 제한 없이 쓸 수 있다.
- 합이 K원이 되도록 할 때 **필요한 동전 개수의 최솟값**을 구한다.

### 제약 조건
- N: 1 이상 10 이하, K: 1 이상 100,000,000 이하 (1억)
- A₁ = 1, 그리고 i ≥ 2이면 Aᵢ는 Aᵢ₋₁의 **배수** → 그리디가 성립하는 조건

---

## 2. 고민 과정 및 코드의 발전

### ❌ 1단계: 큰 동전부터 몫만큼 쓰기, `while now > 0` (오답)

```python
import sys
def main():
    input = sys.stdin.readline
    N, K = map(int, input().split())
    A = [ int(input().strip()) for idx in range(N) ]
    now = N-1
    answer = 0
    while now > 0:
        coin = A[now]
        if K // coin > 0:
            answer += K // coin
            K %= coin
        now-=1
    print(f"{answer}")
main()
```

- **아이디어**: 가장 큰 동전부터 `K // coin`개를 쓰고, 남은 금액 `K %= coin`으로 다음 동전으로 넘어간다.
- **문제점**: 직접 고른 10개 케이스 중 6개 오답. 예제 두 개는 통과했다.

| 입력 (N K / 동전) | 결과 | 정답 |
|---|---|---|
| `10 4793` / 1 5 10 … 50000 | `12` | `15` |
| `10 1` / 1 5 10 … 50000 | `0` | `1` |
| `1 7` / `1` | `0` | `7` |
| `2 4` / `1 5` | `0` | `4` |
| `10 66666` / 1 5 10 … 50000 | `9` | `10` |
| `2 8` / `1 3` | `2` | `4` |

  1. **인덱스 0을 처리하지 않음**: `now > 0`이라 `now`가 0이 되면 반복이 끝나서 맨 앞 동전(1원)을 한 번도 쓰지 않는다. 틀린 6개는 모두 마지막에 1원짜리가 필요한 경우였다.
  2. 예제 1(4200), 예제 2(4790)는 1원이 필요 없어서 **우연히 통과**했다.

```text
동전: 1 5     K = 4
now=1 (5)  now > 0 참   → 4 // 5 = 0, 안 씀    K = 4
now=0 (1)  now > 0 거짓 → 반복 종료            1원을 못 봄 → 출력 0 (정답 4)
```

### ⭕ 2단계: `while now >= 0` (통과)

```python
import sys
def main():
    input = sys.stdin.readline
    N, K = map(int, input().split())
    A = [ int(input().strip()) for idx in range(N) ]
    now = N-1
    answer = 0
    while now >= 0:
        coin = A[now]
        if K // coin > 0:
            answer += K // coin
            K %= coin
        now-=1
    print(f"{answer}")
main()
```

- 1단계 힌트("`now`는 어디까지 내려가야 하나?")를 받고 반복 조건 한 줄만 고쳤다.
- 검증: 직접 고른 10개 케이스(예제 2개, 1원 필요, K=1, 동전 1종류, 1원만으로 딱, 큰 동전 하나로 딱, 모든 동전 1개씩, 동전 2종류, 최대 K=1억) 모두 통과. 최대 K 0.02초.
- 백준 제출 통과.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 큰 동전부터 최대한 쓰기 (그리디)

```text
예제 2: K = 4790
동전    몫 (K // 동전)   남은 K (K % 동전)   누적 개수
50000   0                4790                0
10000   0                4790                0
5000    0                4790                0
1000    4                790                 4
500     1                290                 5
100     2                90                  7
50      1                40                  8
10      4                0                   12
5       0                0                   12
1       0                0                   12
출력 12
```

### 💡 2. 왜 그리디가 맞나 — "배수 조건"
- 큰 동전이 작은 동전의 배수라서, 큰 동전 1개로 바꿀 수 있는 작은 동전 묶음이 있으면 바꾸는 쪽이 항상 개수가 적다.
- 그래서 큰 동전을 덜 쓰고 작은 동전으로 채우는 선택은 절대 더 좋아지지 않는다.
- 배수 조건이 없으면 깨진다. 예: 동전 `1 3 4`, K=6 → 그리디는 4+1+1 = **3개**, 최적은 3+3 = **2개**. 이럴 때는 DP가 필요하다.

### 💡 3. 큰 K도 빠른 이유
- 동전을 하나씩 빼지 않고 `//`, `%`로 한 번에 계산해서, 반복은 동전 종류 수(N ≤ 10)만큼만 돈다.

## 4. 디버깅 & 실수했던 포인트 정리

1. **거꾸로 내려가는 반복의 끝 확인**: 인덱스 `N-1`부터 `0`까지 → 조건은 `now >= 0`. 경계는 "마지막으로 처리해야 할 인덱스를 넣었을 때 조건이 참인가"로 확인한다.
2. **예제 통과 ≠ 정답**: 예제는 1원이 필요 없는 금액이라 버그가 숨었다. 가장 작은 원소가 꼭 필요한 케이스(K=1 등)를 넣어 보자.
3. **`for coin in reversed(A):`**: 인덱스를 직접 관리하지 않으면 이런 경계 실수가 생기지 않는다.
4. 작은 것: `if K // coin > 0:`은 없어도 결과가 같다(몫이 0이면 더하는 값도 0, `K`도 그대로). `print(f"{answer}")`는 `print(answer)`와 같다.

---

## 5. 복잡도 분석

- **시간 복잡도**: $O(N)$ — 동전마다 몫·나머지 한 번씩.
- **공간 복잡도**: $O(N)$ — 동전 배열.

## 6. 결론 및 배운 점
- "큰 것이 작은 것의 배수" 같은 조건이 있으면 그리디를 의심하고, 반례(`1 3 4`, K=6)로 조건이 왜 필요한지 확인한다.
- 인덱스로 직접 도는 반복은 **시작과 끝 인덱스를 둘 다** 넣어 보며 조건을 정한다.
