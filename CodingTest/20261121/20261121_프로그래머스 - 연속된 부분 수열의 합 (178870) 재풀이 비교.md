# 프로그래머스 - 연속된 부분 수열의 합 (178870) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/178870

## 문제 요약
- 비내림차순으로 정렬된 수열 `sequence`와 정수 `k`가 주어진다.
- 합이 정확히 `k`인 **연속된 부분 수열** 중 길이가 가장 짧은 구간의 `[시작 인덱스, 끝 인덱스]`를 반환한다.
- 길이가 같은 구간이 여러 개면 **시작 인덱스가 가장 작은** 구간을 반환한다.
- `sequence`의 길이는 최대 1,000,000이라 O(n²)은 불가능하고 O(n)이 필요하다.

## 핵심 아이디어 (두 풀이 공통)
- 모든 원소가 양수이므로 **투 포인터(슬라이딩 윈도우)**를 쓴다.
  - 구간을 넓히면 합이 커지고, 좁히면 합이 작아진다.
  - 합이 `k`보다 작으면 넓히고, 크면 좁힌다.
- 두 포인터가 한 방향으로만 움직이므로 전체 O(n)이다.
- 같은 길이의 구간이 여러 개일 때는 "먼저 찾은 구간 유지"(Python) 또는 "같은 값 구간을 왼쪽 끝으로 밀기"(Java)로 시작 인덱스가 가장 작은 구간을 고른다.

## 과거 풀이 (Java)

```java
class Solution {
    public int[] solution(int[] sequence, int k) {
        int[] answer = new int[2];
        int len = sequence.length;
        
        int start = len-1; 
        int end = len-1;
        int max = len-1;
        
        for(int i = len-1 ; i >= 0 ; i--){
            if(sequence[i] == k){
                answer[0] = i;
                answer[1] = i;
                break;
            }
            else if(sequence[i] < k){
                start = i;
                end = i;
                break;
            }
        }
        
        int sum = 0; 
        answer[0] = start;
        answer[1] = end;
        while(sum != k){       
            while(start >= 0 && sum < k){
                answer[0] = start;
                sum += sequence[start--];
            }
            
            while(end >= start && sum > k){    
                sum -= sequence[end--];
                answer[1] = end;
            }   
        }
        
        int check = sum / (answer[1]-answer[0]+1) ;
        if(check == sequence[answer[1]] && answer[0] > 0){
            int count = 1;
            while(answer[0]-count >= 0 && sequence[answer[0]-count] == sequence[answer[0]]){
                count++;
            }
            answer[0] -= count-1;
            answer[1] -= count-1;
        }
        
        return answer;
    }
}
```

동작 방식:
- **오른쪽 끝에서 왼쪽으로** 탐색한다. 큰 값부터 쓰면 적은 개수로 `k`에 도달하므로, 처음 찾은 구간이 가장 짧다.
- 처음 반복문으로 `k` 이하인 가장 오른쪽 원소를 찾아 시작점으로 잡는다.
- `start`를 왼쪽으로 늘려 합을 키우고, 합이 `k`를 넘으면 `end`를 왼쪽으로 당겨 줄인다.
- 마지막 `check` 부분: 구간 평균이 마지막 원소와 같으면 구간 안의 값이 모두 같다는 뜻이다. 이때 왼쪽에 같은 값이 더 있으면 구간을 그만큼 왼쪽으로 민다. 길이가 같은 구간 중 시작 인덱스가 가장 작은 것을 고르기 위해서다.
- 문제 예제 3개와 랜덤 입력 20,000개(모든 구간을 직접 확인하는 방식과 비교)에서 모두 정답이었다.

## 오늘 풀이 (Python, 직접 풀이 후 최종본)

```python
def solution(sequence, k):
    length = len(sequence)
    answer = [0, length]
    
    left = 0
    
    now = 0
    for right in range(length):
        now += sequence[right]
        
        while now > k:
            now -= sequence[left]
            left+=1
                
        if now == k and right - left < answer[1]-answer[0]:
            answer = [left, right]
    
    return answer
```

## 수정한 내용 (처음 코드 → 2차 → 최종본)

| 단계 | 구조 | 결과 | 문제 / 바뀐 점 |
|---|---|---|---|
| 처음 코드 | 바깥 `while` 안에 넓히는 `while`, 좁히는 `while` + 정답 찾으면 `break` | 예제 1, 2 오답, 예제 3 무한 루프 | 더한 뒤 `right += 1` 해서 정답 기록 구간이 실제 구간과 어긋남. `break` 후 포인터를 안 옮겨 같은 원소를 두 번 더하거나 뺌. `left > right`가 되면 두 `while` 모두 안 돌아 무한 루프. 제출 코드에 `print`가 남아 있음 |
| 2차 코드 | 같은 구조, `break` 제거 | 모두 정답 | 더하기는 "더하고 → 확인 → `right` 이동", 빼기는 "빼고 → `left` 이동 → 확인"으로 순서를 맞춤. 빼는 쪽 구간은 `[left, right-1]`로 기록 |
| 최종본 | `for right` + 좁히는 `while` 하나 | 모두 정답 | 구간을 항상 `[left, right]`(양 끝 포함)로 정의. 좁히는 조건을 `now > k`로 바꿔 정답 확인을 한 곳에서만 함 |

## 비교

| 구분 | 과거 풀이 (Java) | 오늘 풀이 (Python 최종본) |
|---|---|---|
| 핵심 알고리즘 | 투 포인터 | 투 포인터 (동일) |
| 탐색 방향 | 오른쪽 → 왼쪽 (큰 값부터) | 왼쪽 → 오른쪽 |
| 가장 짧은 구간 찾기 | 큰 값부터 쓰니 처음 찾은 구간이 가장 짧음 → 찾으면 종료 | 끝까지 돌면서 더 짧은 구간이 나올 때마다 갱신 |
| 같은 길이 처리 | 평균으로 "모두 같은 값인지" 확인 후 왼쪽으로 밀기 (별도 코드 필요) | `<`로 비교해서 먼저 찾은 구간 유지 (추가 코드 없음) |
| 시작점 잡기 | `k` 이하인 가장 오른쪽 원소를 먼저 찾음 | 0부터 시작 |
| 반복문 구조 | `while(sum != k)` 안에 `while` 두 개 | `for` 하나 + `while` 하나 |
| 시간 복잡도 | O(n) | O(n) |
| 코드 길이 | 약 40줄 | 약 15줄 |

Java 풀이는 "정렬돼 있으니 큰 값부터 쓰면 가장 짧다"는 성질을 이용해 정답을 찾으면 바로 끝낸다. 대신 같은 길이 처리와 시작점 잡기에 코드가 더 필요했다. Python 풀이는 끝까지 다 보지만 규칙이 단순해서 특별히 처리할 경우가 없다.

## 남은 개선점
- `answer = [0, length]`는 "어떤 실제 구간보다 긴 가짜 정답"이라는 의도를 주석으로 남기면 나중에 읽기 쉽다.
- `left+=1`은 `left += 1`로 띄어 쓰면 다른 줄과 스타일이 맞는다.
- Java 풀이의 `int max = len-1;`은 쓰이지 않는 변수다.
- Java 풀이의 첫 반복문에서 `sequence[i] == k`일 때 `answer`에 넣은 값은 바로 아래 `answer[0] = start;`에서 덮어써진다. 결과는 맞지만 의도가 드러나지 않는다.

## 배운 점
- 투 포인터에서는 **"`now`는 항상 어디부터 어디까지의 합인가"**를 먼저 한 문장으로 정해야 한다. 처음 코드의 버그(어긋난 인덱스, 중복 더하기/빼기, 무한 루프)는 모두 이 정의가 코드 곳곳에서 달랐던 데서 나왔다.
- 오른쪽 끝을 `for`로 돌리면 "더한 뒤 언제 포인터를 옮기지?"라는 고민이 사라진다. 한 번 반복할 때 정확히 한 칸만 늘어난다.
- 좁히는 조건을 `> k`로 두면 `while`이 끝난 뒤 합이 항상 `k` 이하라서, 정답 확인을 한 곳에서만 해도 빠지는 경우가 없다.
- "길이가 같으면 시작이 앞선 것" 같은 조건은 탐색 방향을 잘 고르면 `<` 하나로 공짜로 해결된다.
- 길이 100만짜리 입력에서는 `print` 한 줄도 시간 초과의 원인이 될 수 있으니 제출 전에 지운다.
