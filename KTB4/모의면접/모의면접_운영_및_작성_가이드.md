# KTB4 모의면접 스터디 운영 및 작성 가이드 (AI 지침서)

이 문서는 **주 2회 진행되는 모의면접 스터디**와 관련하여 질문 정리, 핵심 지식 문서 작성, 녹음 분석 리포트 작성, 파일명 규칙 등을 규정한 표준 운영 지침(Playbook)입니다. AI는 이후 세션에서 이 가이드를 항상 최우선으로 참고하여 일관된 형식과 품질로 문서를 생성·검토합니다.

---

## 1. 파일 및 폴더 네이밍 규칙

모의면접 스터디는 **주 2회** 지속해서 누적되므로, 체계적인 버전 관리와 날짜 식별이 가능하도록 아래 규칙을 엄격히 준수합니다.

| 분류 | 파일명 패턴 | 실제 예시 | 설명 |
| :--- | :--- | :--- | :--- |
| **주차별 질문 & 지식 문서** | `{N}주차_{주제}.md` | `3주차_파이썬.md`, `3주차_웹.md` | 주차별 면접 예상 질문과 핵심 지식/용어 정리 |
| **모의면접 녹음 파일** | `{N}주차 MM.DD(요일).m4a` | `3주차 09.14(월).m4a` | 실제 진행된 모의면접 음성 녹음 원본 |

## 2. 주차별 질문 & 핵심 지식 문서 작성 표준

### 2.1. 작성 원칙
1. **완성형 문장 대신 지식 요약 제공:** 면접자가 달달 외우는 답변이 아니라, 핵심 지식을 보고 **자신의 언어로 직접 답변을 구성**할 수 있도록 요약합니다.
2. **반드시 질문 원문 포함:** 어떤 질문에 대응하는 지식인지 한눈에 알 수 있도록 항목 제목 바로 아래에 `> **질문:** ...` 인용구로 명시합니다.
3. **핵심 포인트 + 필수 용어 분리:** '원리와 실무 팁'은 핵심 지식 포인트에, '면접에서 쓰기 좋은 전문 단어'는 용어 해설에 분리 배치합니다.
4. **실무 및 꼬리 질문 대비 팁(차별화 포인트) 포함:** 단순 교과서 지식이 아니라 구체적 수치(메모리 절감율 등), 실무 도구(Ruff, Mypy, SSE 등), 언어 간 비교(Java JVM 등)를 반드시 곁들입니다.

### 2.2. 문서 템플릿 (면접자 & 면접관 공용)
```markdown
# {N}주차 {주제} 모의면접 핵심 정리 & 면접관 체크리스트

### {번호}. {항목 요약 제목}
> **질문:** {실제 면접 질문 전문}

**🎯 면접관 필수 체크 키워드:**
*   [ ] **{핵심 키워드 1}:** 설명 및 평가 기준
*   [ ] **{핵심 키워드 2}:** ...
*   [ ] **{핵심 키워드 3}:** ...

**💡 핵심 지식 포인트:**
*   **원리 및 핵심 개념:** ...
*   **비교 및 장단점:** ...
*   **💡 실무 보완 팁:** (구체적 수치, 언어 간 비교, 실무 안티패턴 방지책)

**🔍 심층 꼬리 질문 & 대응 가이드 (면접관용):**
*   **Q1. "{면접관이 파고들 날카로운 심층 꼬리 질문 1}"**
    *   👉 **답변 포인트:** ...
*   **Q2. "{또 다른 각도의 실무/아키텍처 꼬리 질문 2}"**
    *   👉 **답변 포인트:** ...

**📚 필수 핵심 용어 해설:**
*   **{전문 용어 1}:** 개념 정의 및 쉬운 비유/원리
*   **{전문 용어 2}:** ...
```

## 3. 모의면접 녹음 분석 및 피드백 표준

### 3.1. 분석 및 평가 기준 (Rubric)
1. **기술적 팩트의 정확성 (Fact Check):**
   * 답변한 내용 중 잘못된 컴퓨터 공학 개념이나 라이브러리 스펙이 없는지 정밀 검증.
2. **질문 의도와의 일치도 (Direct Answer):**
   * 묻는 말에 회피하지 않고 두괄식으로 핵심을 짚었는가?
3. **꼬리 질문 대처 및 논리 전개 (Resilience & Logic):**
   * 면접관의 압박/추가 질문에 당황하지 않고 배경 지식을 기반으로 유연하게 방어했는가?
4. **추가 권장 키워드 제시:**
   * 실무에서 면접관이 듣고 싶어 하는 결정적 키워드(예: Generator, EAFP vs LBYL, SSE, Offloading 등)를 보완점으로 제안.

## 4. 모의면접 단골 주제별 핵심 기술 키워드 체크리스트

AI는 사용자 질문 작성 및 답변 검토 시 아래 핵심 키워드들이 누락되지 않도록 체크합니다.

### 🐍 Python
- [ ] 실행 구조: `.py` -> 컴파일 -> `.pyc` (바이트코드) -> PVM 인터프리트
- [ ] 컴파일 언어 및 Java와의 차이: Java의 JVM + JIT 컴파일러 대비 PVM의 특성
- [ ] 동적 타이핑 & GIL: 런타임 타입 에러, CPython 단일 스레드 락의 한계, `mypy` 정적 분석
- [ ] 메모리 최적화: `Generator`(`yield`), 지연 평가(Lazy Evaluation), `__slots__`, `for line in f:`
- [ ] 예외 처리: 스택 언와인딩(Stack Unwinding) 오버헤드, LBYL vs EAFP, 포괄적 `except Exception` 안티패턴

### 🌐 Web / Backend (FastAPI)
- [ ] 보안 (HTTPS): SSL/TLS 핸드셰이크, 비대칭키(키 교환) + 대칭키(데이터 암호화) 하이브리드, 무결성/인증
- [ ] 데이터 검증: Pydantic 자동 타입 캐스팅, `422 Unprocessable Entity`, `@field_validator`
- [ ] 오류 처리: 4xx vs 5xx 상태 코드 엄격 분리, 스택 트레이스 은닉(정보 유출 방지), 커스텀 예외 + 전역 핸들러
- [ ] 동시성/비동기: 동시성(Concurrency) vs 병렬성(Parallelism), I/O 바운드 vs CPU 바운드
- [ ] FastAPI 비동기의 비밀: `async def` 안에서의 CPU 블로킹 위험, 일반 `def`의 스레드 풀 위임(Threadpool)
- [ ] AI 서비스 아키텍처: 비동기 태스크 큐(Celery/Redis) 오프로딩, SSE(Server-Sent Events) 스트리밍
