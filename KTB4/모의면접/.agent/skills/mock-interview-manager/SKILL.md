# KTB 모의면접 관리 및 자동 분석 스킬 (Mock Interview Manager)

이 스킬은 사용자가 음성 메모를 드래그하여 추가하거나 새로운 모의면접 질문/녹음을 공유했을 때, **파일 정리, 음성 분석, 피드백 리포트 작성, 주차별 폴더 관리**를 표준화된 절차에 따라 자동으로 수행합니다.

---

## 1. 활성화 시점 (When to Activate)

* 사용자가 음성 메모 파일(예: `삼평동.m4a` 등)을 폴더에 넣고 이름 변경 또는 분석을 요청할 때
* 새로운 모의면접 질문을 등록하고 핵심 지식 정리를 요청할 때
* 주차별 폴더 정리 및 다음 주차 대비 폴더 생성을 요청할 때
* 이전 모의면접 진행 결과와 비교 분석을 요청할 때

---

## 2. 워크플로우 (Step-by-Step Workflow)

### 1단계: 음성 파일 감지 및 네이밍 표준화
1. 작업 폴더(`/Users/emet/TIL/KTB4/모의면접`) 내에 새로 추가된 `.m4a` 파일(예: Apple 음성 메모 기본 위치명인 `삼평동.m4a`, `새로운 녹음.m4a` 등)을 감지합니다.
2. 현재 날짜와 요일을 확인합니다 (예: `2026-09-16 (수)`).
3. 진행 중인 주차를 파악하여 아래 규칙으로 이름을 변경합니다:
   * **형식:** `{N}주차 MM.DD(요일).m4a` (예: `3주차 09.16(수).m4a`)

### 2단계: 주차별 폴더 정리 (Directory Management)
* **루트 폴더(`.../모의면접/`) 유지 파일:**
  * `모의면접_운영_및_작성_가이드.md` (AI가 언제든 참조해야 하므로 루트에 보관)
* **주차별 폴더(`{N}주차/`)로 이동할 파일들:**
  * `{N}주차_{주제}.md` (예: `3주차_파이썬.md`, `3주차_웹.md`)
  * `{N}주차 MM.DD(요일).m4a` (음성 녹음 파일)
  * `모의면접_분석결과_{YYYYMMDD}.md` (해당 회차 분석 리포트)
* **다음 주차 폴더 준비:**
  * 다음 주차 폴더(`{N+1}주차/`)가 없다면 미리 생성해 둡니다.

### 3단계: 음성 파일 청취 및 심층 분석
1. `view_file` 도구를 사용해 해당 `.m4a` 오디오 파일을 전체 청취합니다.
2. 해당 주차의 질문 문서(`{N}주차_{주제}.md`)를 기준으로 면접자의 답변을 대조 분석합니다.
3. 평가 루브릭(Fact Check, Direct Answer, Seniority/Nuance)을 적용합니다.

### 4단계: 분석 결과 리포트 작성
* **저장 위치:** `{N}주차/모의면접_분석결과_{YYYYMMDD}.md`
* **헤더 메타데이터:**
  * `# [{YYYY-MM-DD}] {주제} 모의면접 분석 결과 리포트 ({N}주차 {회차}회차)`
  * 일시, 진행 방식, 다룬 주제 명시
* **본문 구성:**
  1. **총평:** 이전 회차 대비 발전된 점, 전반적인 논리와 톤앤매너 평가
  2. **질문별 세부 분석:** 답변 요약 / 👍 잘한 점 / 💡 개선 팁
  3. **종합 조언:** 스터디 방식 피드백, 실전 면접용 두괄식 템플릿 제안

---

## 3. 핵심 규칙 및 주의사항
* **루트 보존:** AI 가이드 문서(`모의면접_운영_및_작성_가이드.md`)는 절대 주차별 하위 폴더로 이동하지 않습니다.
* **자신감 고취:** 기술적으로 깊이 있는 답변(예: CPU 블로킹, Fallback 등)을 했을 때는 면접자가 위축되지 않도록 강하게 칭찬하고 실전 무기로 쓸 수 있게 격려합니다.
* **이원화 사고 유지:** 개발자 중심의 아키텍처(422, Task Queue)와 최종 사용자 중심의 UX(친절한 언어, 입력값 보존, 폴백)를 명확히 구분하여 피드백합니다.
