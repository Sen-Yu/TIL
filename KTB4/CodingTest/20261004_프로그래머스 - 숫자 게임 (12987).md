# 프로그래머스 - 숫자 게임 (12987) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/12987

## 문제 요약
- A팀과 B팀이 각자 N개의 숫자를 가지고 1:1로 맞붙는다.
- 승리 조건은 B팀의 숫자가 A팀의 숫자보다 **엄격히 클 때(>)** 뿐이다. (같으면 승점 없음)
- A팀의 출전 순서를 미리 알고 있을 때, B팀의 출전 순서를 자유롭게 배치하여 B팀이 얻을 수 있는 **최대 승점**을 구하는 문제.

## 아이디어
- 전형적인 **그리디(Greedy)** 알고리즘 문제. 
- "A팀의 큰 숫자를 B팀의 가급적 '가장 아슬아슬하게 큰 숫자'로 이기는 것"이 최적해지만, 이를 구현하기 위해 **내림차순 정렬**을 활용한다.
- A와 B를 모두 내림차순(`reverse=True`)으로 정렬하고, 각 팀의 가장 큰 숫자부터 맞붙여 본다.
    1. **B팀의 가장 큰 수가 A팀의 현재 수보다 크다면?**
       - 무조건 이기는 게 이득이므로 승점을 올리고(`answer += 1`), B팀도 그다음으로 큰 숫자를 꺼낸다(`left += 1`).
    2. **B팀의 가장 큰 수가 A팀의 현재 수보다 작거나 같다면?**
       - B팀에서 가장 큰 숫자로도 못 이긴다면, B팀의 그 어떤 숫자로도 현재 A를 이길 수 없다.
       - 따라서 B팀의 가장 '작은(쓸모없는)' 숫자를 제물로 바쳐 A팀의 큰 카드를 허비하게 해야 한다.
       - **[핵심 로직]** 코드에서는 쓸모없는 숫자를 직접 찾아서 버리지 않고, **B팀의 포인터(`left`)를 멈춰둔 채 A팀의 탐색만 다음으로 넘어감**으로써 이 동작을 완벽히 대체했다! (가장 큰 B 카드를 아꼈다가 다음 A 카드와 싸우게 함)

## 배운 점
- 메모하신 *"큰 수끼리 싸우게 하고 A한테 진다면 가장 작은 수 보내자"*라는 투 포인터(양방향) 아이디어를, **포인터 1개(`left`)만 멈춰 세우는 방식**으로 초압축하여 구현해 낸 매우 우아하고 훌륭한 코드다.
- 만약 제일 작은 수를 찾기 위해 `pop()`을 하거나 끝에서부터 `right` 포인터를 당겨왔다면 코드가 훨씬 길어지고 복잡해졌을 것이다. A팀의 카드만 소모시키고 B팀의 에이스 카드(`B[left]`)는 다음 대결을 위해 보존하는 이 방식은 그리디 구현의 정석이자 정점이다.
- 구명보트 문제 때 다듬어졌던 정렬 + 포인터 감각이 이번 문제에서 100% 폭발했다.

## 최종 코드
```python
def solution(A, B):
    answer = 0
    # 1. 두 배열 모두 내림차순 정렬
    A.sort(reverse=True)
    B.sort(reverse=True)
    
    # 2. B팀의 가장 강한 카드(현재 남은 가장 큰 수)를 가리키는 포인터
    left = 0
    
    # 3. A팀의 가장 강한 카드부터 순서대로 꺼내며 대결
    for a in A:
        # B팀의 에이스 카드가 A를 이길 수 있다면
        if B[left] > a:
            answer += 1
            left += 1  # 이겼으므로 B팀은 다음 카드를 꺼냄
        
        # 만약 못 이긴다면, B팀의 포인터는 그대로 두고 A만 소모시킴 
        # (암묵적으로 B팀의 가장 약한 카드를 내보낸 것과 동일한 효과)
            
    return answer
```
