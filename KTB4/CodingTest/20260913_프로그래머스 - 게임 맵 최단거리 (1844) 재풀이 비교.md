# 프로그래머스 - 게임 맵 최단거리 (1844) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1844

## 문제 요약
- `n × m` 크기의 게임 맵이 주어진다. 각 칸은 `1`(이동 가능) 또는 `0`(벽)이다.
- `(0, 0)`에서 시작해서 `(n-1, m-1)`까지 이동할 수 있는 **최단 칸 수**를 구한다.
- 도착 지점에 도달할 수 없으면 `-1`을 반환한다.
- 가중치 없는 격자의 최단 거리 문제이므로 BFS로 접근한다.

## 이 문서의 목적
같은 문제를 과거(2026-08-01)와 오늘(2026-09-13) 두 번 풀었다. 두 풀이 모두 BFS 정답이지만, 그 사이에 BFS를 다루는 방식이 어떻게 달라졌는지 비교해서 정리한다.

## 과거 코드 (2026-08-01) — maps 배열 재활용 방식

```python
"""
최단 거리 -> BFS
도착X -> -1
"""
from collections import deque
def solution(maps):
    answer = 0
    n = len(maps)
    m = len(maps[0])
    dx = [-1,1,0,0]
    dy = [0,0,-1,1]
    visited = [[False] * m for _ in range(n)]
    visited[0][0] = True
    que = deque([[0,0]])

    while que:
        x, y = que.popleft()

        for d in range(4):
            next_x = x + dx[d]
            next_y = y + dy[d]

            if next_x >= 0 and next_x < m and next_y >= 0 and next_y < n :
                if maps[next_y][next_x] > 0 and not visited[next_y][next_x] :
                    maps[next_y][next_x] = maps[y][x] + 1
                    visited[next_y][next_x] = True
                    que.append([next_x,next_y])

    if maps[n-1][m-1] == 1:
        return -1

    return maps[n-1][m-1]
```

- 거리를 `maps` 배열 자체에 덮어써서(`maps[next_y][next_x] = maps[y][x] + 1`) 기록한다. 시작점 값이 `1`이라, 도착점의 최종 값이 곧 이동 칸 수가 된다.
- 도착 여부와 무관하게 큐가 빌 때까지 도달 가능한 모든 칸을 끝까지 탐색한다.
- 마지막에 `maps[n-1][m-1]`이 시작값 `1` 그대로면 도달 실패로 보고 `-1`을 반환한다.

## 오늘 코드 (2026-09-13) — 큐에 거리 저장 + 조기 종료 방식

```python
"""
최솟값 -> 최단거리
bfs
맵 탈출, 벽만나는 경우
"""
dy = [0,0,1,-1]
dx = [1,-1,0,0]
from collections import deque
def solution(maps):
    answer = -1
    ## 시작 지점 1,1 -> 0,0
    y, x = 0, 0
    y_maps = len(maps)
    x_maps = len(maps[0])

    visited = [[False] * x_maps for _ in range(y_maps)]

    que = deque()
    que.append([1,y,x])
    visited[0][0] = True
    flag = False

    while que and not flag:

        turn, now_y, now_x = que.popleft()

        for d in range(4):
            if 0 <= now_y + dy[d] < y_maps and 0 <= now_x + dx[d] < x_maps and not visited[now_y + dy[d]][now_x + dx[d]] and maps[now_y + dy[d]][now_x + dx[d]] == 1:
                if now_y + dy[d] == y_maps-1 and now_x + dx[d] == x_maps-1 :
                    answer = turn+1
                    flag = True
                    break
                else:
                    que.append([turn+1, now_y + dy[d], now_x + dx[d]])
                    visited[now_y + dy[d]][now_x + dx[d]] = True

    return answer
```

- 거리(`turn`)를 큐의 각 원소에 함께 담아서(`[turn, y, x]`) 나르고, `maps`는 읽기 전용으로만 사용한다.
- 도착점에 처음 도달하는 순간 `answer`에 기록하고 `flag`로 BFS를 즉시 종료한다.
- 도착 직전 노드는 어차피 다시 꺼내지 않으므로, 큐에 넣거나 방문 처리하지 않고 바로 멈춘다(군더더기 제거).

## 두 코드 비교

| 구분 | 과거 코드 (08-01) | 오늘 코드 (09-13) |
|---|---|---|
| 거리 저장 위치 | `maps` 배열에 직접 덮어씀 | 큐 원소에 `turn`으로 함께 저장 |
| 원본 입력 | 변형됨 | 그대로 보존 |
| 상태 관리 | `maps` 하나가 벽 정보 + 거리를 겸함 | 벽 정보(`maps`)와 거리(큐)를 분리 |
| 종료 방식 | 큐가 빌 때까지 전체 탐색 후 도착점 값 확인 | 도착 즉시 조기 종료(`flag`) |
| 도달 불가 판정 | 도착점 값이 시작값 `1` 그대로인지 확인 | `answer` 초기값 `-1`이 그대로 반환됨 |
| 시간복잡도 | O(n×m) | O(n×m) |

## 무엇이 달라졌는가 (풀이 방식의 변화)
1. **원본 데이터를 건드리지 않는 방향으로 바뀌었다.** 과거엔 `maps`에 거리를 덮어써 입력을 변형했지만, 오늘은 거리를 큐에 실어 나르고 `maps`는 읽기만 한다. 입력을 부작용 없이 다루려는 감각이 생겼다.
2. **필요한 만큼만 탐색하고 멈추는 최적화가 추가됐다.** 과거엔 도착 여부와 무관하게 끝까지 탐색했지만, 오늘은 도착하는 즉시 종료한다. "목표를 찾으면 바로 멈춘다"는 사고가 반영됐다.
3. **관심사를 분리했다.** 과거엔 `maps` 배열 하나에 벽 정보와 거리를 함께 담았지만, 오늘은 벽 정보와 거리 정보를 서로 다른 자료구조로 나눠 관리한다.

## 아직 더 다듬을 여지 (다음 단계)
- 오늘 코드는 **이웃을 탐색하면서(자식을 보면서)** 도착 판정을 하기 때문에, 내부 `for`문 안에 "이동"과 "도착 판정"이 섞여 있고 `flag`/`break`가 필요하다.
- 대신 **큐에서 꺼내는 순간(자기 자신을 보면서)** 도착 판정을 하면, 내부 `for`문은 "이웃을 큐에 넣기"라는 하나의 역할만 하게 되어 더 단순해진다. 이 경우 `flag`, `break`, 이웃 판정 안의 도착 분기가 모두 사라지고, 시작점이 곧 도착점인 예외(1×1 맵)도 자연스럽게 처리된다.
- 즉, 조기 종료라는 방향은 옳았고, 이제는 그 판정을 "어디에서 하느냐"를 더 깔끔하게 다듬는 것이 다음 단계다.

## 배운 점
- 같은 문제를 다시 풀어보면, 알고리즘의 기본기(BFS 자체)는 그대로여도 그 위에 데이터 관리와 효율성에 대한 감각이 어떻게 쌓였는지 확인할 수 있다.
- "배열 하나에 여러 의미를 담아 끝까지 도는" 방식에서, "관심사를 분리하고, 원본을 보존하고, 목표를 찾으면 멈추는" 방식으로 발전한 것이 이번 재풀이의 핵심 변화다.
- 리팩터링의 다음 단계는 동작을 바꾸는 것이 아니라, 같은 동작을 더 명확하고 간결한 구조로 표현하는 것(예: 도착 판정 위치 조정)이라는 점도 확인했다.
