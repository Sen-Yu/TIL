# 프로그래머스 - 게임 맵 최단거리 (1844) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1844

## 문제 요약
- `n × m` 크기의 게임 맵이 주어진다. 각 칸은 `1`(이동 가능) 또는 `0`(벽)이다.
- `(0, 0)`에서 시작해서 `(n-1, m-1)`까지 이동할 수 있는 **최단 칸 수**를 구한다.
- 도착 지점에 도달할 수 없으면 `-1`을 반환한다.

## 아이디어
- 가중치 없는 격자에서의 최단 거리 문제이므로 BFS로 접근한다.
- 별도의 거리 배열을 두지 않고, `maps` 배열 자체를 재활용했다. 시작점의 값은 원래 `1`이고, 이동 가능한 칸에 도착할 때마다 `maps[y][x] = maps[이전 칸] + 1`로 덮어써서 그 칸이 몇 번째 칸인지를 기록한다.
- `visited` 배열로 방문 여부를 따로 관리해 같은 칸을 중복 처리하지 않도록 했다.
- 상하좌우 이동은 `dx`, `dy` 델타 배열로 4방향을 순회하며 처리했다.
- BFS가 끝난 뒤 `maps[n-1][m-1]`이 시작값 그대로인 `1`이면 도착점에 한 번도 방문하지 못했다는 뜻이므로 `-1`을 반환하고, 그렇지 않으면 그 값이 곧 최단 이동 칸 수가 된다.

## 발생했던 문제
없음. 이전 문제들에서 다룬 BFS 패턴(방문 처리, 큐를 이용한 레벨별 확장)을 그대로 응용해서 막힘없이 풀렸다.

## 배운 점
- 최단 거리를 별도의 `distance` 배열 없이, 이동 가능 여부를 나타내던 배열(`maps`) 자체에 누적 값을 덮어써서 재활용할 수 있다. 메모리를 아낄 수 있는 방식이지만, 원본 입력을 변형한다는 점은 유의할 부분이다.
- `dx`, `dy` 델타 배열로 4방향(상하좌우)을 순회하는 패턴은 격자 기반 BFS/DFS 문제에서 반복적으로 쓰이는 정형화된 기법이다.
- "도달 불가능"을 판별할 때, 시작값과 동일한 값이 도착점에 그대로 남아있는지를 확인하는 방식으로 별도의 플래그 없이 처리할 수 있다.


~~~
"""
최단 거리 -> BFS
도착X -> -1 
"""
from collections import deque
def solution(maps):
    answer = 0
    n = len(maps)
    m = len(maps[0])
    dx = [-1,1,0,0]
    dy = [0,0,-1,1]
    visited = [[False] * m for _ in range(n)]
    #maps[0][0] = 1
    visited[0][0] = True
    que = deque([[0,0]])
    
    while que:
        x, y = que.popleft()
        
        for d in range(4):
            next_x = x + dx[d]
            next_y = y + dy[d]
            
            if next_x >= 0 and next_x < m and next_y >= 0 and next_y < n :
                if maps[next_y][next_x] > 0 and not visited[next_y][next_x] :
                    maps[next_y][next_x] = maps[y][x] + 1
                    visited[next_y][next_x] = True
                    que.append([next_x,next_y])
                    
                    #print(f"({next_x},{next_y}) = {maps[next_y][next_x]}")
        
    if maps[n-1][m-1] == 1:
        return -1
    
    return maps[n-1][m-1]
~~~
