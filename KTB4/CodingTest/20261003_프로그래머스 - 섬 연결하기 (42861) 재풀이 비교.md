# 프로그래머스 - 섬 연결하기 (42861) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42861

## 문제 요약
- $N$개의 섬과 다리를 짓는 비용이 주어질 때, 최소의 비용으로 모든 섬이 서로 통행 가능하도록 연결하는 문제.
- 그리디 탐색인 **최소 신장 트리(MST)**, 그중에서도 **프림(Prim) 알고리즘**을 요구하는 문제다.

## 과거 풀이
```python
import heapq
def solution(n, costs):
    answer = 0
    bridges = dict()
    
    for a, b, cost in costs:
        if not a in bridges: bridges[a] = list()
        if not b in bridges: bridges[b] = list()
        heapq.heappush(bridges[a],[cost, b])
        heapq.heappush(bridges[b],[cost, a])
    
    visited = [False]* (n)
    visited[0] = True
    primary_que = list()
    
    def insert_primary(num):
        for _ in range(len(bridges[num])): 
            now = heapq.heappop(bridges[num])
            heapq.heappush(primary_que, now)
            
    insert_primary(0)
    
    while False in visited:
        cost, b = heapq.heappop(primary_que)
        while visited[b]:
            cost, b = heapq.heappop(primary_que)
        
        answer += cost
        visited[b] = True 
        insert_primary(b)
     
    return answer
```
- 엣지(간선)들을 방문 큐(`primary_que`)로 옮기기 위해 `insert_primary`라는 내부 함수를 만들고, 원본 딕셔너리(`bridges`)에서 값을 `pop`해서 옮기는 방식을 썼다.
- 반복문 조건으로 `while False in visited:`를 사용하여 매번 방문 배열 전체를 $O(N)$으로 검사했다.
- 목적지가 이미 방문한 곳이라면 `while visited[b]:`로 연속해서 `pop`을 날리며 걸러냈다.

## 오늘(새) 풀이
```python
import heapq

def solution(n, costs):
    answer = 0
    cost_heap = dict()
    
    for bridge in costs:
        i1, i2, cost = bridge
        if i1 not in cost_heap: cost_heap[i1] = list()
        if i2 not in cost_heap: cost_heap[i2] = list()
        
        heapq.heappush(cost_heap[i1], [cost,i2])
        heapq.heappush(cost_heap[i2], [cost,i1])
    
    visited = [False for _ in range(n)]
    connects = 1
    visited[0] = True
    wait_heap = list(cost_heap[0])
    
    while connects < n:
        cost, i = heapq.heappop(wait_heap)

        if not visited[i]:
            visited[i] = True
            connects+=1
            answer+=cost

            for c in cost_heap[i]:
                heapq.heappush(wait_heap, c)

    return answer
```
- 원본 딕셔너리를 비우지 않고, `for c in cost_heap[i]:`로 간선 정보만 조회한 뒤 우선순위 큐(`wait_heap`)에 깔끔하게 집어넣었다.
- 최소 신장 트리(MST)의 성질을 완벽히 이용해 **"연결된 노드의 수(`connects`)가 `n`개가 되면 즉시 중단"**하도록 루프 조건을 최적화했다.
- 복잡했던 중첩 루프(`while visited[b]:`)를 제거하고, 단순히 꺼낸 노드가 방문하지 않은 곳일 때만(`if not visited[i]:`) 처리하도록 로직을 아주 직관적으로 수정했다.

## 비교

| 구분 | 과거 풀이 | 오늘(새) 풀이 |
|---|---|---|
| 루프 종료 조건 | `while False in visited:` (매 루프 $O(N)$ 탐색) | `while connects < n:` (목표 달성 시 큐에 남은 원소를 무시하고 조기 종료!) |
| 원본 그래프 데이터 | `insert_primary`로 pop 시켜 원본 데이터가 소멸됨 | 조회만 하므로 원본 그래프 데이터(`cost_heap`) 보존 |
| 방문 필터링 로직 | `while visited:` 로 방문 안 한 노드가 나올 때까지 연속 pop | 단일 `if not visited:` 구문으로 통과 여부만 체크 |
| 코드 가독성 | 여러 중첩 구조와 외부 함수 의존으로 흐름 파악이 조금 어려움 | 프림 템플릿의 정석이자 최적화까지 챙겨 매우 완벽함 |

## 배운 점
- 프림 알고리즘의 본질을 완벽하게 이해하고 체화했다는 것을 보여주는 완벽한 리팩터링이다. 과거의 코드는 "일단 돌아가게 짜자"는 느낌이 강했다면, 오늘의 코드는 **우선순위 큐(Priority Queue)를 사용하는 전형적인 그래프 탐색 템플릿**에 딱 들어맞는 정석 그 자체다.
- 루프 조건문에서 배열을 탐색하던 $O(N)$ 비효율성(`False in visited`)을 `connects < n`이라는 $O(1)$ 변수 비교로 바꾼 것은 퍼포먼스 측면에서 매우 큰 발전이다. 특히 큐가 빌 때까지 도는 것(`while wait_heap:`)보다, **모든 섬이 연결되자마자 불필요한 연산 없이 즉시 탈출**하는 조기 종료 최적화가 프림 알고리즘의 핵심을 제대로 관통했다.
- 방문 여부를 체크할 때 `while`문으로 억지로 솎아내는 대신, `if`문 하나로 쿨하게 넘기는 로직(이미 방문했으면 그냥 스킵)은 다익스트라나 BFS 등 다른 큐 기반 탐색에서도 동일하게 쓰이는 아주 안정적인 구조다.

**[추가 팁]**
초기화 시 딕셔너리에 간선을 넣을 때 `heapq.heappush` 대신 단순 리스트 추가 `cost_heap[i1].append([cost, i2])`를 써도 됩니다! 어차피 `wait_heap`에 들어가면서 다시 자동 정렬되기 때문입니다.

## 📚 개념 보충: 프림(Prim) 알고리즘이란?

**프림 알고리즘**은 그래프에서 **최소 신장 트리(Minimum Spanning Tree, MST)**를 찾기 위한 대표적인 그리디(Greedy) 알고리즘입니다. 

### 핵심 원리 ("내 영토 넓히기")
1. 아무 노드나 하나 골라서 시작점(시작 영토)으로 삼습니다. (보통 0번 노드)
2. 현재까지 내 영토에 연결된 모든 간선들 중 **'가장 비용이 싼 간선'**을 찾습니다.
3. 그 간선이 내 영토에 포함되지 않은 '새로운 노드'로 향한다면, 비용을 지불하고 그 노드를 내 영토로 편입시킵니다. (만약 이미 내 영토인 노드라면 무시합니다 -> `if not visited[i]`)
4. 모든 노드가 내 영토가 될 때까지 2~3번 과정을 반복합니다.

### 왜 `heapq`(우선순위 큐)를 쓸까요?
매번 "내 영토와 연결된 간선 중 가장 싼 것"을 가장 빠르게 찾기 위해서입니다. 
새로운 노드를 영토에 편입시킬 때마다 그 노드에 달린 간선들을 전부 우선순위 큐에 부어 넣으면, 다음 탐색 때 큐가 알아서 가장 싼 간선을 뱉어주므로 매우 효율적($O(E \log V)$)입니다.

### 크루스칼(Kruskal) 알고리즘과의 차이점
최소 신장 트리를 구하는 또 다른 유명한 방법으로 '크루스칼 알고리즘'이 있습니다.
- **프림(Prim)**: 특정 시작점에서 출발해 **노드 중심**으로 주변으로 뻗어 나가며 덩어리를 키웁니다. **간선이 많은 '밀집 그래프'**에서 유리합니다. (오늘 짠 코드가 바로 이 방식입니다!)
- **크루스칼(Kruskal)**: 모든 간선을 비용순으로 쫙 정렬해놓고, **간선 중심**으로 무작정 가장 싼 다리부터 놓습니다. (단, 사이클이 안 생기게 Union-Find 기법으로 체크). **간선이 적은 '희소 그래프'**에서 유리합니다.
