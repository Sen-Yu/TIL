## 1. 과거 풀이 (2026.08)

```python
"""
점이 아닌 선분 중복체크가 필요
"""
def solution(dirs):
    answer = 0
    dx = [-1, 1, 0, 0]
    dy = [0, 0, -1, 1]
    visited = []
    now = [0, 0]

    for di in range(len(dirs)):
        d = dirs[di]
        if d == 'L':
            next = [now[0] + dx[0], now[1] + dy[0]]
        elif d == 'R':
            next = [now[0] + dx[1], now[1] + dy[1]]
        elif d == 'D':
            next = [now[0] + dx[2], now[1] + dy[2]]
        elif d == 'U':
            next = [now[0] + dx[3], now[1] + dy[3]]
        
        if -5 <= next[0] <= 5 and -5 <= next[1] <= 5:
            route = (now, next)
            re_route = (next, now)
            # 리스트 전체를 순회하며 O(N)으로 중복 검사
            if not route in visited and not re_route in visited:
                visited.append(route)
            now = next
        
    return len(visited)
```

### 🧐 과거 풀이의 특징 및 한계점
1. **리스트 선형 탐색으로 인한 시간 복잡도 $O(N^2)$**:
   - `visited`를 `list`로 관리하여 매번 `route in visited` 검사를 수행했다.
   - 리스트의 `in` 연산은 $O(K)$(K는 방문한 경로 수)이므로, 명령어가 길어지면 최악의 경우 $O(N^2)$의 시간 복잡도를 갖게 된다.
2. **반복적인 `if/elif` 분기**:
   - 상/하/좌/우를 모두 4개의 분기문으로 나누어 일일이 `next` 좌표를 계산했다.

## 2. 오늘 푼 풀이 (2026.10.20)

```python
"""
0,0 L = -1,0 R
0,0 -> -1,0  -> 출발지 목적지 둘다 만들기 -
-1,0 -> 0,0
""" 

dx = [0, 0, 1, -1]
dy = [1, -1, 0, 0]
dd = ["U", "D", "R", "L"]

def boundary(x, y, d):
    n = dd.index(d)
    if -5 <= x + dx[n] <= 5 and -5 <= y + dy[n] <= 5:
        x += dx[n]
        y += dy[n]
    return x, y

def solution(dirs):
    answer = 0
    record = dict()
    x, y = 0, 0
    
    for d in dirs:
        bx, by = x, y
        x, y = boundary(x, y, d)
        
        # 실제로 유효한 이동이 발생했을 때만 처리
        if bx != x or by != y:
            if (bx, by) not in record:
                record[(bx, by)] = set()
            if (x, y) not in record:
                record[(x, y)] = set()
                
            if not (x, y) in record[(bx, by)]:
                record[(bx, by)].add((x, y))
            if not (bx, by) in record[(x, y)]:
                record[(x, y)].add((bx, by))
                answer += 1
  
    return answer
```

## 3. 핵심 발전 포인트 비교

| 구분 | 과거 풀이 (2026.08) | 오늘 푼 풀이 (2026.10) |
| :--- | :--- | :--- |
| **자료구조** | `visited = list()` (선형 탐색) | **`record = dict() + set()` (해시 기반 인접 리스트)** |
| **중복 검사 속도** | **$O(N)$** (`in visited` 시 전체 순회) | **$O(1)$** (해시 셋 조회) |
| **전체 시간 복잡도**| $O(N^2)$ (입력이 커지면 위험) | **$O(N)$ (이상적인 최적화 달성)** |
| **이동 로직 구현** | 메인 루프 내 4단 `if/elif` 하드코딩 | **`boundary` 전용 함수로 모듈화 및 `index` 매핑** |
| **경계 초과 처리** | `if -5 <= next <= 5:` 안에서만 갱신 | 이동 전 좌표 `bx, by` 보존 후 **`bx != x or by != y`로 명확히 판별** |
| **그래프 모델링** | `(now, next)` 튜플 2종 수동 검사 | **양방향 무방향 그래프의 인접 세트**로 정교하게 모델링 |

## 4. 💡 추가 최적화 & 실전 팁 (Refactoring)

### 팁 1: 며칠 전 학습한 `defaultdict(set)` 적용하기
오늘 작성하신 코드에서 `if (bx, by) not in record:` 초기화 구문은 `defaultdict(set)`을 사용하면 단 2줄로 압축할 수 있습니다.

```python
from collections import defaultdict

def solution(dirs):
    answer = 0
    record = defaultdict(set)
    x, y = 0, 0
    
    for d in dirs:
        bx, by = x, y
        x, y = boundary(x, y, d)
        
        if (bx, by) != (x, y):
            if (x, y) not in record[(bx, by)]:
                record[(bx, by)].add((x, y))
                record[(x, y)].add((bx, by))
                answer += 1
                
    return answer
```

### 팁 2: 단일 `set`에 "정렬된 간선" 넣기 (코테용 초간결 정석)
선분 `(A, B)`와 `(B, A)`는 방향만 다를 뿐 같은 간선입니다. 
양방향 딕셔너리를 관리할 필요 없이, **양 끝점 4개 좌표를 정렬해서 단일 Set에 넣으면** 코드가 훨씬 간결해집니다.

```python
def solution(dirs):
    move = {'U': (0, 1), 'D': (0, -1), 'R': (1, 0), 'L': (-1, 0)}
    visited = set()
    x, y = 0, 0
    
    for d in dirs:
        dx, dy = move[d]
        nx, ny = x + dx, y + dy
        
        if -5 <= nx <= 5 and -5 <= ny <= 5:
            # 출발점과 도착점을 정렬하여 방향 무관하게 동일한 하나의 튜플로 저장!
            visited.add(tuple(sorted([(x, y), (nx, ny)])))
            x, y = nx, ny
            
    return len(visited)
```

## 5. 결론 및 배운 점
- 과거에는 리스트(`list`)의 `in` 연산을 사용하여 $O(N^2)$으로 처리했으나, 이번에는 **해시 딕셔너리와 세트(`dict + set`)를 결합하여 탐색 시간을 $O(1)$로 완전히 최적화**했습니다.
- 이동 처리 로직을 `boundary` 별도 함수로 분리하고 `bx, by`로 상태 변화를 체크하는 등 **코드의 모듈화와 안전성**이 눈에 띄게 발전했습니다.
- 그래프 간선(선분)의 양방향 중복 체크 문제를 풀 때는 **"해시 셋($O(1)$)"** 또는 **"정렬된 튜플 집합"**을 활용하는 패턴이 가장 강력합니다.
