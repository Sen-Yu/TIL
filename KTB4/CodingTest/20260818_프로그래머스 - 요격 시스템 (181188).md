# 프로그래머스 - 요격 시스템 (181188) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/181188

## 문제 요약
- 여러 개의 구간 `targets`(각 구간은 `[시작, 끝]`)가 주어진다.
- 미사일 한 발은 특정 x좌표 하나에서 터지며, 그 좌표를 포함하는 모든 구간을 한 번에 요격할 수 있다.
- 모든 구간을 요격하기 위한 **최소 미사일 발사 횟수**를 구한다.

## 아이디어
전형적인 구간 커버링(interval point cover) 그리디 문제다.

- 구간을 시작점(`x[0]`) 기준으로 정렬한다. (시작점이 같으면 끝점 기준으로 보조 정렬)
- 지금까지 겹쳐온 구간들의 **끝점 중 최솟값**을 `before_e`로 추적한다. 이 값이 "지금 이 겹치는 그룹을 요격하려면 반드시 이 지점 이전에 쏴야 한다"는 제약을 의미한다.
- 다음 구간의 시작점이 `before_e`보다 크거나 같다면(`s >= before_e`), 지금까지의 겹치는 그룹과는 더 이상 겹치지 않는다는 뜻이므로 **새로운 미사일이 필요**하다. 미사일 개수를 늘리고, `before_e`를 이 새 구간의 끝점으로 갱신한다.
- 반대로 여전히 겹친다면(`s < before_e`), 새 미사일을 쏘지 않고, 대신 `before_e`를 현재 값과 새 구간의 끝점 중 **더 작은 값**으로 갱신한다. 겹치는 구간이 늘어날수록 "반드시 쏴야 하는 마감 지점"이 더 빡빡해지기 때문이다.

## 왜 끝점의 최솟값을 추적해야 하는가
여러 구간이 서로 겹쳐 있을 때, 그 겹치는 구간들을 전부 한 방으로 요격하려면 **모든 구간에 공통으로 포함되는 지점**을 찾아야 한다. 그 공통 구간의 오른쪽 한계는 겹치는 구간들 중 **가장 일찍 끝나는 구간의 끝점**이다. 새로운 구간이 들어올 때마다 이 최솟값이 갱신되면서, "지금 그룹을 요격 가능한 마지노선"이 점점 좁혀진다. 만약 다음 구간의 시작점이 이 마지노선을 넘어서면, 더 이상 하나의 미사일로 묶어서 처리할 수 없으므로 그룹을 분리하고 새 미사일을 배정해야 한다.

## `answer + 1`을 반환하는 이유
`before_e`를 첫 번째 구간의 끝점으로 미리 초기화해두고 `for` 루프를 첫 번째 구간부터 다시 도는데, 이 첫 번째 반복에서는 `s`와 `before_e`가 같은 구간에서 나온 값이라 `s >= before_e`가 성립하지 않아(구간이 유효하다면 시작점이 끝점보다 항상 작으므로) 새 미사일로 카운트되지 않는다. 즉 **첫 번째 그룹은 `answer`에 반영되지 않고 루프가 시작되는 구조**라서, 마지막에 `+1`을 더해 첫 번째 그룹에 대한 미사일 한 발을 보정해준다.

## 발생했던 문제
없음. 그리디 접근(정렬 + 겹치는 그룹의 최소 끝점 추적)을 처음부터 정확히 설계해서 바로 통과했다.

## 복잡도
- 정렬: O(n log n)
- 이후 한 번의 순회로 그룹을 판별: O(n)
- 전체 시간복잡도: **O(n log n)**
- 공간복잡도: O(n) (정렬된 배열 보관)

## 배운 점
- 구간을 커버하는 최소 개수를 구하는 문제는, 정렬 기준을 "시작점"으로 잡고 "현재 겹치는 그룹의 최소 끝점"을 추적하는 방식으로도 풀 수 있다. (끝점 기준으로 정렬해서 그리디하게 접근하는 방식도 잘 알려져 있는데, 이번엔 시작점 정렬 + 최소 끝점 추적으로 동일한 결과를 얻었다.)
- "겹치는 구간들을 하나의 그룹으로 묶고, 그 그룹을 대표하는 값(여기선 최소 끝점)을 유지하며 갱신한다"는 패턴은, 이전에 봤던 슬라이딩 윈도우나 카데인 알고리즘처럼 "매번 전체를 다시 계산하지 않고 누적된 상태를 재사용"하는 최적화와 같은 계열의 사고방식이다.
- 루프의 초기화 방식에 따라 첫 번째 원소가 자연스럽게 카운트되지 않는 경우, 반복문 밖에서 `+1` 같은 보정을 해줘야 할 수 있다는 걸 확인했다. 이런 경계 처리는 항상 작은 예제로 손으로 검증해보는 습관이 필요하다.

## 최종 코드

```python
"""
x가 작은것부터해서 정렬
하니씩 순회하면서 현재 x[0] 이전 x[1] 보다 크면 +1
이전 x[1]은 이때까지 수회하면서 가장 작은 x[1]
"""
def solution(targets):
    answer = 0

    targets = sorted(targets, key=lambda x: [x[0], x[1]])
    before_e = targets[0][1]

    for s, e in targets:
        if s >= before_e:
            before_e = e
            answer += 1
        else:
            before_e = min(e, before_e)

    return answer + 1
```
