# 프로그래머스 - 구명보트 (42885) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42885

## 문제 요약
- 무인도에 갇힌 사람들을 구명보트를 이용하여 구출해야 한다.
- 구명보트는 한 번에 **최대 2명**씩 탈 수 있고, 무게 제한(`limit`)이 있다.
- 구명보트를 최대한 적게 사용하여 모든 사람을 구출하는 문제.

## 과거 풀이
```python
def solution(people, limit):
    answer = 0

    people.sort(reverse = True)
    
    left, right = 0, len(people)-1
    while left <= right:
        #print(f"left:{left}, right:{right}")
        if left < right:
            now = people[left] + people[right]
            #print(f"now:{now}")
            if now <= limit:
                right -= 1
        
        left += 1
        answer += 1 
            
    return answer
```
- 내림차순(`reverse=True`)으로 정렬하여 `left`가 가장 무거운 사람, `right`가 가장 가벼운 사람을 가리키도록 설정했다.
- 무거운 사람(`left`) 기준으로 짝지을 가벼운 사람(`right`)을 찾는다.
- 혼자 남았을 때(`left == right`)를 대비하여 `if left < right:`라는 안전장치 방어 코드를 명시적으로 두었다.

## 오늘(새) 풀이
```python
def solution(people, limit):
    answer = 0
    people.sort()
    left, right = 0, len(people) - 1
    
    while left <= right:
        if people[left] + people[right] <= limit:
            left+=1
        right-=1    
        answer+=1    
    
    return answer
```
- 오름차순(`sort()`)으로 정렬하여 `left`가 가장 가벼운 사람, `right`가 가장 무거운 사람을 가리키도록 설정했다.
- 무거운 사람(`right`) 기준으로 짝지을 가벼운 사람(`left`)을 찾는다.
- 단 한 명만 남아서 `left == right`가 되었을 때의 예외 처리를 별도로 하지 않았다. 만약 혼자 남아서 자신의 몸무게를 두 번 더한 값(`people[left] * 2`)이 한계치를 넘든 넘지 않든, 다음 루프에서 어차피 `left > right`가 되며 조건문이 종료되므로 결과가 완벽히 동일하게 처리된다. 코드의 군더더기가 완전히 사라졌다.

## 비교

| 구분 | 과거 풀이 | 오늘(새) 풀이 |
|---|---|---|
| 정렬 방식 | 내림차순 정렬 (`reverse=True`) | 오름차순 정렬 (기본) |
| 기준 포인터 | `left` (무거운 사람 이동), `right` (가벼운 사람 짝짓기) | `right` (무거운 사람 이동), `left` (가벼운 사람 짝짓기) |
| 예외 처리 (`left == right`) | `if left < right:` 조건문으로 방어 | 별도 방어 조건문 없이 자연스럽게 while 루프 통과로 해결 |
| 코드 길이 및 가독성 | 방어 코드가 있어 길고 조금 복잡해 보임 | 조건과 실행문이 최소화되어 극도로 깔끔하고 우아함 |
| 시간복잡도 / 공간복잡도 | O(N log N) / O(N) | O(N log N) / O(N) (동일) |

## 배운 점
- 투 포인터(Two Pointers) 로직의 핵심 아이디어는 과거에도 완벽하게 알고 있었다. 양 끝단을 묶어서 처리하고 인덱스만 조작해 시간 초과를 막는 기본기는 훌륭하게 자리 잡혀 있다.
- 과거 풀이는 "혹시 모를 에러"를 방지하기 위해 `if left < right`라는 안전장치를 명시적으로 추가하여 사람의 직관적 흐름에 맞춰 짰다면, 이번 풀이는 **반복문 자체의 흐름(`left <= right`의 속성과 이후 연산)**을 온전히 신뢰하여 군더더기 분기를 걷어냈다.
- 결과적으로 알고리즘의 뼈대는 같지만 코드를 표현하는 방식에서 불필요한 예외 처리를 덜어내고, 알고리즘의 우아함을 한껏 살린 아주 성숙한 리팩터링이 이루어졌다!
