## 1. 문제 요약
- $N$개의 마을이 있고, 마을 간 도로 정보 `road` `[a, b, c]`(마을 $a$와 $b$를 잇는 시간 $c$)가 주어진다.
- 도로는 **양방향**이며, 두 마을을 잇는 도로가 여러 개 있을 수도 있다.
- **1번 마을**에서 출발하여 각 마을로 배달을 갈 때, 음식 배달 시간이 **$K$ 이하인 마을의 총 개수**를 구하는 문제다.

---

## 2. 1차 시도에서의 문제점과 수정 과정

### 🚨 1차 시도 코드의 문제점
1. **무한 루프 (시간 초과)**:
   - 도로가 양방향이므로 `1 -> 2`, `2 -> 1` 왕복이 가능하다.
   - 1차 코드에서는 `queue.append(b)`를 무조건 수행하여 끝없이 큐에 데이터가 쌓이는 무한 루프가 발생했다.
2. **정답 미누적**:
   - `times` 배열을 계산해 두고 `answer`를 갱신하지 않아 `0`이 반환되었다.

### 💡 수정 및 해결 로직
- **"더 짧은 경로가 발견되었을 때만(최단 거리가 갱신될 때만)"** 큐에 다음 노드를 넣도록 조건문(`if times[b] > times[now] + cost:`)을 추가하여 무한 루프를 완벽하게 차단했다!
- 탐색 종료 후 `times` 배열에서 $K$ 이하인 마을의 개수를 세어 정답을 반환했다.

---

## 3. 최종 작성 코드 (거리 갱신 탐색)

```python
import heapq

def solution(N, road, K):
    answer = 0
    roadmap = dict()
    
    for r in road:
        a, b, c = r 
        if a not in roadmap:
            roadmap[a] = list()
        if b not in roadmap:
            roadmap[b] = list()
        heapq.heappush(roadmap[a], (c, b))
        heapq.heappush(roadmap[b], (c, a))
    
    times = [float('inf')] * (N + 1)
    times[1] = 0
    
    queue = [1]

    while queue:
        now = heapq.heappop(queue)
        for r in roadmap[now]:
            cost, b = r
            if times[b] > times[now] + cost:
                heapq.heappush(queue, b)
                times[b] = times[now] + cost

    for t in times:
        if t <= K:
            answer += 1
    return answer
```

## 4. 깊이 있는 분석: 현재 방식과 정석 다익스트라(Dijkstra)의 차이

작성하신 코드는 알고리즘에서 **SPFA (Shortest Path Faster Algorithm)** 또는 **BFS 기반 완화(Relaxation)** 기법으로 불리는 방식입니다.

- **장점**: 우선순위 큐 관리 없이 직관적인 `queue` 조작만으로 최단 거리를 정확하게 찾아냅니다. 프로그래머스 이 문제처럼 $N \le 50$ 정도로 작을 때는 매우 빠르게 올 패스합니다.
- **🚨 대규모 데이터($N=100,000$)에서의 위험성**:
  - 일반 큐(`pop` / `popleft`)를 쓰면 "누적 비용이 큰 경로"가 먼저 갱신되고, 나중에 "더 작은 경로"가 도달했을 때 **이미 방문했던 마을들을 큐에 또다시 중복으로 집어넣게 됩니다.**
  - 최악의 경우 시간 복잡도가 $O(V \cdot E)$까지 치솟아 백준 골드 이상 최단 경로 문제에서는 시간 초과가 날 수 있습니다.

### 🌟 정석 다익스트라 (Dijkstra) 최적화 포인트
이를 방지하는 것이 바로 **다익스트라 알고리즘($O(E \log V)$)**입니다.
- **핵심 차이**: `heapq`는 그래프 저장용(`roadmap`)이 아니라 **탐색 대기열(`queue`)**에 써야 합니다!
- 대기열에서 **"가장 누적 시간이 적게 걸린 노드부터 꺼내서 확정"**짓기 때문에, 동일한 노드를 불필요하게 여러 번 재탐색하는 오버헤드가 완전히 사라집니다.

```python
import heapq
from collections import defaultdict

def solution_dijkstra(N, road, K):
    # 인접 리스트는 defaultdict로 깔끔하게 구성
    graph = defaultdict(list)
    for a, b, c in road:
        graph[a].append((c, b))
        graph[b].append((c, a))
        
    times = [float('inf')] * (N + 1)
    times[1] = 0
    
    # heapq를 '탐색 대기열'에 적용! (누적비용, 마을)
    pq = []
    heapq.heappush(pq, (0, 1))
    
    while pq:
        current_time, now = heapq.heappop(pq)
        
        # 이미 처리된 적 있는(더 빠른 경로가 확정된) 노드라면 무시
        if times[now] < current_time:
            continue
            
        for cost, next_node in graph[now]:
            new_time = current_time + cost
            if new_time < times[next_node]:
                times[next_node] = new_time
                heapq.heappush(pq, (new_time, next_node))
                
    return sum(1 for t in times if t <= K)
```

## 5. 결론 및 배운 점
- 양방향 그래프에서 최단 경로를 탐색할 때, **`if times[next] > times[now] + cost:` 조건문은 사이클(무한 루프)을 막아주는 생명줄**이다.
- 가중치가 있는 최단 경로 문제에서 `heapq`의 역할은 **"탐색 순서를 가장 비용이 적게 든 순서대로 정렬하여 불필요한 재탐색을 없애는 것"**이다.
- 이번 문제를 통해 양방향 그래프의 순환 오류를 스스로 수정하고 최단 거리를 정확히 구해내는 완화(Relaxation) 메커니즘을 확실하게 체화했다!
