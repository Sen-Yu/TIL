# 프로그래머스 - 외벽 점검 (60062) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/60062

## 문제 요약
- 총 둘레가 `n`미터인 원형 벽에, 취약 지점들의 위치가 배열 `weak`로 주어진다.
- 친구들을 보내 취약 지점을 점검하는데, 각 친구가 1시간 동안 점검할 수 있는 거리가 배열 `dist`에 담겨 있다(친구마다 다름).
- 모든 취약 지점을 점검하기 위해 필요한 **최소 친구 수**를 구한다. 불가능하면 `-1`을 반환한다.
- 벽이 원형이라는 점과, 친구마다 이동 가능 거리가 다르다는 점이 문제를 복잡하게 만드는 핵심 요소다.

## 풀이 과정 — 2시간 동안 세 번 아이디어를 갈아엎은 과정
코드를 실제로 작성하기 전, 상단 주석에 아이디어를 계속 바꿔가며 검토하는 데 시간이 오래 걸렸고, 정작 코드 작성 자체는 구상보다 짧게 걸렸다.

### 1차 시도: 단순 반복문
`dist`에서 가장 큰 값을 하나씩 꺼내며, 원형 리스트 형태로 취약 지점 중 겹치는 구간을 매번 찾아나가는 방식을 구상했다. 그런데 "매번 찾아야 할 필요가 있다"는 점에서 막혔다. 이미 처리된(점검이 끝난) 구역을 저장해서 재사용하려 했지만, 어떻게 재사용할지 구체화하는 과정에서 시간복잡도 초과 문제가 예상되어 이 방향을 접었다.

**왜 막혔는가**: 친구마다 이동 가능 거리가 다르기 때문에, 어떤 친구를 어떤 순서로 어느 구간에 배치하느냐에 따라 커버되는 영역이 완전히 달라진다. 단순히 "처리된 구역을 캐싱"하는 방식만으로는 이 배치 순서의 자유도를 감당하기 어려웠다.

### 2차 시도: 트리 + 더블링
각 구간을 트리로 구성해서 가장 긴 범위(루트)부터 내려가며 `dist`를 매핑하는 방식을 시도했다. 원형 구조를 다루기 위해 취약 지점 리스트를 두 배로 이어 붙이는 "더블링" 아이디어도 도입했다. 하지만 **"시계 방향과 반시계 방향을 모두 체크해야 하는데, 트리 구조로는 이걸 표현할 수 없다"**는 한계에 부딪혀 이 방향도 접었다.

### 3차 시도: 더블링 + 순열(조합) — 최종 해결
`dist`가 최대 8개, `weak`가 최대 15개로 제한 크기가 작다는 점에 착안해, 완전 탐색에 가까운 접근으로 방향을 바꿨다.

- `dist`를 내림차순 정렬해서 가장 멀리 갈 수 있는 친구부터 사용하도록 준비한다.
- 친구 수(`friend_count`)를 1부터 늘려가며, 그 인원으로 성공하는 배치가 있는지 확인한다.
- 같은 인원수라도 **누가 어느 구간을 맡느냐(순서)**에 따라 커버리지가 달라지므로, `permutations(dist[:friend_count])`로 가능한 모든 배치 순서를 다 시도한다. 이것이 2차 시도에서 막혔던 "방향성" 문제를 해결하는 핵심이다.
- 원형 벽은 `weak + [w+n for w in weak]`로 이어 붙여(더블링) 일자로 펼치고, 모든 취약 지점을 시작점 후보로 삼아(`for start in range(W)`) 돌아가며 시도한다.
- 정해진 순열과 시작점 조합으로, 더블링된 배열을 `W`칸만큼 순회하며 각 취약 지점이 현재 친구의 이동 범위 안에 있는지 확인하고, 범위를 벗어나면 다음 친구로 교체한다. 모든 친구를 다 썼는데도 범위를 벗어나면 이 조합은 실패, 끝까지 커버하면 성공이다.

## 발생했던 문제
코드 자체의 버그보다는, **문제에 맞는 알고리즘 설계 방향을 찾는 데** 시간이 오래 걸렸다. 원형 구조(더블링으로 해결), 친구별 상이한 이동 거리, 배치 순서의 중요성(순열로 해결)이라는 세 가지 요소를 모두 만족하는 접근을 찾기까지 두 번의 시행착오가 있었다.

## 복잡도
- `dist`의 최대 길이가 8, `weak`의 최대 길이가 15로 제한되어 있어, `friend_count`별 순열(`P(8, friend_count)`) × 시작점(`W`개) × 커버리지 확인(`O(W)`)을 모두 곱해도 최악의 경우 수만 번 수준의 연산에 그친다.
- 이런 작은 제약 조건에서는 순열 기반의 완전 탐색이 사실상 정석적인 접근이다.

## 배운 점
- 문제에 "방향성"(시계/반시계, 혹은 순서에 따라 결과가 달라지는 성질)이 있다면, 트리처럼 한 방향으로만 뻗어나가는 구조보다는 **순열로 모든 순서를 직접 시도하는 방식**이 더 적합할 수 있다.
- 원형 구조를 다루는 문제에서는 배열을 두 배로 이어 붙이는 "더블링"이 순환을 일자 순회로 바꿔주는 유용한 전처리 기법이다.
- 입력 제약 조건(`dist` 최대 8개, `weak` 최대 15개)이 작다는 걸 인지하면, 정교한 자료구조 대신 순열 기반의 완전 탐색으로 접근하는 것도 충분히 유효한 전략이라는 걸 확인했다.
- 아이디어 단계에서 여러 번 갈아엎더라도, 그 과정에서 나온 부분적인 통찰(예: 더블링)이 최종 해법에 그대로 재사용될 수 있다. 시행착오가 헛되지 않았다는 걸 보여주는 사례였다.

## 최종 코드

```python
"""
weak 원형리스트화
수복하면 recovered에 week 요소 넣기
1) 단순 반복문
반복문 len(recovered) < len(처음 week)
    dist에서 가장 큰 값 하나 꺼내기
        외벽돌면서 dist가 허용하는 겹치는 구간 찾기
        (원형리스트 형식으로 찾기)
        (week 최대 15개 즉 바이너리 서치 불필요)
        (매번 찾아야할 필요가 있음-> 제거되지 않은 구역은 저장해서 다음번에 재사용하기 -> 어떻게? 시간 복잡도 초과 발생!!!)
            distance = week[n] - week[n-1]

2) 트리
각 구간을 트리로 만들어서 루트(가장 긴 범위부터) 내려가면서 dist 매핑하기
 -> 원형리스트는??
 -> 더블링으로 추가 연결해서 해결하자.
 -> 더블링을 추가할때 n+기존week로 해서 추가하자

 ->하지만 시계 반시계 체크가 불가능!!!


3) 더블링 + 조합사용
조합으로 미리 구현하면 방향성에 대한 문제가 해결됨
dist <= 8이기에 내림차순 정렬 후 가장 멀리갈 수 있는 친구부터해서 사용해서 친구 증가하면서 체크하기.
    조합 예) {[4], [4,3], [4,3,2], [4,3,2,1]}
    weak의 각요소를 시작 지점(시작 인덱스)으로 잡기
        현재 조합의 최대 인원 부터 뽑아서 합하면 그 요소를 포함한 이동거리가 됨.
        더블링한 weak에서 현재 설정한 시작 인덱스 포함 len(weak) 만큼 하나씩 이동거리에 포함되는지 체크
        현재 친구에서 초과된 요소만나면 현재 처음 세팅한 인원수 초과했는지 체크
            초과하면 다음 조합으로 진행하기 -> break
            초과안하면 다음 친구로 변경해서 계산하기
        현재 설정된 친구들로 체크 다돌았음에도 반복문을 통과-> 적합한 인원수 -> 정답
    계속된 초과(break)로 반복문 빠져나옴 -> 처음 설정한 답(초과한값)이면 -1로 리턴
"""
from itertools import permutations
def solution(n, weak, dist):
    answer = len(dist) + 1
    W = len(weak)

    ## 원형리스트화를 위한 더블링
    dubbling_weak = weak + [(w + n) for w in weak]
    dist.sort(reverse=True)

    for friend_count in range(1, len(dist) + 1):
        for friends in permutations(dist[:friend_count]):
            ## 시작 idx 설정
            for start in range(W):
                count = 1
                distance = dubbling_weak[start] + friends[count - 1]

                # 더블링 weak에서 weak수 만큼까지 체크
                for i in range(start, start + W):
                    ## 이동거리를 초과한 더블링weak를 만나면 카운트 추가
                    if distance < dubbling_weak[i]:
                        count += 1
                        ## 처음 설정한 친구 수를 초과함-> 그 다음 친구 추가해서 다시하기
                        if count > friend_count:
                            break
                        ## 처음 설정한 친구 수를 초과안함 -> 다음 친구 확인하기
                        else:
                            distance = dubbling_weak[i] + friends[count - 1]
                else:
                    return friend_count

    if answer > len(dist):
        return -1

    return answer
```
