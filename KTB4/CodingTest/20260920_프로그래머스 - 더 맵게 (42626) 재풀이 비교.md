# 프로그래머스 - 더 맵게 (42626) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42626

## 문제 요약
- 모든 음식의 스코빌 지수를 담은 배열 `scoville`과 목표 지수 `K`가 주어진다.
- 가장 맵지 않은 두 음식(최솟값 두 개)을 `min1 + min2 * 2` 공식으로 섞어 새로운 음식을 만드는 과정을 반복한다.
- 모든 음식의 스코빌 지수를 `K` 이상으로 만들 수 있는 **최소 섞기 횟수**를 구한다.
- 만들 수 없는 경우 `-1`을 반환한다.

## 이전 풀이 (2026.08.03) 요약
- `heapq.heappop`으로 최솟값(`min1`)을 미리 꺼내서 별도 변수에 저장해두고, 루프 조건에서 `scoville`(힙에 남은 원소 존재 여부)과 `min1 < K`를 함께 검사했다.
- 루프 안에서 두 번째 최솟값(`min2`)을 팝하고 섞은 뒤 다시 힙에 push, 그리고 다음 반복을 위해 `min1`을 힙에서 다시 pop하는 방식이었다.
- 문제점: "재료가 바닥나서 루프가 끝난 경우"와 "min1 >= K가 되어 끝난 경우"를 while 조건만으로 구분할 수 없어서, 루프 종료 후 `if (len(scoville) == 0) and min1 < K: return -1` 같은 별도 예외 처리가 필요했다.

## 새 풀이
```python
import heapq
def solution(scoville, K):
    answer = 0

    heapq.heapify(scoville)
    min = scoville[0]

    while len(scoville) >= 2 and min < K :
        min_1st = heapq.heappop(scoville)
        min_2nd = heapq.heappop(scoville)
        heapq.heappush(scoville, min_1st + (min_2nd * 2))
        min = scoville[0]
        answer+=1

    if min >= K:
        return answer

    return -1
```
- `heapq.heappop`으로 최솟값을 미리 꺼내 별도 변수에 저장해두는 대신, `scoville[0]`으로 힙의 루트를 그대로 "엿보기(peek)"만 해서 `min` 변수를 갱신한다.
- 루프 조건을 `len(scoville) >= 2`로 바꿔, "섞을 재료가 최소 2개 이상 남아있는가"를 직접 검사하도록 했다. (이전 풀이는 원소를 미리 pop해놓은 상태에서 "힙이 비었는가"로 같은 조건을 간접적으로 판단했다.)
- 힙에서 원소를 미리 꺼내두지 않고 top 값을 peek만 하기 때문에, 루프가 어떤 이유로 끝나든 `min` 변수는 항상 "현재 힙에서 가장 작은 값"이라는 의미를 그대로 유지한다. 그래서 루프 종료 후 `if min >= K` 단 하나의 조건만으로 성공/실패를 판별할 수 있다.

## 비교

| 구분 | 이전 풀이 (2026.08.03) | 새 풀이 |
|---|---|---|
| 최솟값 확인 방식 | `heapq.heappop`으로 미리 꺼내서 변수에 저장(pop) | `scoville[0]`으로 엿보기만 함(peek), 힙에서 제거하지 않음 |
| 루프 조건 | `scoville and min1 < K` (남은 원소 존재 여부를 간접적으로 사용) | `len(scoville) >= 2 and min < K` (섞을 재료가 2개 이상 남았는지 직접 검사) |
| 루프 종료 후 처리 | 종료 이유가 두 가지(K 달성 vs 재료 소진)라 별도 `if (len(scoville)==0) and min1 < K: return -1` 필요 | `min` 변수가 항상 현재 최솟값을 나타내므로 `if min >= K` 하나로 충분 |
| 코드 가독성 | pop-재pop 패턴 때문에 "왜 min1을 두 번 pop 하는가"를 이해하는 데 설명이 필요함 | peek 기반이라 값의 의미가 루프 내내 일관되게 유지되어 더 직관적 |
| 잠재적 주의점 | 없음 | 변수명으로 내장 함수 `min`을 그대로 사용해 shadowing 발생 — 이 함수 안에서는 `min()`을 별도로 호출하지 않아 실제 문제는 없지만 좋은 습관은 아님 |
| 시간복잡도 | O(n log n) | O(n log n) (동일) |
| 공간복잡도 | O(n) | O(n) (동일) |

## 배운 점
- 힙에서 "현재 최솟값이 무엇인가"를 추적할 때, pop으로 미리 꺼내두는 방식은 "루프가 어떤 이유로 끝났는지"를 나중에 다시 판별해야 하는 부담을 만든다. 반면 `heap[0]`으로 peek만 하면 힙의 상태와 변수의 의미가 항상 일치하기 때문에, 종료 조건을 훨씬 단순하게 만들 수 있다.
- "while 루프를 빠져나오는 이유가 여러 가지일 수 있다"는 이전 풀이에서 배웠던 교훈을, 이번엔 애초에 pop 대신 peek을 쓰는 구조로 바꿔서 근본적으로 제거할 수 있다는 걸 확인했다. 특수 케이스를 사후에 처리하는 것보다, 루프 조건과 변수의 의미를 설계 단계에서 일치시키는 게 더 견고한 해법이 될 수 있다.
- 다만 새 풀이처럼 내장 함수명(`min`)을 변수명으로 재사용하면 가독성·안전성 측면에서 좋지 않으므로, `current_min`처럼 구분되는 이름을 쓰는 게 더 바람직하다.
