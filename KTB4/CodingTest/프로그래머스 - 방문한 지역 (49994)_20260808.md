# 프로그래머스 - 방문한 지역 (49994) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/49994

## 문제 요약
- `(0, 0)`에서 시작해서 `dirs`에 담긴 방향(`L`, `R`, `U`, `D`)대로 한 칸씩 이동한다.
- `-5 ~ 5` 범위를 벗어나는 이동은 무시하고 제자리에 그대로 있는다.
- 지나간 **선분(구간)**을 기준으로, 방향에 상관없이 이미 지나간 적 있는 선분은 다시 세지 않는다.
- 처음 방문하는 고유한 선분의 개수를 반환한다.

## 아이디어
- 좌표를 이동시키며, 매 이동마다 `(현재 위치, 다음 위치)`라는 선분 하나를 얻는다.
- 이미 지나간 선분인지 확인할 때는 **점(좌표) 단위가 아니라 선분(구간) 단위**로 비교해야 한다. 같은 칸을 여러 번 지나가도 되지만, 같은 구간을 두 번 세면 안 되기 때문이다.
- "방향에 상관없이"라는 조건이 핵심이다. `(0,0)→(1,0)`과 `(1,0)→(0,0)`은 같은 선분으로 취급해야 하므로, 중복 체크 시 **정방향과 역방향을 모두 확인**해야 한다.

## 발생했던 문제

**1. 리스트를 딕셔너리 키로 사용**
초기 시도에서 `now`, `next`를 리스트로 다루면서 `visited[now] = next`처럼 딕셔너리 키로 사용했다. 리스트는 값이 바뀔 수 있는(mutable) 자료형이라 해시가 불가능해, `TypeError: unhashable type: 'list'`가 발생하는 구조였다.

**2. 격자 밖 이동 시에도 위치가 갱신됨**
```python
if -5 <= next[0] <= 5 and -5 <= next[1] <= 5:
    ... (visited 갱신)
now = next   # if문 밖에 있어서 무조건 실행됨
```
`now = next`가 범위 체크 `if`문 밖에 있어서, 격자를 벗어나는 이동에도 위치가 그대로 갱신돼버렸다. 문제 규칙상 벗어나는 이동은 무시하고 제자리에 있어야 하는데, 이 로직 때문에 이후의 모든 이동이 잘못된 위치를 기준으로 계산될 수 있었다.

**3. 역방향 이동을 체크하지 않음**
```python
if now in visited:
    if not next in visited[now]:
        ...
```
정방향(`now → next`)만 확인하고, 역방향(`next → now`)으로 이미 지나간 적이 있는지는 확인하지 않았다. 예를 들어 `(0,0)→(1,0)`을 이미 지나갔는데 나중에 `(1,0)→(0,0)`으로 되돌아가면, 이걸 새로운 선분으로 잘못 카운트하는 문제가 있었다.

## 해결 방법
- `visited`를 딕셔너리 대신 **리스트**로 바꿨다. 리스트의 `in` 연산은 해시가 아니라 값 비교(equality)로 동작하기 때문에, `now`/`next`가 리스트여도 에러 없이 정상 동작한다.
- `now = next`를 범위 체크 `if` 블록 **안으로** 옮겨서, 유효한 이동일 때만 위치가 갱신되도록 했다.
- 매 이동마다 `route = (now, next)`와 `re_route = (next, now)`를 모두 만들어서, 둘 중 하나라도 이미 `visited`에 있으면 새로 추가하지 않도록 했다. 이렇게 방향에 상관없이 같은 선분을 동일하게 취급할 수 있었다.

## 복잡도
- `dirs`의 길이를 `m`이라 하면, 매 이동마다 `route in visited`, `re_route in visited` 검사가 리스트를 순서대로 훑는 방식이라 O(길이)만큼 걸린다.
- 최악의 경우 전체 시간복잡도는 O(m²)이지만, 이 문제는 `dirs`의 길이가 최대 500 정도로 작아 실제로는 문제없이 통과한다.
- 만약 `dirs`가 훨씬 큰 입력이었다면, `visited`를 리스트 대신 `set`으로 바꾸고 `(min(now,next), max(now,next))`처럼 정규화된 튜플을 키로 사용해 O(1) 조회가 가능하도록 개선할 수 있다.

## 배운 점
- 리스트는 mutable이라 딕셔너리 키나 set의 원소로 쓸 수 없다. 좌표처럼 값을 키로 사용해야 할 때는 튜플로 다루는 습관이 필요하다. (다만 리스트를 그대로 두고 `in` 연산만으로 값 비교하는 방식도 규모가 작을 땐 유효한 대안이 될 수 있다.)
- 조건문 안에서만 실행되어야 하는 상태 갱신(`now = next`)의 위치가 조건문 밖으로 새어나가면, 그 이후의 모든 계산이 잘못된 상태를 기준으로 진행되는 연쇄 오류가 생길 수 있다.
- "방향에 상관없이 동일하게 취급"해야 하는 데이터(이 문제의 선분)는 정방향과 역방향을 모두 명시적으로 비교하거나, 애초에 하나의 정규화된 표현으로 저장하는 방식으로 처리해야 한다.

## 최종 코드

```python
"""
점이 아닌 선분 중복체크가 필요
"""
def solution(dirs):
    answer = 0
    dx = [-1, 1, 0, 0]
    dy = [0, 0, -1, 1]
    visited = []
    now = [0, 0]

    for di in range(len(dirs)):
        d = dirs[di]
        if d == 'L':
            next = [now[0] + dx[0], now[1] + dy[0]]
        elif d == 'R':
            next = [now[0] + dx[1], now[1] + dy[1]]
        elif d == 'D':
            next = [now[0] + dx[2], now[1] + dy[2]]
        elif d == 'U':
            next = [now[0] + dx[3], now[1] + dy[3]]

        if -5 <= next[0] <= 5 and -5 <= next[1] <= 5:
            route = (now, next)
            re_route = (next, now)
            if not route in visited and not re_route in visited:
                visited.append(route)
            now = next

    return len(visited)
```
