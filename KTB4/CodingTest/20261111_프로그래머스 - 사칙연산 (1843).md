# 프로그래머스 - 사칙연산 (1843) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/1843

---

## 1. 문제 요약
- 숫자와 `+`, `-` 연산자가 번갈아 들어있는 문자열 배열 `arr`가 주어진다.
- 연산 순서(괄호의 위치)를 마음대로 바꿀 수 있을 때, 계산 결과의 **최댓값**을 구하는 문제.
- 숫자 개수 $N \le 101$ (수식 전체 길이 최대 201).

---

## 2. 핵심 아이디어: 구간 DP (Interval DP)

### 💡 1. 최댓값을 위해 최솟값도 함께 추적해야 하는 이유
마이너스(`-`) 연산자 뒤에 오는 수식은 부호가 반전됩니다.
- `A - B`를 **최대**로 만들려면 ➡️ `(A의 최댓값) - (B의 최솟값)`
- `A - B`를 **최소**로 만들려면 ➡️ `(A의 최솟값) - (B의 최댓값)`

따라서 모든 구간 `[i, j]`에 대해 **`max_dp[i][j]`**와 **`min_dp[i][j]`** 2개의 2차원 테이블을 동시에 유지해야 합니다.

### 💡 2. 괄호 분할점 `k`와 점화식
구간 `i`부터 `j`까지의 계산은, 그 사이의 어떤 연산자 `k`(`i <= k < j`)를 마지막으로 계산하느냐로 나뉩니다.
- 연산자가 `+`인 경우:
  - `max_dp[i][j] = max(max_dp[i][j], max_dp[i][k] + max_dp[k+1][j])`
  - `min_dp[i][j] = min(min_dp[i][j], min_dp[i][k] + min_dp[k+1][j])`
- 연산자가 `-`인 경우:
  - `max_dp[i][j] = max(max_dp[i][j], max_dp[i][k] - min_dp[k+1][j])`  (🔥 핵심)
  - `min_dp[i][j] = min(min_dp[i][j], min_dp[i][k] - max_dp[k+1][j])`  (🔥 핵심)

### 💡 3. 구간 길이(`step`)를 늘려가는 순서
작은 덩어리의 답이 먼저 완성되어 있어야 큰 덩어리를 쪼개서 참조할 수 있으므로, **구간의 길이 `step`을 1부터 $N-1$까지 순차적으로 증가**시키며 테이블을 채웁니다.

---

## 3. 정답 코드

```python
def solution(arr):
    # 1. 숫자와 연산자를 분리 (인덱스 조작 편의성)
    nums = [int(x) for x in arr[0::2]]
    ops = arr[1::2]
    n = len(nums)
    
    # 2. DP 테이블 초기화
    # max_dp[i][j]: i번째 숫자부터 j번째 숫자까지 계산했을 때의 최댓값
    # min_dp[i][j]: i번째 숫자부터 j번째 숫자까지 계산했을 때의 최솟값
    max_dp = [[-float('inf')] * n for _ in range(n)]
    min_dp = [[float('inf')] * n for _ in range(n)]
    
    # 자기 자신(길이 1) 구간은 해당 숫자로 초기화
    for i in range(n):
        max_dp[i][i] = nums[i]
        min_dp[i][i] = nums[i]
        
    # 3. 구간의 길이 step (1부터 n-1까지 증가)
    for step in range(1, n):
        for i in range(n - step):
            j = i + step
            # 분할 지점 k (i <= k < j)
            for k in range(i, j):
                op = ops[k]
                
                if op == '+':
                    max_dp[i][j] = max(max_dp[i][j], max_dp[i][k] + max_dp[k + 1][j])
                    min_dp[i][j] = min(min_dp[i][j], min_dp[i][k] + min_dp[k + 1][j])
                elif op == '-':
                    # 빼기의 최댓값 = (앞의 최대) - (뒤의 최소)
                    max_dp[i][j] = max(max_dp[i][j], max_dp[i][k] - min_dp[k + 1][j])
                    # 빼기의 최솟값 = (앞의 최소) - (뒤의 최대)
                    min_dp[i][j] = min(min_dp[i][j], min_dp[i][k] - max_dp[k + 1][j])
                    
    # 전체 수식(0번부터 n-1번 숫자까지)의 최댓값 반환
    return max_dp[0][n - 1]
```

---

## 4. 복잡도 분석
- **시간 복잡도**: $O(N^3)$
  - 3중 for문(구간 길이 $N$, 시작 위치 $N$, 분할점 $N$).
  - 숫자의 개수 $N \le 101$이므로 $101^3 \approx 1,000,000$ (약 100만 번의 연산).
  - 파이썬 기준 0.05초~0.1초 만에 모든 효율성 테스트를 가볍게 통과합니다.
- **공간 복잡도**: $O(N^2)$
  - $101 \times 101$ 크기의 2차원 리스트 2개로 메모리 사용량이 극히 적습니다.

---

## 5. 결론 및 배운 점
- 괄호의 순서를 마음대로 묶는 문제는 전형적인 **행렬 곱셈 순서(Matrix Chain Multiplication)**와 동일한 **구간 DP** 유형이다.
- 마이너스 부호가 섞여 있을 때는 단순 최댓값만 저장해서는 안 되며, **최댓값과 최솟값을 동시에 테이블로 전진**시켜야 음수 반전의 최적해를 찾아낼 수 있다!
