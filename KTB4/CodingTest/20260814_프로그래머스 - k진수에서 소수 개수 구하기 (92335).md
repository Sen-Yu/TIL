# 프로그래머스 - k진수에서 소수 개수 구하기 (92335) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/92335

## 문제 요약
- 정수 `n`을 `k`진법으로 변환한다.
- 변환된 수를 `0`을 기준으로 나눠서 여러 개의 부분 수(segment)로 쪼갠다.
- 그 부분 수들 중 **소수인 것의 개수**를 구한다.

## 아이디어
1. `n`을 `k`진법 문자열로 변환한다 (`zinsu` 함수).
2. 그 문자열을 `"0"` 기준으로 `split`해서 여러 개의 부분 문자열을 얻는다. 빈 문자열(연속된 `0`이나 맨 앞/뒤의 `0`으로 인해 생기는 것)은 제외한다.
3. 남은 부분 문자열들을 정수로 변환한 뒤, 각각이 소수인지 판별해서 개수를 센다.

## 시도 1: 에라토스테네스의 체 — 시간초과 발생
처음엔 이전에 풀었던 "소수 찾기(42839)" 문제처럼, 나올 수 있는 모든 값 중 최댓값까지 에라토스테네스의 체를 만들어 소수 여부를 O(1)에 조회하는 방식으로 접근했다. 그런데 일부 테스트 케이스에서 시간초과(또는 메모리 문제)가 발생했다.

## 왜 이번엔 에라토스테네스의 체가 안 맞았는가
핵심은 **"검사해야 할 값의 최댓값"과 "실제로 검사해야 할 값의 개수"의 관계**가 이전 문제와 정반대라는 점이다.

- **소수 찾기(42839)**: `numbers`의 자릿수가 최대 7자리 정도로 제한되어 있어, 만들 수 있는 순열의 최댓값도 최대 7자리 수(최대 약 9,999,999) 수준으로 작았다. 반면 검사해야 할 값의 **개수**는 순열 조합 수만큼 많았다(수천~수만 개). 이런 경우 "값의 범위는 작고, 검사 횟수는 많다"는 조건이 성립해서, 한 번의 체 생성(O(M log log M))으로 이후 모든 조회를 O(1)에 처리하는 게 훨씬 유리했다.

- **k진수에서 소수 개수 구하기(92335)**: `n`은 최대 10억(10^9)까지 주어질 수 있다. `k`진법으로 변환한 뒤 `0`으로 나눈 부분 수 하나는, 0이 거의 없는 경우 `n` 자체에 가까운 아주 큰 값(최대 약 10^9)이 될 수 있다. 반면 부분 수의 **개수**는 `n`을 `k`진법으로 표현했을 때의 자릿수 정도로 매우 적다(k=3일 때도 최대 20자리 안팎, 즉 최대 20여 개 수준). 즉 이번엔 "값의 범위는 아주 크고, 검사 횟수는 적다"는 정반대의 조건이다.

이 조건에서 에라토스테네스의 체를 쓰면, 검사할 값이 몇 개 안 되는데도 **최댓값(최대 10^9)까지의 배열을 통째로 만들어야 해서**, 체 생성 자체에 O(10^9) 수준의 시간과 메모리가 들어간다. 정작 실제로 필요한 조회는 많아야 수십 번인데, 그 몇 번의 조회를 위해 수억 개짜리 배열을 미리 다 채우는 건 낭비가 심한 접근이었다.

## 해결 방법: 개별 값에 대한 시행 나눗셈(trial division) 판별로 변경
```python
def is_prime(N):
    if N <= 1:
        return False
    for i in range(2, int(N**0.5) + 1):
        if N % i == 0:
            return False
    return True
```
각 부분 수마다 `2`부터 `√N`까지 나눠보며 약수가 있는지 직접 확인하는 방식으로 바꿨다. 값 하나를 판별하는 데 O(√N)이 걸리지만, 검사해야 할 값의 개수 자체가 적기 때문에(많아야 수십 개) 전체적으로는 훨씬 빠르게 끝난다. 예를 들어 값이 10^9여도 `√(10^9) ≈ 31,623`번의 나눗셈이면 충분하고, 이런 판별을 수십 번 반복해도 총 연산량이 수백만 번 수준이라 여유 있게 통과한다.

## 두 접근법 비교

| 구분 | 에라토스테네스의 체 | 개별 시행 나눗셈 (trial division) |
|---|---|---|
| 적합한 상황 | 값의 최댓값(M)이 작고, 조회 횟수가 많을 때 | 값의 최댓값(M)이 크고, 조회 횟수가 적을 때 |
| 시간복잡도 | 전처리 O(M log log M) + 조회 O(1)씩 | 값 하나당 O(√N), 총 (조회 횟수 × O(√N)) |
| 공간복잡도 | O(M) — 최댓값 크기만큼의 배열 필요 | O(1) — 값마다 독립적으로 계산, 별도 배열 불필요 |
| 이 문제에서의 결과 | M이 최대 10^9라 배열 생성 자체가 시간초과/메모리 문제 유발 | 조회 횟수가 적어 개별 판별로도 충분히 빠름 |

## 배운 점
- "소수를 여러 번 판별해야 한다"는 조건만 보고 무조건 에라토스테네스의 체를 쓰는 건 위험하다. **판별해야 할 값의 범위(최댓값)**와 **판별 횟수(조회 횟수)**를 같이 따져봐야 한다.
  - 값의 범위가 작고 조회가 많다 → 체로 미리 전처리
  - 값의 범위가 크고 조회가 적다 → 값마다 개별 판별(O(√N))이 더 효율적
- 같은 "소수 판별"이라는 주제라도, 입력 데이터의 성격(값의 크기 vs 개수)에 따라 최적의 알고리즘이 정반대로 바뀔 수 있다는 걸 이번 문제로 확인했다.

## 최종 코드

```python
def zinsu(n, k):
    number = ""
    while n > 0:
        number += str(n % k)
        n //= k
    return "".join(reversed(number))

def is_prime(N):
    if N <= 1:
        return False
    for i in range(2, int(N**0.5) + 1):
        if N % i == 0:
            return False
    return True

def solution(n, k):
    answer = 0

    numbers = zinsu(n, k).split("0")
    sides = []
    if len(numbers) == 0:
        return 0
    for n in numbers:
        if n != "":
            sides.append(int(n))

    for s in sides:
        if is_prime(s):
            answer += 1

    return answer
```
