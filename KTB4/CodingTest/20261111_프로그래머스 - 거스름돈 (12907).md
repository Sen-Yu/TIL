## 1. 문제 요약
- 거슬러 주어야 하는 금액 `n`과 사용할 수 있는 동전의 종류 `money`가 주어진다.
- 각 동전은 무한히 사용할 수 있다.
- 동전을 조합하여 `n`원을 만들 수 있는 **방법의 총 가짓수**를 `1,000,000,007`로 나눈 나머지를 반환하는 문제.

---

## 2. 작성한 코드 (고민 과정 주석 포함 원본)

```python
"""
k.  money
1 = 1   => dp[0]
2 = 1 1, 2 dp[0] + dp[1]
3 = 1 1 1, 2 1, dp[0] dp[1] dp[2]
4 = 1 1 1 1, 2 1 1, 2 2

화폐단위가 없는 순간부터 1개씩 늘어가는방향으로 생각하기
money k
0     0  1.  2.  3.  4.  5  
dp.   1. 0.  0.  0.  0.  0
1        1   2   3   4   5
dp.   1  1.  1.  1.  1.  1  
2            2   3   4   5
dp.   1. 1.  2.  2.  3.  3
5                        5
                         4
        

"""
def solution(n, money):
    answer = 0
    dp = [0] * (n + 1)
    dp[0] = 1
    
    for m in money:
        for k in range(m, n + 1):
            dp[k] += dp[k - m]

    return dp[n] % 1000000007
```

---

## 3. 핵심 아이디어 및 원리 분석

이 문제는 배낭 문제(Knapsack Problem)의 변형이자 대표적인 **동전 교환(Coin Change) DP** 문제입니다.

### 💡 1. "화폐 단위가 시장에 하나씩 추가되는 방향" (바깥 루프의 중요성)
- 만약 **금액(`k`)을 바깥 루프**로 두고 동전을 안쪽에서 돌리면:
  - 3원을 만들 때 `[1원 + 2원]`과 `[2원 + 1원]`을 서로 다른 경우로 세어버리는 **순열(Permutation)** 오류가 발생합니다.
- 따라서 **동전(`m`)을 바깥 루프**에 두고 "1원짜리만 쓸 수 있을 때 ➡️ 2원짜리도 추가되었을 때 ➡️ 5원짜리도 추가되었을 때"처럼 순차적으로 장부를 갱신해야 **중복 없는 조합(Combination)**을 구할 수 있습니다.

### 💡 2. 점화식 `dp[k] += dp[k - m]`의 의미
- 내가 새롭게 추가된 `m`원짜리 동전을 적어도 1개 써서 `k`원을 만드는 새로운 방법의 수는?
- ➡️ **"일단 `m`원짜리 동전 1개를 탁자에 내려놓고, 나머지 `(k - m)`원을 만드는 방법의 수(`dp[k - m]`)"**와 완벽히 같습니다!
- 이미 앞에서부터 순차적으로 채워왔기 때문에, `m`원을 2개, 3개 여러 개 쓰는 경우까지 알아서 자연스럽게 누적됩니다.

### 💡 3. 초기값 `dp[0] = 1`의 이유
- "0원을 만드는 방법 = 동전을 아무것도 안 내기" 1가지가 존재해야,
- 동전 액면가 그대로 딱 떨어질 때(`k == m`) `dp[m] += dp[0]`을 통해 **"해당 동전 1개만 단독으로 쓰는 경우의 수"**가 정상적으로 장부에 1로 기록되기 시작합니다.

---

## 4. 복잡도 분석
- **시간 복잡도**: $O(N \times M)$
  - $N$은 목표 금액(최대 100,000), $M$은 동전의 종류 수(최대 100).
  - $100,000 \times 100 = 10,000,000$ (1천만 번 연산)으로 파이썬 기준 0.1~0.2초 이내에 매우 여유롭게 통과합니다.
- **공간 복잡도**: $O(N)$
  - 2차원 배열을 만들지 않고 크기 $N+1$의 1차원 리스트 하나만 재사용하므로 메모리 낭비가 전혀 없습니다.

- "조합을 구해야 하는 배낭/동전 문제에서는 **동전(아이템)이 바깥 루프, 금액(용량)이 안쪽 순방향 루프**를 돈다"는 핵심 공식을 완벽하게 체화했다!
