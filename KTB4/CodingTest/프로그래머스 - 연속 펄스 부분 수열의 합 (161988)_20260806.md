# 프로그래머스 - 연속 펄스 부분 수열의 합 (161988) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/161988

## 문제 요약
- 정수 수열 `sequence`가 주어진다.
- `sequence`의 연속된 부분 수열에 `[1, -1, 1, -1, ...]` 또는 `[-1, 1, -1, 1, ...]` 형태의 펄스 수열을 각 원소끼리 곱해서 "연속 펄스 부분 수열"을 만든다.
- 가능한 모든 연속 펄스 부분 수열의 합 중 **최댓값**을 구한다.

## 아이디어
- `sequence`에 `+1, -1, +1, -1, ...`을 곱한 배열(`pulse[0]`)과 `-1, +1, -1, +1, ...`을 곱한 배열(`pulse[1]`)을 각각 만든다.
- 이렇게 만들면 문제가 "이 두 배열 각각에서 **연속된 구간의 최대 합**을 구하고, 둘 중 더 큰 값을 답으로 삼는다"는 형태로 단순해진다.
- "연속 구간의 최대 합"은 **카데인 알고리즘(Kadane's Algorithm)**의 전형적인 적용 사례다.

## 시도 1: DP 점화식으로 모든 구간을 직접 저장 — 시간초과
처음엔 `dp[k][n] = dp[k-1][n] + pulse[n+k]` 형태의 점화식으로, 길이 `k`짜리 모든 구간의 합을 모든 시작 위치 `n`에 대해 전부 저장했다. 이 방식은 가능한 모든 (시작점, 길이) 조합을 다 계산하는 것이라, 시간복잡도와 공간복잡도가 모두 **O(n²)**이 되어 시간초과가 발생했다.

## 시도 2: 저장 공간만 줄임 — 여전히 시간초과 + 정확성 문제
`dp` 테이블 전체를 저장하는 대신 `sum` 변수 하나로 누적하도록 바꿨지만, 여전히 `k`(길이)와 `n`(시작점)에 대한 **이중 루프** 구조는 그대로였다. 즉 공간복잡도만 O(1)로 줄었을 뿐, 시간복잡도는 O(n²)로 그대로 남아있었다. 게다가 `range(k, length-k)`처럼 대칭적인 루프 범위를 사용한 탓에, `k`가 커질수록 검사되지 않는 구간이 생겨 **일부 정답 구간을 아예 놓치는 정확성 문제**까지 있었다.

## 카데인 알고리즘으로 전환
카데인 알고리즘의 핵심은 "시작점을 미리 정해서 순회하는 것"이 아니라, **배열을 단 한 번만 훑으면서 매 위치마다 "이어갈지 새로 시작할지"를 그 자리에서 판단**하는 것이다.

- `current_sum`: 지금 위치에서 끝나는 구간의 최대 합
- `best_sum`(또는 `answer`): 지금까지 나온 `current_sum` 중 최댓값

매 위치마다 다음을 갱신한다.
```
current_sum = max(현재 원소, current_sum + 현재 원소)
best_sum = max(best_sum, current_sum)
```
이전까지의 `current_sum`이 음수라면 다음 원소에 더해봤자 손해이므로, `max()` 연산 안에서 자연스럽게 "버리고 새로 시작"하는 효과가 나온다. 이 판단 하나로 사실상 모든 시작점 후보를 암묵적으로 검토한 것과 같아지기 때문에, 별도의 시작점 루프 없이 **O(n)** 한 번의 순회로 끝난다. `pulse[0]`, `pulse[1]` 각각에 대해 이 과정을 독립적으로 수행하므로 전체 시간복잡도는 O(2n) = O(n)이다.

## 발생했던 문제 (off-by-one 오류)
카데인 알고리즘으로 직접 구현한 뒤 시간초과는 해결됐지만, 일부 테스트 케이스에서 오답이 발생했다. 원인은 순회 범위였다.

```python
for n in range(1, length-1):
```

파이썬의 `range(start, stop)`은 `stop`을 **포함하지 않는** 반개구간이라, `range(1, length-1)`은 `1`부터 `length-2`까지만 순회하고 **배열의 마지막 인덱스(`length-1`)를 빠뜨린다.** 그 결과, 최적 구간이 배열의 마지막 원소를 포함해서 끝나는 경우(또는 마지막 원소 하나가 곧 정답인 극단적인 경우) `current_sum`과 `answer`가 그 지점에서 갱신되지 않아 오답이 나왔다.

## 해결 방법
루프 범위를 `range(1, length-1)`에서 `range(1, length)`로 수정했다. `range(1, length)`는 `1`부터 `length-1`(마지막 인덱스)까지 정확히 포함하므로, 배열 전체를 빠짐없이 순회하게 되어 문제가 해결됐다.

## 복잡도
- `pulse[0]`, `pulse[1]` 생성: O(n)
- 각 펄스 배열에 대한 카데인 알고리즘: O(n)씩, 총 O(2n)
- 전체 시간복잡도: **O(n)**
- 공간복잡도: O(n) (`pulse` 배열 두 개)

## 배운 점
- "가능한 모든 구간의 합"을 구하는 문제라고 해서 반드시 모든 (시작점, 길이) 조합을 전부 계산해야 하는 건 아니다. 카데인 알고리즘처럼 "매 위치에서 이어갈지 새로 시작할지"만 판단하는 방식으로 바꾸면, 이중 루프 없이 단 한 번의 순회로 모든 시작점 후보를 암묵적으로 검토할 수 있다.
- 저장 공간을 줄이는 것(리스트 → 변수)과 시간복잡도를 줄이는 것은 별개의 문제다. 이중 루프 구조 자체를 없애지 않으면, 변수로 바꿔도 시간복잡도는 그대로 O(n²)로 남는다.
- 파이썬의 `range(start, stop)`은 `stop`을 포함하지 않는다는 걸 명확히 기억해야 한다. 배열의 마지막 인덱스까지 포함하려면 `stop` 자리에 `배열 길이`를 그대로 넣어야 하며, 여기서 하나를 더 빼면 마지막 원소가 통째로 순회에서 빠진다.

## 최종 코드

```python
def solution(sequence):
    n = len(sequence)

    # pulse[0]: +1로 시작하는 펄스를 곱한 수열
    # pulse[1]: -1로 시작하는 펄스를 곱한 수열
    pulse = [[], []]
    sign = [1, -1]
    for i in range(n):
        pulse[0].append(sequence[i] * sign[0])
        pulse[1].append(sequence[i] * sign[1])
        sign[0] *= -1
        sign[1] *= -1

    answer = -100001

    for k in range(2):
        current_sum = pulse[k][0]
        answer = max(current_sum, answer)

        for i in range(1, n):
            current_sum = max(pulse[k][i], current_sum + pulse[k][i])
            answer = max(current_sum, answer)

    return answer
```
