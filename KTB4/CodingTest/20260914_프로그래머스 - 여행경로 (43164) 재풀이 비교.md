# 프로그래머스 - 여행경로 (43164) 재풀이 비교 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43164

## 문제 요약
- `ICN`에서 출발해서, 주어진 편도 티켓(`tickets`)을 **모두 사용**하는 여행 경로를 찾는다.
- 가능한 경로가 여러 개라면 **알파벳 순서로 가장 앞서는 경로**를 반환한다.
- 항상 모든 티켓을 다 쓰는 경로가 존재하므로, "경로를 못 찾는 경우"는 고려하지 않아도 된다.
- DFS + 백트래킹으로 접근한다.

## 이 문서의 목적
같은 문제를 과거(2026-08-05)와 오늘(2026-09-14) 두 번 풀었다. 두 풀이 모두 재귀 DFS로 동일한 골격을 갖지만, 세부 구현에서 몇 가지 차이가 있어 비교해서 정리한다.

## 공통 골격 (두 풀이 모두 동일)
- `tickets.sort()`로 미리 정렬해서, DFS가 항상 알파벳 순으로 앞선 티켓부터 시도하도록 한다. 그러면 가장 먼저 완성되는 경로가 자연스럽게 알파벳 순 최우선 경로가 된다.
- `visited` 배열로 티켓의 **인덱스 단위** 사용 여부를 추적한다. (같은 도시 쌍 티켓이 여러 장일 수 있으므로 도시 이름이 아니라 인덱스로 관리)
- 모든 티켓을 다 쓰면(`turn == ticket_len`) 종료 조건으로 `True`를 반환하고, 실패하면 `visited`를 되돌려(백트래킹) 다음 후보를 시도한다.
- 경로를 도착지부터 역순으로 `answer`에 쌓은 뒤 마지막에 `reverse()`로 뒤집어 정방향 경로를 완성한다.

## 과거 풀이 (2026-08-05)

```python
def solution(tickets):
    answer = []
    length = len(tickets)
    visited = [False for _ in range(length)]
    tickets.sort()

    def dfs(start, used):
        if used == length:
            return True

        for idx, t in enumerate(tickets):
            if t[0] == start and not visited[idx]:
                visited[idx] = True
                if dfs(t[1], used + 1):
                    answer.append(t[1])
                    return True
                visited[idx] = False

    dfs("ICN", 0)
    answer.append("ICN")
    answer.reverse()
    return answer
```

특징:
- 종료 조건에서 `True`만 반환하고, 도착지(`t[1]`)만 `answer`에 쌓는다. 그래서 시작점 `"ICN"`은 재귀가 끝난 뒤 **바깥에서 따로** `answer.append("ICN")`으로 추가해야 한다.
- 성공 시 `return True`로 즉시 함수를 빠져나간다. 별도의 성공 여부 변수 없이 반환값으로만 흐름을 제어한다.
- 성공하지 못하고 for문을 다 돈 경우, 명시적인 반환값이 없어 파이썬 기본값인 `None`이 반환된다(암묵적으로 실패로 취급됨).

## 오늘 풀이 (2026-09-14)

```python
"""
티켓 다 사용하기, 이름빠른순으로 경유하는 경로 1개 찾기 -> DFS
"""
def solution(tickets):
    answer = []

    ticket_len = len(tickets)
    visited = [False for _ in range(ticket_len)]
    tickets.sort()

    def dfs(now, turn):
        flag = False
        if turn == ticket_len:
            answer.append(now)
            return True

        for idx, t in enumerate(tickets):
            start, end = t
            if start == now and not visited[idx]:
                visited[idx] = True

                if dfs(end, turn+1):
                    answer.append(now)
                    flag = True
                    break
                visited[idx] = False

        return flag

    dfs("ICN", 0)
    answer.reverse()
    return answer
```

특징:
- 종료 조건에서 **현재 위치(`now`)를 직접 `answer`에 추가**한다. 마지막 공항(더 이상 티켓이 없는 지점)이 이 시점에 쌓이므로, 시작점을 바깥에서 따로 추가할 필요가 없다.
- 각 재귀 호출에서 성공 시 **현재 위치(`now`)를 쌓는다.** 그래서 경로의 모든 공항(시작점 포함)이 재귀 안에서 자연스럽게 쌓이고, 바깥의 `answer.append("ICN")`이 사라졌다.
- `flag`라는 성공 여부 변수를 두고, 성공 시 `break`로 for문을 빠져나온 뒤 마지막에 `return flag`로 반환한다. 성공/실패 여부를 명시적인 변수로 관리한다.
- 튜플을 `start, end = t`로 미리 언패킹해서 가독성을 높였다.

## 두 풀이 비교

| 구분 | 과거 (08-05) | 오늘 (09-14) |
|---|---|---|
| answer에 쌓는 대상 | 도착지 `t[1]`만 | 현재 위치 `now` (시작점 포함) |
| 시작점 "ICN" 처리 | 재귀 밖에서 `answer.append("ICN")` 별도 추가 | 재귀 안에서 자연스럽게 쌓임 (별도 처리 불필요) |
| 성공 여부 전달 | `return True` / 암묵적 `None` | `flag` 변수 + `return flag`로 명시적 관리 |
| 티켓 언패킹 | `t[0]`, `t[1]` 인덱스로 직접 접근 | `start, end = t`로 언패킹 |
| 종료 조건 인자명 | `used` (사용한 티켓 수) | `turn` (진행한 횟수) |

## 무엇이 달라졌는가 (풀이 방식의 변화)
1. **경로를 쌓는 기준이 "도착지"에서 "현재 위치"로 바뀌면서 코드가 더 일관성 있어졌다.** 과거엔 도착지만 쌓다 보니 시작점을 바깥에서 예외적으로 한 번 더 붙여야 했는데, 오늘은 "각 재귀 단계에서 자기 위치를 쌓는다"는 하나의 규칙으로 통일되어 시작점까지 자연스럽게 포함된다. 예외 처리 한 줄이 사라진 것이 핵심 개선이다.
2. **성공 여부를 `flag` 변수로 명시적으로 관리하게 됐다.** 과거엔 성공 시 `return True`, 실패 시 암묵적 `None` 반환에 의존했는데, 오늘은 `flag`로 상태를 명확히 표현하고 `return flag`로 일관되게 반환한다. 흐름을 읽기가 더 쉬워졌다.
3. **튜플 언패킹(`start, end = t`) 등 가독성을 높이는 습관이 자리 잡았다.** 인덱스로 직접 접근(`t[0]`, `t[1]`)하던 것을 의미 있는 이름으로 풀어써서 코드 의도가 더 잘 드러난다.

## 배운 점
- 재귀에서 결과를 누적할 때 "무엇을 기준으로 쌓느냐"(도착지 vs 현재 위치)에 따라, 시작점 같은 경계 원소를 바깥에서 따로 처리해야 하는지가 달라진다. 현재 위치를 기준으로 쌓으면 경계 예외가 자연스럽게 흡수되어 코드가 더 깔끔해진다.
- 성공/실패를 반환값의 암묵적 동작(`None`)에 맡기기보다, 명시적인 변수와 반환으로 표현하면 재귀 흐름을 추적하기 쉬워진다.
- 같은 알고리즘(재귀 DFS + 백트래킹)이라도, 결과를 쌓는 지점과 상태를 표현하는 방식을 다듬으면 예외 처리를 줄이고 가독성을 높일 수 있다. 기본 골격이 정확한 상태에서 세부 표현을 개선한 재풀이였다.
