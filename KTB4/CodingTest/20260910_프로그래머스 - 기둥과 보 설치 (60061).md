# 프로그래머스 - 기둥과 보 설치 (60061) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/60061

## 문제 요약
- `n × n` 크기의 벽면에 기둥과 보를 설치/삭제하는 명령(`build_frame`)이 순서대로 주어진다.
- 각 명령은 `[x, y, 자재종류, 명령]` 형태다. 자재종류는 기둥(0)/보(1), 명령은 삭제(0)/설치(1)다.
- 모든 명령을 수행한 뒤, 남아있는 구조물을 정해진 정렬 순서대로 반환한다.
- 설치와 삭제 모두 아래 규칙을 항상 만족해야 하며, 규칙을 어기게 되는 명령은 무시한다.
  - 기둥: 바닥 위이거나, 아래에 기둥이 있거나, 보의 한쪽 끝 위에 있어야 한다.
  - 보: 한쪽 끝 아래에 기둥이 있거나, 양쪽 끝이 다른 보와 이어져 있어야 한다.

## 아이디어
- 벽면을 `build_map`이라는 2차원 배열로 표현하고, 각 칸의 상태를 숫자 하나로 관리했다.
  - `-1`로 초기화(빈 칸)
  - 기둥을 설치하면 `+1` → `0`이 되어 "기둥 있음"
  - 보를 설치하면 `+2` → `1`이 되어 "보 있음"
  - 둘 다 설치되면 `2`가 되어 "기둥과 보 둘 다 있음"
- `check_bong`(기둥 설치 가능 여부), `check_floor`(보 설치 가능 여부) 함수로 각 자재의 설치 조건을 판별한다.

## 발생했던 문제 — 삭제 시 "일부 자재만 확인"하는 한계
초기 삭제 로직은 삭제하려는 자재의 **주변 몇 칸(직접 인접한 자재)만 개별적으로 확인**해서, 그 자재를 지워도 괜찮은지 판단하는 방식이었다. 그런데 이 방식은 삭제된 자재에 **간접적으로 의존하던 먼 구조물**까지는 검증하지 못하는 한계가 있었다. 예를 들어 어떤 보를 지웠을 때, 그 보에 직접 닿아있진 않지만 연쇄적으로 그 보에 의존하던 다른 구조물이 규칙을 위반하게 되는 경우, 개별 인접 검사만으로는 이를 놓쳐서 삭제하면 안 되는 자재를 그대로 삭제해버렸다.

## 해결 방법 — 삭제 검증을 "전체 확인"으로 전환
삭제 조건을 인접 자재별로 일일이 나눠서 확인하는 대신, **일단 삭제한 뒤 맵 전체를 다시 검사해서, 규칙을 위반하는 구조물이 하나라도 있으면 삭제를 되돌리는 방식**으로 바꿨다.

이를 위해 `check_map()` 함수를 추가했다. 이 함수는 맵 전체를 순회하며, 기둥이 있는 모든 칸은 `check_bong`을, 보가 있는 모든 칸은 `check_floor`를 만족하는지 검사한다. 하나라도 어기면 `False`를 반환한다.

```python
def check_map():
    for x in range(n+1):
        for y in range(n+1):
            if build_map[y][x] == 0 or build_map[y][x] == 2:
                if not check_bong(x, y):
                    return False
            if build_map[y][x] == 1 or build_map[y][x] == 2:
                if not check_floor(x, y):
                    return False
    return True
```

삭제 로직은 다음과 같이 단순해졌다. 일단 지우고, 전체 검사가 실패하면 원래대로 복구한다.

```python
## 1.0. 기둥 삭제
if frame_type == 0:
    build_map[fy][fx] -= 1
    if not check_map():
        build_map[fy][fx] += 1
## 1.1. 보 삭제
else:
    build_map[fy][fx] -= 2
    if not check_map():
        build_map[fy][fx] += 2
```

이렇게 "지운 뒤 전체를 검사한다"로 바꾸면, 삭제된 자재에 직접 닿은 구조물뿐 아니라 간접적으로 의존하던 모든 구조물의 영향까지 한 번에 검증되므로, 개별 인접 검사에서 놓치던 케이스가 모두 해결된다.

## 복잡도
- 명령마다 `check_map()`이 맵 전체(O(n²))를 순회한다.
- 명령 수를 `m`이라 하면 전체 시간복잡도는 **O(m × n²)**이다. 이 문제의 제약(명령 수와 `n`이 크지 않음) 안에서는 충분히 통과한다.

## 배운 점
- 어떤 자재를 삭제/변경했을 때 그 영향이 **직접 인접한 대상에만 국한되지 않고 연쇄적으로 퍼질 수 있는 문제**에서는, 변경 지점 주변만 개별적으로 확인하는 방식이 간접적인 의존 관계를 놓치기 쉽다.
- 이런 경우 "일단 실행하고 → 전체 상태가 여전히 유효한지 검사하고 → 위반하면 되돌리기"라는 방식이 훨씬 안전하고 정확하다. 검증 로직을 하나의 전체 검사 함수로 통일하면, 케이스를 일일이 나누다 발생하는 누락도 방지할 수 있다.

## 최종 코드

```python
"""
기능
1.기둥 설치(0<=x<=n, 0<=y<=n):위로 설치
    현재 위치가 바닥인가 y == 0
    현재 위치의 아래에 기둥이 있는가 [y][x] == 기둥
    현재 위치에 보의 끝부분이 있는가 [y]
2.보 설치(0<=x<=n, 0<y<=n): 오른쪽으로 설치
    현재 위치에 기둥이 있는가
    양쪽끝에 다른보가 위치하는가
3.기둥 삭제:위쪽 삭제
4.보 삭제:오른쪽 삭제

5 <= n <= 100
a = 건축 자재(0:기둥, 1:보)
b = 건축 명령(0:삭제, 1:설치)


겹치는 설치,없는구조물 삭제는 둘다 X

서로다른 기둥 설계부터 시작 가능 -> 트리


명령 확인 ---> 삭제 -> 자재확인 -> 기둥 -> 본인 자리포함, 연결된 자재확인
                                    -> 연결자재종류마다 지웠을경우의 추가 조건 확인하기
         |
         |                -> 보 -> 본인 자리포함, 연결된 자재확인
         |
         --> 추가 -> 자재확인 -> 기둥 -> 현재 좌표 확인 -> 바닥인가?, 아래좌표에 기둥이 있는가?,왼쪽 좌표에 보가 있는가?

                          -> 보 > 현재 좌표 확인 -> 아래좌표에 기둥이 있는가?,오른쪽 아래좌표에 기둥이 있는가?,왼쪽 좌표와 오른쪽좌표에 보가 둘다 있는가?
"""

def solution(n, build_frame):
    answer = []
    ## -1로 초기화한 이유 -> 기둥 설치를 하면 +1 -> 0이 되면서 기둥이 설치됬음을 알 수 있음
    ## 보설치를 하면 +2 로 1이 되면서 보가 설최 되잇음을 알 수 있음
    ## 둘다 설치된 기준점이되면 2됨 -> 기둥과 보 둘다 설치 되있음을 알 수 있음
    build_map = [[-1] * (n+1) for _ in range(n+1) ]

    def check_bong(fx,fy):
        if fy == 0 or (fy-1 >= 0 and 0 <= fx <= n and (build_map[fy-1][fx] == 0 or build_map[fy-1][fx] == 2)) or (fx-1 >=0 and (build_map[fy][fx-1] == 1 or build_map[fy][fx-1] == 2)) or (0 <= fx <= n and (build_map[fy][fx] == 1 or build_map[fy][fx] == 2)):
            if  0 <= fy <= n and 0 <= fx <= n :
                return True
        return False

    def check_floor(fx,fy):
        if (fy-1 >= 0 and 0 <= fx+1 <= n and (build_map[fy-1][fx] == 0 or build_map[fy-1][fx] == 2)) or (fy-1 >= 0 and 0 <= fx+1 <= n and (build_map[fy-1][fx+1] == 0 or build_map[fy-1][fx+1] == 2)) or (fx-1 >=0 and fx+1 < n and (build_map[fy][fx-1] == 1 or build_map[fy][fx-1] == 2) and (build_map[fy][fx+1] == 1 or build_map[fy][fx+1] == 2)):
            if  0 < fy <= n and 0 <= fx < n :
                return True
        return False

    def check_map():
        for x in range(n+1):
            for y in range(n+1):
                if build_map[y][x] == 0 or build_map[y][x] == 2:
                    if not check_bong(x,y):
                        return False
                if build_map[y][x] == 1 or build_map[y][x] == 2:
                    if not check_floor(x,y):
                        return False
        return True

    for fx, fy, frame_type, command in build_frame:

        ## 0.삭제
        if command == 0:
            ## 1.0. 기둥 삭제
            if frame_type == 0:
                build_map[fy][fx] -= 1
                if not check_map():
                    build_map[fy][fx] += 1

            ## 1.1. 보 삭제
            else:
                build_map[fy][fx] -= 2
                if not check_map():
                    build_map[fy][fx] += 2
        ## 1.설치
        else:
            ## 1.0. 기둥 설치
            if frame_type == 0:
                ## 설치 가능 여부 확인
                if check_bong(fx,fy):
                    build_map[fy][fx] += 1

            ## 1.1. 보 설치
            else:
                if check_floor(fx,fy):
                    build_map[fy][fx] += 2


    for x in range(n+1):
        for y in range(n+1):
            if -1 < build_map[y][x] < 2:
                answer.append([x,y,build_map[y][x]])
            elif build_map[y][x] == 2:
                answer.append([x,y,0])
                answer.append([x,y,1])



    return answer
```
