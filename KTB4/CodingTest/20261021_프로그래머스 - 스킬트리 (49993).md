# 프로그래머스 - 스킬트리 (49993) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/49993

---

## 1. 문제 요약
- 선행 스킬 순서 `skill`(예: `"CBD"`)이 주어질 때, 유저들이 만든 스킬트리 `skill_trees` 중 올바른 스킬트리의 개수를 구하는 문제.
- `C -> B -> D` 순서라면, `B`를 배우려면 반드시 `C`를 먼저 배워야 하고, `D`를 배우려면 `C`와 `B`를 모두 먼저 배워야 한다.
- 선행 스킬 순서에 없는 스킬(예: `A`, `E`, `F` 등)은 순서와 상관없이 언제든 배울 수 있다.

---

## 2. 작성한 코드 및 풀이 로직

```python
def solution(skill, skill_trees):
    answer = len(skill_trees) # 전체가 가능하다고 가정하고 시작
    
    for skills in skill_trees:
        now = -1 # 현재까지 정상적으로 통과한 선행 스킬의 인덱스
        
        for s in skills:
            if s in skill:
                # 다음으로 배워야 할 스킬(now + 1)의 위치와 일치하지 않으면 규칙 위반!
                if now + 1 != skill.find(s):
                    answer -= 1
                    break
                else:
                    now += 1
                    
    return answer
```

### 💡 핵심 아이디어 및 우수한 점
1. **인덱스 포인터(`now`)를 활용한 선행 조건 검증**:
   - `now = -1`로 시작하여, 선행 스킬트리에 포함된 스킬을 만났을 때 그 스킬의 위치(`skill.find(s)`)가 정확히 `now + 1`인지 검사한다.
   - 첫 선행 스킬은 반드시 인덱스 `0`이어야 하고(`-1 + 1 == 0`), 그다음은 `1`, `2` 순서대로만 나타나야 한다는 규칙을 깔끔하게 수식으로 구현했다.
2. **조기 탈출(Early Exit)을 통한 불필요한 연산 방지**:
   - 전체 개수(`len(skill_trees)`)에서 시작하여 잘못된 순서가 감지되는 순간 `answer -= 1` 후 즉시 `break`를 걸어 다음 스킬트리로 넘어간다.
3. **추가 메모리 생성 없는 $O(1)$ 공간 복잡도**:
   - 별도의 문자열이나 리스트를 새로 만들지 않고, 변수 하나(`now`)로만 상태를 추적하여 메모리와 속도 면에서 매우 효율적이다.

## 3. 다른 접근법 및 파이써닉(Pythonic) 팁

### 접근법 1: `startswith` 활용 (추출 후 접두사 비교)
선행 스킬에 포함된 문자들만 쏙 뽑아낸 뒤, 그 문자열이 원본 `skill`의 **앞부분(접두사)**으로 시작하는지 확인하는 직관적인 방식이다.

```python
def solution(skill, skill_trees):
    answer = 0
    for skills in skill_trees:
        # skill에 포함된 문자만 순서대로 추출
        filtered_skill = ''.join([s for s in skills if s in skill])
        # 원본 skill이 filtered_skill로 시작하는지 검사
        if skill.startswith(filtered_skill):
            answer += 1
    return answer
```
- 예: `skill = "CBD"`일 때, 추출된 문자열이 `""`, `"C"`, `"CB"`, `"CBD"` 중 하나라면 무조건 올바른 스킬트리다.

### 접근법 2: 파이썬 `for-else` 문법 활용
반복문이 `break` 없이 온전히 끝났을 때만 실행되는 `for-else` 구조를 쓰면 감산 방식(`answer = len()`) 대신 가산 방식으로도 깔끔하게 짤 수 있다.

```python
def solution(skill, skill_trees):
    answer = 0
    for skills in skill_trees:
        skill_idx = 0
        for s in skills:
            if s in skill:
                if s != skill[skill_idx]:
                    break
                skill_idx += 1
        else: # 중간에 break에 걸리지 않고 정상 완료된 경우만
            answer += 1
    return answer
```

---

## 4. 결론 및 배운 점
- 문자열의 순서 조건을 검증할 때, `now + 1 == skill.find(s)`처럼 **다음 기대 인덱스를 순차적으로 비교하는 포인터 방식**은 추가 메모리 없이 가장 빠르고 정확하게 풀 수 있는 정석적인 접근법이다.
- 문자열 문제에서는 `skill.startswith()` 같은 메서드나 `for-else` 문법도 코드 가독성을 높이는 훌륭한 무기가 될 수 있다.
