# 프로그래머스 - 최고의 집합 / 최단경로 문제 (132266) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/132266

## 문제 요약
- `n`개의 노드와 `roads`(양방향 도로)로 이루어진 그래프가 주어진다.
- `destination`으로부터 `sources`에 있는 각 노드까지의 **최단 거리**를 구해야 한다.
- 가중치가 없는 그래프의 최단 거리 문제이므로 BFS로 접근한다.

## 아이디어
- `destination`을 시작점으로 BFS를 한 번만 돌리면, 그 과정에서 모든 노드까지의 최단 거리가 동시에 계산된다.
- 굳이 `sources`의 각 노드마다 따로 BFS를 돌릴 필요 없이, `destination` 기준 최단 거리 배열(`min_map`)을 한 번 만들어두고 `sources`를 순회하며 조회만 하면 된다.
- 그래프 표현 방식에 따라 이웃 탐색 비용이 크게 달라지는데, 이 부분이 이번 문제의 핵심 병목이었다.

## 발생했던 문제
초기 코드는 그래프를 **인접 행렬**(`maps[s][d]`)로 표현했다. BFS에서 한 노드의 이웃을 찾을 때마다 `for r in range(1, n+1)`로 가능한 모든 노드를 검사했기 때문에, 노드 하나당 O(n)의 비용이 들었다. 전체 BFS가 노드 수(n) × 검사 비용(O(n)) = **O(n²)**이 되어, n이 큰 입력에서 시간초과가 발생했다.

## 해결 방법
그래프를 **인접 리스트**(`graphs[s]` = s와 연결된 노드들의 리스트)로 바꾸었다. BFS에서 이웃을 찾을 때 `for d in graphs[now]`로 **실제로 연결된 노드만** 순회하게 되어, 전체 BFS 복잡도가 간선 수(m)에 비례한 **O(n + m)**으로 줄었다. 이번엔 알고리즘 설계 자체는 처음부터 맞았고, 그래프 표현 방식만 교체하여 해결했다.

## 인접 행렬 vs 인접 리스트 비교

| 구분 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 자료구조 | `(n+1) × (n+1)` 2차원 배열 | 각 노드마다 연결된 노드들의 리스트 |
| 공간복잡도 | O(n²) | O(n + m) |
| 두 노드 연결 여부 확인 | O(1) — 바로 조회 가능 | O(연결된 노드 수) — 리스트를 순회해야 함 |
| 한 노드의 이웃 전체 탐색 | O(n) — 존재 여부와 무관하게 전체를 훑음 | O(해당 노드의 실제 이웃 수) |
| BFS/DFS 전체 복잡도 | O(n²) | O(n + m) |
| 유리한 경우 | 그래프가 촘촘함 (m이 n²에 가까움), 두 노드 연결 여부를 자주 O(1)로 확인해야 할 때 | 그래프가 희소함 (m이 n²보다 훨씬 작음), 도로망/지도처럼 실전 그래프 대부분 |
| 이번 문제 적합성 | 부적합 — 실제 도로 수보다 훨씬 큰 n²만큼 매번 스캔하여 시간초과 | 적합 — 실제 도로 수만큼만 순회하여 해결 |

## 배운 점
- 그래프 문제에서 "시간초과"는 알고리즘(BFS/DFS 자체)이 틀려서가 아니라, **그래프를 표현하는 자료구조 선택**이 원인인 경우가 많다.
- 노드 수(n)는 크고 간선 수(m)는 상대적으로 적은 희소 그래프에서는 인접 리스트가 사실상 필수적인 선택이다.
- destination(또는 특정 기준점) 하나에서 BFS를 한 번만 돌려 모든 노드까지의 최단 거리를 동시에 구하고, 이후엔 필요한 지점만 조회하는 패턴은 매번 개별적으로 BFS를 반복하는 것보다 훨씬 효율적이다.
