# 프로그래머스 - 명예의 전당 (1) (138477) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/138477

## 문제 요약
- 매일 프로그램 출연자의 점수(`score`)가 하나씩 주어진다.
- 매일, 그날까지 등장한 모든 점수 중 **상위 `k`개**를 "명예의 전당"에 올린다.
- 그날의 명예의 전당 **최저 점수**(상위 k개 중 가장 낮은 점수)를 매일 기록해 배열로 반환한다.
- 아직 점수가 `k`개보다 적은 날은, 그때까지 나온 점수 중 최저 점수가 기록된다.

## 아이디어 — 최소 힙으로 상위 k개 유지
이 문제의 핵심은 "지금까지 등장한 점수 중 **상위 k개의 최솟값**"을 매일 구하는 것이다. 최소 힙(min-heap)을 쓰면 힙의 맨 위(`best[0]`)가 항상 그 최솟값이 되므로 딱 맞는다.

- 매일 점수를 힙에 넣는다.
- 힙의 크기가 `k`를 넘으면 가장 작은 값(`heappop`)을 버린다. 이렇게 하면 힙에는 항상 "상위 k개"만 남는다.
- 그 상태에서 힙의 최솟값(`best[0]`)이 곧 그날의 명예의 전당 커트라인이다.

## 발생했던 문제
없음. 최소 힙으로 상위 k개를 유지한다는 아이디어를 처음부터 정확히 잡아 통과했다.

## 개선한 부분 — 커트라인 조회를 O(1)로
초기 코드에서는 커트라인(최솟값)을 확인하기 위해 `heappop`으로 꺼낸 뒤 다시 `heappush`로 넣는 방식을 썼다.

```python
now = heapq.heappop(best)
answer.append(now)
heapq.heappush(best, now)
```

하지만 파이썬 최소 힙에서 최솟값은 `best[0]`으로 **O(1)에 바로 조회**할 수 있다. 굳이 꺼냈다 다시 넣으면 pop/push 각각 O(log k)의 불필요한 연산이 발생한다. 그래서 다음과 같이 인덱싱 한 줄로 바꿨다.

```python
answer.append(best[0])
```

동작 결과는 동일하지만, 불필요한 힙 연산 한 쌍이 사라져 더 간결하고 상수 계수도 줄었다.

## 복잡도
- 점수 개수를 `m`이라 하면, 각 점수마다 힙 연산(`heappush`, 필요 시 `heappop`)이 O(log k)
- 커트라인 조회(`best[0]`)는 O(1)
- 전체 시간복잡도: **O(m log k)**
- 공간복잡도: O(k) (힙에 최대 k개의 점수만 유지)

## 배운 점
- "지금까지 등장한 값들 중 상위 k개"를 유지해야 하는 문제는, 최소 힙에 넣고 크기가 k를 넘으면 최솟값을 버리는 방식으로 항상 top-k를 유지할 수 있다. 이때 힙의 맨 위가 곧 "상위 k개 중 최저값"이 된다.
- 파이썬 힙에서 최솟값은 `heappop`으로 꺼내지 않아도 `best[0]` 인덱싱으로 O(1)에 읽을 수 있다. 값을 확인만 할 목적이라면 꺼냈다 다시 넣는 대신 인덱싱을 쓰는 것이 효율적이다.
- 이는 이전에 다룬 "이미 아는 값을 다시 계산하지 말고 그대로 재사용한다"는 최적화 감각과 같은 맥락이다.

## 최종 코드

```python
import heapq
def solution(k, score):
    answer = []
    count = 0
    best = list()

    for s in score:
        heapq.heappush(best, s)

        if count >= k :
            heapq.heappop(best)

        answer.append(best[0])
        count+=1

    return answer
```
