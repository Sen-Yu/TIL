# 프로그래머스 - 달리기 경주 (178871) 풀이 정리

문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/178871

## 문제 요약
- 1등부터 꼴등까지 순서대로 선수 이름이 담긴 배열 `players`가 주어진다.
- 해설진이 어떤 선수의 이름을 부르면(`callings`), 그 선수가 바로 앞 선수를 추월한다(두 선수의 등수가 서로 바뀐다).
- 모든 추월이 끝난 뒤, 1등부터 순서대로 선수 이름을 담은 배열을 반환한다.

## 아이디어
- 제약 조건상 `players`의 길이가 최대 50,000까지 갈 수 있어서, 매번 `players.index(선수이름)`처럼 이름으로 위치를 찾는 방식은 탐색에 O(n)이 걸려 전체적으로 느려질 수 있다.
- 이를 피하기 위해 `players_dict = {선수이름: 현재 인덱스}` 형태의 딕셔너리를 만들어, **이름으로 현재 등수(인덱스)를 O(1)에 바로 조회**할 수 있도록 했다.
- 추월이 일어날 때마다 다음 네 가지를 갱신한다.
  1. 추월한 선수(`c`)의 현재 인덱스(`now`)를 딕셔너리에서 조회
  2. 바로 앞 선수의 인덱스(`front = now - 1`)와 그 이름(`front_player`) 확인
  3. 두 선수의 위치를 서로 바꾼 뒤, `players_dict`에도 각자의 새 인덱스를 반영
  4. `players` 배열에도 같은 방식으로 두 위치의 값을 맞바꿈
- 이렇게 하면 각 `calling`마다 이름 탐색, 위치 갱신이 전부 O(1)로 처리된다.

## 발생했던 문제
없음. 처음부터 "탐색이 많이 걸리는 문제"라는 점을 인지하고, 이름→인덱스 매핑을 위한 딕셔너리를 바로 도입해 설계해서 막힘없이 풀렸다.

## 복잡도
- 딕셔너리 초기화: O(n)
- 각 `calling`마다 딕셔너리 조회/갱신과 배열 원소 교체가 전부 O(1)이므로, `callings`의 길이를 `m`이라 하면 전체는 O(m)
- 전체 시간복잡도: **O(n + m)**
- 공간복잡도: O(n) (`players_dict`)

## 배운 점
- "이름(또는 값) → 위치"를 반복적으로 조회해야 하는 문제에서는, 배열을 매번 탐색(`list.index()`)하는 대신 딕셔너리로 이름과 인덱스를 양방향에 가깝게 매핑해두면 조회 비용을 O(n)에서 O(1)로 줄일 수 있다.
- 값을 맞바꾸는 로직에서는, 실제 데이터(`players` 배열)와 그 데이터의 위치를 추적하는 보조 자료구조(`players_dict`)를 **항상 함께 갱신**해야 한다는 점이 중요하다. 하나만 갱신하고 다른 하나를 빠뜨리면 이후 조회가 전부 어긋나게 된다.
- 문제의 제약 조건(선수 수, 호출 횟수가 큰 경우)을 미리 보고 "단순 탐색이면 안 되겠다"고 판단한 뒤 자료구조를 선택하는 습관이, 시간초과를 사전에 예방하는 데 도움이 된다.

## 최종 코드

```python
"""
5 ≤ players의 길이 ≤ 50,000
->탐색이 많이 걸리는 문제
맵으로 바로바로 찾아서 서로 바꾸기
"""
def solution(players, callings):

    players_dict = {p: idx for idx, p in enumerate(players)}

    for c in callings:
        now = players_dict[c]
        front = now - 1

        front_player = players[front]

        players_dict[front_player] = now
        players_dict[c] = front

        players[now] = front_player
        players[front] = c

    return players
```
