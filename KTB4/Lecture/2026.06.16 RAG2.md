## 고급 검색기법

### Hybrid Search (하이브리드 검색)
- **임베딩** 기반 검색과 **키워드** 기반 검색을 **동시에 수행**하고, 두 수행결과 **점수를 가중합산**하여 **최종 순위를 결정**하는 검색기법
- 사용 이유: 두 검색 기법의 단점을 서로 보완 및 장점을 결합함
- 두 검색 비교 표
| 비교 항목 | **Dense (임베딩 기반)** | **Sparse (키워드 기반)** |
|---|---|---|
| **정식 명칭** | Dense Retrieval | Sparse Retrieval |
| **검색 기준** | 의미 유사도(코사인 유사도) | 키워드 일치(단어 빈도) |
| **검색 원리** | 벡터 공간에서의 의미적 유사도 측정 | 문서-질의 간 키워드 출현 빈도 매칭 |
| **표현 방식** | 고밀도 실수 벡터 (Dense Vector) | 고차원 희소 벡터 (Sparse Vector) |
| **벡터 차원** | 128 ~ 4096차원 (압축된 의미 공간) | 어휘 크기만큼 (수만 ~ 수십만 차원) |
| **벡터 값** | 모든 차원에 실수값 존재 | 대부분 0, 단어 등장 위치만 0이 아닌실수 |
| **핵심 알고리즘** | FAISS, HNSW, IVF (ANN 근사 검색) | BM25, TF-IDF |
| **대표 모델/도구** | BERT, `bge-m3`, `e5-large`, OpenAI Embeddings | BM25 (Elasticsearch, OpenSearch, Lucene) 

- 검색 파이프라인
```
[질의 (Query)]
      │
      ├──────────────────────────────────────┐
      ▼                                      ▼
  [Dense 검색]                            Sparse 검색]
임베딩 모델로 벡터 변환                       BM25 키워드 매칭
Vector DB에서 ANN 검색                    역색인에서 빠른 조회
      │                                      │
      └──────────────┬───────────────────────┘
                     ▼
               [Score Fusion]
           Dense + Sparse 결과 통합
                     │
                     ▼
             [Reranker (선택적)]
           Cross-Encoder로 최종 정렬
                     │
                     ▼
           [Top-K 문서 → LLM 생성]
```
~~~
# [Score Fusion]
## 점수 정규화
### Dense 점수와 Sparse 점수의 스케일이 다르므로, 0~1 범위로 정규화
## 가중합산 Score Fusion
### alpha: Dense 검색의 비중(0 < alpha < 1)
final_score = alpha * dense_score + (1 - alpha) * sparse_score
~~~

### Query Expansion (쿼리 확장) 
- **원문 질문**을 **재구성** 또는 **관련 용어를 추가**해서 검색 범위를 확장하는 기법
  예) 질문: RAG -> 보완질문: RAG Retrieval-Augmented Generation 검색 증강 생성
- 사용이유: 검색 누락 감소, 검색 품질 상승을 위해서 (실무에서 자주 쓰이는편)

전처리 조차 LLM으로 하는 경우가 점점늘고있다.
- 세이프티 필터링, 가드레일
- 단점: 많은 디버깅, 결과속도 느림, 비용(토큰)
- 검색 파이프라인
```
[원본 질문 (Original Query)]
             │
             ▼
┌─────────────────────────┐
│  STEP 1. 유의어 추가       │  ← 규칙 기반 (동의어 사전, 약어 매핑)
│  Synonym Expansion      │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│  STEP 2. 다중 질문 생성    │  ← LLM이 여러 관점으로 질문 재구성
│  Multi-Query            │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│  STEP 3. 추상화 질문 변환   │  ← 구체적 질문 → 상위 추상 질문으로 변환(맥락 확장)
│  Step-back              │
└────────────┬────────────┘
             │
             ▼
┌─────────────────────────┐
│  STEP 4. 결과 통합        │   ← RRF 등으로 중복 제거 및 순위 통합
│  + Generation           │     → LLM에 전달하여 최종 답변 생성
└─────────────────────────┘
```

### Reranking (재순위화)
- **1차검색**에서 확보한 **문서**들을 **별도 정밀 모델**로 다시 **평가**해서 질문과 더 유사성 **높은 문서순으로 정렬**하는 재조정 기법
  예) 예선투표, 결선 투표
- 사용이유: 1차 검색결과가 부정확하거나 무관한 문서가 포함되서 답변 품질이 낮은 문제를 해결(검색결과 정밀도와 최종답변 정확도 높임)
- 바이 인코더(1차 검색) : 질문과 문서를 각각 독립적으로 벡화화 후 유사도 비교(긴밀한 상태가 아닐수있다.)
- 크로스 인코더(랭킹): **(질문, 문서)**를 하나의 **입력**으로 넣고, **관령성 점수를 계산**
  - 관련성 점수화 기준: 두 문서간의 관계를 어텐션(attention)으로 계산

~~~
[사용자 질문 (Query)]
         │
         ▼
┌─────────────────────────────────────────┐
│  STEP 1. 1차 검색 (Bi-Encoder)            │
│                                         │
│  벡터 DB에서 ANN 검색                       │
│  → Top-N 후보 문서 추출                    │
└────────────────────┬────────────────────┘
                     │ Top-N 후보 문서
                     ▼
┌─────────────────────────────────────────┐
│  STEP 2. Reranking (Cross-Encoder)      │
│                                         │
│  (질문, 문서1) → 관련도 점수: 0.92            │
│  (질문, 문서2) → 관련도 점수: 0.45            │
│  (질문, 문서3) → 관련도 점수: 0.78            │
│  ...                                    │
│  각 쌍을 개별 추론하여 점수 재계산              │
└────────────────────┬────────────────────┘
                     │ 관련도 점수 목록
                     ▼
┌─────────────────────────────────────────┐
│  STEP 3. 최종 Top-K 선택                  │
│                                         │
│  점수 기준 내림차순 정렬                     │
│  1위: 문서1 (0.92)                        │  
│  2위: 문서3 (0.78)                        │
│  3위: 문서2 (0.45)                        │
│  → Top-K 문서만 선택 (K = 3~10)            │
└────────────────────┬────────────────────┘
                     │ Top-K 문서
                     ▼
┌─────────────────────────────────────────┐
│  STEP 4. Generation (LLM)               │
│                                         │
│  [시스템 프롬프트]                           │
│  + [Top-K 문서 = 컨텍스트]                  │
│  + [사용자 질문]                           │
│  → LLM 최종 답변 생성                       │
└─────────────────────────────────────────┘
                     │
                     ▼
            [최종 답변 (Answer)]
~~~

### HyDE (Hypothetical Document Embeddings)
- LLM으로 가상 답변을 생성하고, 그 답변을 임베딩해서 실제 문서를 검색하는 기법
- 사용이유: 질문이 짧고 압축적이어서 실제 정답돠 거리 유사도가 멀다
