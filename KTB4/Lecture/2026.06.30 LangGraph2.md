# LangGraph

## Persistence(영속성)
- 랭그래프의 state 정보를 유지하는 기능(state를 실행 이후에도 유지)
- `thread_id`: 실행흐름 구분 
- 코드 예제

~~~
## 1. 체크포인터 연결(#### checkpointer)
graph = builder.compile(checkpointer=<체크포인터>)

## 2. thread_id 전달(#### thread)
graph.invoke(<입력>, config={"configurable": {"thread_id": "<세션 식별자>"}})

## 3. 체크포인터 그래프 실행시 config 전달(#### thread)
result = graph.invoke(<입력>, config)

## 4. 현재(최신) 상태와 실행 이력(과거) 조회(#### Checkpoint)
current = graph.get_state(config)
history = graph.get_state_history(config)		## 최근 체크포인트부터 시간 역순으로 정렬됨
~~~

### Checkpointer
- 실질적으로 Persistence를 동작 및 저장하는 인터페이스
- 사용 이유: 안정적으로 에러 복구, 중복 실행 방지, 운영 디버깅, etc 지원(멀티턴, 장기 실행 워크플로우)
- 종류
	- InMemorySaver
    	- 시스템 메모리에 저장(휘발성)
    	- 개발 단계에서 동작 확인용으로 사용
	- SqliteSaver
		- (SQlite 기반) 파일에 저장
      	- 단일 서버에 적합
	- PostgresSaver
      	- DB서버에 저장
		- 실제 운영(여러 인스턴스가 상태 공유해야하는 경우)에 적합
~~~
from langgraph.checkpoint.memory import InMemorySaver
# 메모리 기반 체크포인터
graph = builder.compile(checkpointer=InMemorySaver())
~~~



#### Thread
- 랭그래프의 세션 단위(`thread_id`로 묶이는 대화)
- OS에서 의미 : 프로세스 내의 실행 처리 단위
- 코드 예제
  - 사용자별로 구분한다면: user_id 로
  - 대화 주제로 구분한다면: 주제로
  - 위의 두 구분자로 동시에 구분한다면:  "user_id + subject" 
~~~
## config의 thread_id 로 구분방식 설정
config = {
    "configurable": {
        "thread_id": "user-emet123-coding" 
    }
}

## invoke에 설정한 config 전달
result = graph.invoke(
    {"messages": [{"role": "user", "content": "안녕하세요."}]},
    config,
)
~~~
#### Checkpoint
- 순간적으로 state가 저장된 지점
- 사용이유: 오류가 발생하면 처음부터가 아닌 발생한 단계 또는 직전 단계에서 기록을 불러와서 문제해결 가능(비용 및 시간 절감)
- 코드 예제

~~~
current = graph.get_state(config)				## 현재(최신) state(상태) 불러옴
history = graph.get_state_history(config)		## 최근 체크포인트부터 시간 역순으로 정렬됨
~~~

#### Time Travel
- 과거 체크포인트의 state 정보로 똑같이 이어서 실행
- 사용 이유: 문제 재현(reproduction)
- 코드 예제
~~~
## 과거 이력 리스트로 불러옴
history = list(graph.get_state_history(config))
## 최근에 3번째로 저장한 체크포인트 상태 불러옴
target = history[2]                                                            

print(target.values)

## 해당 체크포인트의 상태정보로 이어서 실행(재현): 입력없이 실행
new_result = graph.invoke(None, target.config)                                 
print(new_result)

## 해당 체크 포인트의 값을 변경
graph.update_state(config, {"count": 1000})                                    
print(graph.get_state(config).values)
~~~

## Durable Execution
- 문제 발생시 직전 state(상태)를 불러와서 자연스럽게 동작시키는 랭그래프의 실행 모델(장기 실행 가능)

### Determinism
- 같은 실행 경로,결과 재현할 수 있게하는 **일관성 규칙**
- 예시
	- 원래의 흐름: A노드 -> B노드 -> END
	- 문제 발생 지점: A노드 이후
	- 옭게된 재현: A노드 -> B노드 -> END
 	- 잘못된 재현:	A노드 -> C노드 -> END (불러온 체크포인트의 state로 했음에도 새롭게 계산한 결과가 다른 경우)

### Idempotency(멱등성)
- 한 번의 실행 결과가 재반복해도 동일하도록 보장하는 규칙
- 수학 멱등성

$$
0 \+ 0 = 0 (0은 합의 멱등원)
$$


$$   
0 \* 0 = 0, 1 \* 1 = 1 (0,1은 곱의 멱등원)
$$   

- 함수 멱등성 

$$
f(f(x)) = f(x)
$$

$$
f∘f = f
$$

- 예시
	- GET,PUT,DELETE 	
		- 현재 주소: 강북
 		- 이사로 인한 주소 수정진행
   		- 변경 주소: 강남
   		- 이후의 주소는 강남으로 변하지않음
