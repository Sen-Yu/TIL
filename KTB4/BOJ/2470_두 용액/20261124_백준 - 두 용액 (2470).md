## 1. 문제 요약 및 제약 조건

### 문제 요약
- 산성 용액(양수)과 알칼리성 용액(음수)의 특성값이 주어진다. 값은 모두 서로 다르다.
- 서로 다른 두 용액을 섞어 **특성값의 합이 0에 가장 가까운** 두 용액을 찾는다.
- 두 값을 오름차순으로 출력한다. 답이 여러 개면 아무거나 출력한다.

### 제약 조건
- 용액 수 N: **2 이상 100,000 이하 (10만)** → 모든 쌍을 보는 O(N²)은 불가능
- 특성값: **-10억 ~ 10억**

## 2. 고민 과정 및 코드의 발전

백준에서 Python으로 처음 푼 문제. 지금까지 푼 투 포인터(178870, 보석 쇼핑, 롤케이크)는 **두 포인터가 같은 방향**으로 갔는데, 이 문제는 **양 끝에서 안쪽으로** 좁혀야 했다.

### ❌ 1단계: 오른쪽 끝 고정 + 부호 있는 합 비교 (오답)

```python
import sys
def main():
    input = sys.stdin.readline   
    n = int(input())
    input = sys.stdin.readline   
    arr = list(map(int, input().split()))     
    arr.sort()
    
    answer = [arr[0] , arr[-1]]
    
    if arr[0] < arr[-1] < 0 or 0 < arr[0] < arr[-1] :
        answer = [arr[0] , arr[-1]]
        return answer

    right = n-1
    for left in range(n):
        if arr[left]+arr[right] < answer[1]+answer[0]:
            answer = [arr[left], arr[right]]
            
    return answer


print(main())
```

- 시간 초과를 걱정했지만, 반복문이 한 번이라 O(N)으로 속도는 문제없었다. 문제는 **오답**이었다.

| 입력 | 결과 | 정답 |
|---|---|---|
| `-2 4 -99 -1 98` (예제) | `[-99, 98]` | `-99 98` |
| `-5 -4 -3 -1` | `[-5, -1]` | `-3 -1` |
| `1 2 3 10` | `[1, 10]` | `1 2` |
| `-10 -3 4 20` | `[-10, 20]` | `-3 4` |

- **문제점**:
  1. `print(main())`이 `[-99, 98]`처럼 대괄호까지 출력 → 예제도 오답. `print(*answer)`여야 한다.
  2. "0에 가깝다"는 **절댓값** 비교인데, 부호 있는 합으로 비교해서 더 음수인 합을 골랐다.
  3. `right`가 `n-1`에 고정돼서 "가장 큰 수 + 무언가" 조합만 봤다.
  4. 모두 양수면 `arr[0], arr[1]`, 모두 음수면 `arr[-2], arr[-1]`이 정답인데 `arr[0], arr[-1]`을 반환했다.

### ❌ 2단계: `for right` + `left` 앞으로 옮기기 (같은 방향 투 포인터, 오답)

```python
    left = 0
    for right in range(1,n):
        while left < right and abs(arr[left]+arr[right]) > abs(answer[1]+answer[0]):
            left+=1
        if abs(arr[left]+arr[right]) < abs(answer[1]+answer[0]):
            answer = [arr[left], arr[right]]
```

- 출력 형식과 절댓값 비교는 고쳤지만, 178870에서 쓴 **같은 방향 틀**을 그대로 가져왔다.
- `right`가 커질수록 짝이 되어야 할 수는 **더 작은 수(더 음수)**인데, `left`는 오른쪽으로만 움직여서 좋은 짝을 한 번 지나치면 다시 못 본다.

```text
정렬: -29  -17  29  30      처음 answer = [-29, 30], |합| = 1
right=-17: |-29-17|=46 > 1 → left를 -17까지 옮김
right= 29: |-17+29|=12 > 1 → left를 29까지 옮김   ← -29를 이미 지나침
                                                     -29 + 29 = 0을 영영 못 봄
```

### ❌ 3단계: 모두 음수/양수 처리만 고침 (오답)
- 특별 처리를 `arr[-2], arr[-1]` / `arr[0], arr[1]`로 고쳐서 그 경우는 맞게 됐다.
- 반복문은 그대로라 `-17 30 29 -29` 같은 경우는 여전히 틀렸다.
- `-15 -19 30 0 -13 -25`에서는 `0 0`이 출력됐다. while이 끝날 때 `left == right`가 될 수 있는데, 그 상태로 비교해서 **같은 용액을 두 번 고른 것**이다.

### ⭕ 4단계: 양 끝에서 안쪽으로 (통과)
- 약 50분 시도 후 빈칸 코드 힌트(`while left < right`, 합의 부호로 한쪽만 이동)를 받고 빈칸 4개를 채워 통과.
- 이후 모두 음수/양수 특별 처리와 중복된 `return`을 지워 최종본을 만들었다.

```python
import sys
def main():
    input = sys.stdin.readline   
    n = int(input())
    arr = list(map(int, input().split()))     
    arr.sort()
    
    answer = [arr[0] , arr[-1]]

    left = 0
    right = n - 1
    while left < right:                     # 같은 용액을 두 번 고르지 않도록
        now = arr[left] + arr[right]

        if abs(now) < abs(answer[0] + answer[1]):
            answer = [ arr[left], arr[right]]

        if now < 0:
            left+=1          # 합이 음수 → 더 큰 수가 필요
        else:
            right-=1          # 합이 양수 → 더 작은 수가 필요

    return answer

answer = main()
print(*answer)
```

- 검증 (직접 고른 10개 케이스): 예제, 모두 양수, 모두 음수, 2개뿐, 합이 정확히 0, 가운데 쌍이 정답, 0 포함, 정답이 2개인 경우, ±10억, 최대 입력 10만 개(0.04초) 모두 통과.

## 3. 핵심 아이디어 및 원리 분석

### 💡 1. 정렬 + 양 끝에서 안쪽으로 좁히기
- 정렬하면 `left`를 오른쪽으로 옮길수록 합이 커지고, `right`를 왼쪽으로 옮길수록 합이 작아진다.
- **합 < 0** → 더 큰 수가 필요하다. `right`를 줄이면 합이 더 작아지기만 하니 `left`를 옮긴다.
- **합 > 0** → 같은 이유로 `right`를 옮긴다.
- 옮기기 전에 매번 `|합|`이 지금까지보다 작은지 확인한다.

```text
정렬:  -99   -2   -1    4   98
        L                    R    합  -1  → |합| 1 기록. 음수 → L 이동
              L              R    합  96  → 양수 → R 이동
              L         R         합   2  → 1보다 큼. 양수 → R 이동
              L    R              합  -3  → 음수 → L 이동
                   LR             L == R → 종료.  정답 -99 98
```

### 💡 2. 왜 놓치는 쌍이 없나
- 합이 음수라서 `left`를 옮길 때, 지금 `arr[left]`와 `right`보다 왼쪽 수들의 합은 지금 합보다도 작다(더 음수). 그러니 지금 `arr[left]`는 더 볼 필요가 없다.
- 합이 양수일 때 `right`도 같은 이유로 버려도 된다.
- 그래서 모두 양수(`right`만 줄어들어 결국 `arr[0]+arr[1]`까지 확인)와 모두 음수(`left`만 늘어나 `arr[-2]+arr[-1]`까지 확인)도 **특별 처리 없이** 맞는다.

### 💡 3. 같은 방향 vs 양 끝에서 안쪽으로

| | 같은 방향 (178870, 보석 쇼핑, 롤케이크) | 양 끝에서 안쪽으로 (두 용액) |
|---|---|---|
| 시작 위치 | `left = 0`, `right = 0` | `left = 0`, `right = n-1` |
| 반복문 | `for right` + 안쪽 `while`로 `left` 줄이기 | `while left < right` 하나 |
| 움직이는 기준 | 조건을 만족하는가 (합 ≥ k, 종류 다 있음) | **합의 부호** |
| 전제 | 원소가 양수 / 연속 구간 | **정렬된 배열**, 두 원소 고르기 |

## 4. 디버깅 & 실수했던 포인트 정리

1. **백준 출력 형식**: `print(리스트)`는 `[a, b]`로 출력된다. 공백 구분은 `print(*리스트)`.
2. **"0에 가깝다" = 절댓값**: 부호 있는 값으로 비교하면 더 음수인 쪽을 고르게 된다.
3. **익숙한 틀을 무조건 가져오지 않기**: 같은 방향 투 포인터는 "구간이 커지면 값이 커진다"가 성립할 때 쓴다. 두 원소를 고르는 문제에서는 짝이 반대 방향으로 움직여야 한다.
4. **`left < right` 조건**: 포인터가 만나는 순간을 비교에 쓰면 같은 원소를 두 번 고른다.
5. **특별 처리는 일반 규칙이 맞으면 필요 없다**: 모두 음수/양수 분기는 양 끝 투 포인터로 자연스럽게 처리됐다.

## 5. 복잡도 분석

- **시간 복잡도**: $O(N \log N)$
  - 정렬 $O(N \log N)$ + 투 포인터 $O(N)$ (한 번에 한 칸씩 가까워지므로 최대 N-1번).
- **공간 복잡도**: $O(N)$ — 입력 배열.

## 6. 결론 및 배운 점
- 투 포인터에는 **같은 방향**과 **양 끝에서 안쪽으로** 두 가지가 있다. 연속 구간이면 같은 방향, 정렬된 배열에서 두 원소를 고르면 양 끝에서 시작하는 쪽을 먼저 떠올리자.
- 어느 쪽 포인터를 움직일지는 "지금 상태에서 버려도 되는 원소가 누구인가"로 정한다.
- 백준은 출력 형식까지 채점한다. 제출 전에 `input.txt`로 예제 출력을 한 번 확인하자.
