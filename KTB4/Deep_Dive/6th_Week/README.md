## 본문

### Chunking
- RAG 파이프라인에서 문서로딩 이후 토큰 임베딩을 위해서 문서를 일정 단위인 청크(chunk)로 분할하는 과정

- 주요 청킹 전략

| 전략 | 분할 기준 | 장점 | 단점 |
|-----|---------|-----|----|
| Fixed-size Chunking |	글자 수 또는 토큰 수 | 심플한 구현 | 문장 중간에서 분할 발생해서 문맥이 끊김 |
| Regex & Delimiter Chunking |	줄바꿈, 마침표, 제목 등 구분자 |	자연스러운 단위로 분할(심플한 구현)| 청크 크기 불균일|
| Semantic Chunking |	문장 간 임베딩 유사도 |	의미 단위 분할로 높은 검색 정확도 | 개별 임베딩 계산 비용 발생|
| Parent-Child Chunking |	큰 청크(부모)와 작은 청크(자식) 계층 |	검색은 작은 단위로, 응답은 넓은 문맥을 제공합니다.| 복잡한 구현 |


### 검색 품질
#### Context Precision
- 검색된 문서 중 실제로 관련 있는 비율(검색된 문서 실용도)
  -> 실제로 필요하지 않은 문서가 있는가?

$$
\text{Context Precision} = \frac{|\text{Retrieved} \cap \text{Relevant}|}{|\text{Retrieved}|}
$$
 
#### Context Recall
- 관련 문서 중 실제로 검색된 비율(문서 검색 정확도)
  -> 검색되지 못한 실제 필요 문서가 있는가?

$$
\text{Context Recall} = \frac{|\text{Retrieved} \cap \text{Relevant}|}{|\text{Relevant}|}
$$


#### 가상 예시

~~~
<가상 문서>
"환불은 구매일로부터 7일 이내 가능합니다. 단, 세일 상품은 환불이 불가능합니다. 배송은 평균 3일이 소요되며, 제주도와 도서 지역은 추가로 2일이 더 걸립니다. 교환은 환불과 동일한 절차로 진행됩니다."
~~~
~~~
<가상 질문1>
상품 배송이 얼마나 걸릴까?
~~~
~~~
<가상 질문2>
세일 상품도 환불이 되나요?
~~~

##### Fixed-size Chunking
- 세팅: 20자 단위 분할
~~~
청크 1: "환불은 구매일로부터 7일 이내 가능합니다. 단, 세일 상"
청크 2: "품은 환불이 불가능합니다. 배송은 평균 3일이 소요되며"
청크 3: ", 제주도와 도서 지역은 추가로 2일이 더 걸립니다. 교환"
청크 4: "은 환불과 동일한 절차로 진행됩니다."
~~~

<가상 질문1>
  - Retrieved: 청크2
  - Relevant: 청크2, 청크3  
  - Context Precision: 100% 
  - Context Recall 50%
  - 답변의 품질: "배송은 평균 3일이 소요되며"라는 핵심 문장은 받았지만, 제주도·도서 지역 추가 기간 정보(청크3)가 통째로 빠짐. LLM은 "3일"이라고만 답하고 지역별 예외는 언급하지 못해 불완전한 답변이 됨

<가상 질문2>
- Retrieved: 청크2
- Relevant: 청크1, 청크2
- Context Precision: 100%
- Context Recall: 50%
- 답변의 품질: "세일 상품은 환불이 불가능합니다"라는 핵심 문장은 받았지만, 정작 그 앞의 "세일 상"이 빠져 있어 무엇이 환불 불가인지 불완전하게 전달됨. LLM이 "품은 환불이 불가능합니다"만 보고 주어를 추측해서 답할 위험이 있음
    
##### Regex & Delimiter Chunking
- 세팅: "." 단위 분할
~~~
청크 1: "환불은 구매일로부터 7일 이내 가능합니다."
청크 2: "단, 세일 상품은 환불이 불가능합니다."
청크 3: "배송은 평균 3일이 소요되며, 제주도와 도서 지역은 추가로 2일이 더 걸립니다."
청크 4: "교환은 환불과 동일한 절차로 진행됩니다."
~~~

<가상 질문1>
  - Retrieved: 청크3
  - Relevant: 청크3  
  - Context Precision: 100% 
  - Context Recall 100%
  - 답변의 품질: "배송 평균 3일, 제주도·도서 지역은 추가 2일"이라는 완전한 문장을 그대로 받아 정확하고 완결된 답변 생성 가능. 배송 정보가 한 문장에 모여 있어 이 질문에서는 누락 없이 잘 작동
    
<가상 질문2>
  - Retrieved: 청크2
  - Relevant: 청크2
  - Context Precision: 100%
  - Context Recall: 100%
  - 답변의 품질: 맥락이 맞고 완전한 문장이라 "세일 상품은 환불 불가"라는 정확한 답변 생성 가능. 단, 일반 환불 가능 기간(청크1)은 함께 전달되지 않아, "그럼 다른 상품은 며칠 내 환불되나요?"처럼 후속 질문에는 추가 검색이 필요함 

##### Semantic Chunking (주제 유사도 기준)
- 세팅: 주제 기준 분할
청크 1 (환불): "환불은 구매일로부터 7일 이내 가능합니다. 단, 세일 상품은 환불이 불가능합니다. 교환은 환불과 동일한 절차로 진행됩니다."
청크 2 (배송): "배송은 평균 3일이 소요되며, 제주도와 도서 지역은 추가로 2일이 더 걸립니다."

<가상 질문1>
  - Retrieved: 청크2
  - Relevant: 청크2  
  - Context Precision: 100% 
  - Context Recall 100%
  - 답변의 품질: 배송 관련 정보가 모두 한 청크에 모여 있어 Delimiter와 동일하게 완전한 답변이 가능. 다만 이 질문에서는 환불 정보가 섞일 필요가 없으므로, Delimiter 대비 추가 이점은 크지 않음 — 의미 단위 분할의 장점은 질문2(환불 주제)처럼 같은 주제 정보가 여러 곳에 흩어져 있을 때 더 두드러짐
  - 
<가상 질문2>
  - Retrieved: 청크1
  - Relevant: 청크1
  - Context Precision: 100%
  - Context Recall: 100%
  - 답변의 품질: "세일 상품 환불 불가"뿐 아니라 일반 환불 기간(7일)과 교환 절차까지 한 번에 포함되어, "그럼 환불 대신 교환은 되나요?" 같은 후속 질문까지 한 번의 검색으로 답변 가능. Regex & Delimiter보다 풍부한 맥락 제공


##### 4. Parent-Child Chunking
- 세팅: Parent는 전체 문장, child는 "."단위 분할
~~~
[Parent — 전체 문단]   
  ├─ Child 1: "환불은 구매일로부터 7일 이내 가능합니다."   
  ├─ Child 2: "단, 세일 상품은 환불이 불가능합니다."   
  ├─ Child 3: "배송은 평균 3일이 소요되며, 제주도와 도서 지역은 추가로 2일이 더 걸립니다."   
  └─ Child 4: "교환은 환불과 동일한 절차로 진행됩니다."   
~~~

<가상 질문1>
  - Retrieved: 청크3
  - Relevant: Parent(청크3) 
  - Context Precision: 100% 
  - Context Recall 100%
  - 답변의 품질: 배송 기간뿐 아니라 Parent 전체에 포함된 환불·교환 정보까지 함께 전달됨. "배송이 늦어지면 환불도 가능한가요?" 같은 후속 질문까지 한 번의 검색으로 대응 가능, 검색 결과(Child 3)보다 넓은 맥락을 제공
  -  
<가상 질문2>
  - Retrieved: Child 2
  - Relevant: Parent(Child 2)
  - Context Precision: 100%
  - Context Recall: 100%
  - 답변의 품질: 검색은 "세일 상품 환불 불가" Child 2로 정밀하게 매칭되지만, 전달되는 Context는 Parent 전체라서 일반 환불 기간, 배송 기간, 교환 절차까지 모두 포함됨. 가상 질문1과 마찬가지로 검색 결과보다 더 넓은 정보를 담은 Context로 답변 생성

### 파라미터 및 분할 기준

#### 청크 크기(Chunk Size)
- 문서를 분할하는 크기
- 청크 크기 클수록 문맥이 끊기지 않는다. 하지만 너무 크면 질문과의 유사도가 낮을 가능성이 높다.
- 청크 크기 작을수록 질문과의 유사도가 높다. 하지만 너무 작으면 문맥이 끊기기 쉽다.

#### 청크 중첩(Chunk Overlap)
- 문맥 단절을 완화하는 중첩 크기(일반적으로 청크 크기의 10~20% 설정)
- 청크 중첩 클수록 문맥 단절률이 낮아진다. 하지만 너무 크면 여러 청크에 **중복 저장**되서 **벡터DB 용량 증가**, Retrieval 결과에서 동일 문서 도출로 인한 **답변의 다양성 감소**
- 청크 중첩 작을수록   하지만 너무 작으면 청크 중첩을 사용한 이유가 적어짐

#### 의미 단위 분할(Semantic Chunking) 여부
- 계산량은 의미단위 분할을 할 경우 크지만 그 만큼 관련 문서 검색 정확도가 높고, 답변 품질또한 높을 것이다.

#### 비교 표
| 요소 | 너무 작게/약하게 설정 시 | 너무 크게/강하게 설정 시 |
|------|------------------------|------------------------|
| 청크 크기 | 문맥 단절, 검색 정밀도는 높으나 정보 누락 | 주제 혼합, 유사도 흐려짐, Context 노이즈 증가 |
| 청크 중첩 | 경계 문맥 손실, 환각 위험 증가 | 중복 저장, Context 다양성 감소 |
| 분할 방식 | (기계적 분할) 문장·주제가 임의로 끊김 | (의미 단위) 계산 비용 증가, 구현 복잡도 상승 |

-> 요소너무 작게/약하게 설정 시너무 크게/강하게 설정 시청크 크기문맥 단절, 검색 정밀도는 높으나 정보 누락주제 혼합, 유사도 흐려짐, Context 노이즈 증가청크 중첩경계 문맥 손실, 환각 위험 증가중복 저장, Context 다양성 감소분할 방식(기계적 분할) 문장·주제가 임의로 끊김(의미 단위) 계산 비용 증가, 구현 복잡도 상승
